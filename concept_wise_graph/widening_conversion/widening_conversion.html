Rules of the concept (15)

Book (SW-1e, p. 32 (pdf 42)): “You can use data of any primitive numeric type where a value whose type has a larger range of values is expected, because Java automatically converts to the type with the larger range.”
Book (SW-1.2, ): “For primitive numeric types, the system automatically performs type conversion when we use a value whose type has a larger range of values than expected.”
Rule typeRule
E folk-meaning ruleFolk meaning: like containers, a bigger box holds a smaller thing, and a smaller box holds a big thing if it happens to fit (3.0 fits in an int). Java rule: the compiler decides by types, not values: int to long or double is automatic, but double to int is never automatic, even for 3.0.
M wrong rule / right ruleNarrowingAssignmentAllowed: wrong: A double value can be stored in an int variable like an int in a double. | right: int to double is automatic (widening); double to int needs a cast, otherwise the assignment is a compile-time error.
M wrong rule / right ruleNoCastIfSameSize: wrong: If a variable is at least as big as a value, no cast is needed to assign the value. | right: The compiler decides by types, not values: assigning a double to an int needs a cast even when the value (e.g. 3.0) would fit, because a conversion that might involve loss of information leads to a compile-time error.
T uneven-application rulePoints to LT (promotion happens at each operator, at the moment an int operand meets a double). Applied unevenly: the student promotes the whole expression up front on one line (so b*b - 4*c is done in double) but per operator on another.
N identity ruleWidening conversion (promotion) is the automatic conversion of a value to a type with a larger range, e.g. int to long or double, char to int.
S declarative ruleA value of a numeric type can be used wherever a type with a larger range is expected and is converted automatically; the magnitude is preserved (int to double is exact), though long to double may lose low-order precision.
LT operational sequencing ruleAt a binary operator, if one operand is double the other is widened to double just before that operation; in an assignment or method argument, the value is widened to the target type after it has been computed.
OP evaluation / result ruleThe widened value has the larger type and the same magnitude: double d = 5; gives 5.0; 11 * 0.3 is double 3.3; 'a' + 1 is int 98; (x < 3.1) with int x = 3 is true.
OS state-transition ruleWidening creates the converted value for the target; the source variable keeps its type and value (after double d = n; n is still an int).
R composition rule (with a neighbour)with type_conversion: Widening is the automatic branch of type conversion; every other direction needs an explicit cast or method.
P plan / role ruleLets int data feed double formulas and library methods without explicit casts, e.g. Math.sqrt(25) or an int count in a double expression.
C conservation ruleWidening an int to double and casting back restores the original int (reversible); widening a large long to double may not be reversible; widening an int quotient after the division cannot restore the lost fraction.
D error rulerule broken: Only widening is automatic; narrowing needs a cast. (compile-time)
D error rulerule broken: Widening applies to the value after the operation that produced it. (silent logic error)
X applicability ruleRely on widening when mixing int and double in formulas or passing ints to double methods; do not expect it to fix an int division already performed; when a narrowing is intended, write the cast explicitly.
