Rules of the concept (16)

Book (OT-Branch, ): “The break statement terminates the labeled statement; it does not transfer the flow of control to the label.”
Rule typeRule
E folk-meaning ruleFolk meaning: a label like `outer:` reads like a 'go to' target or bookmark, so `break outer;` is read as jump back to the label and start again. In Java, `break outer;` terminates the statement labeled outer and continues after it, and `continue outer;` starts the next iteration of the outer loop.
M wrong rule / right ruleBreakJumpsToLabel: wrong: `break outer;` jumps back to the label and restarts the outer loop. | right: `break outer;` completes the statement labeled outer (the whole outer loop); control continues with the statement after that loop and never returns to the label.
T uneven-application ruleApplies the LT rule unevenly: on a trace, `break outer;` sometimes ends only the inner loop (as an unlabeled break would), or restarts the outer loop, so outer-loop passes that should not happen appear in the trace.
N identity ruleJump statement with target: `break label;` or `continue label;` names an enclosing labeled statement (usually an outer loop) to exit or to continue.
S declarative rule`label: for (...) { ... break label; ... }`. The label must be on a statement that encloses the break. `break label;` completes that statement; `continue label;` must name an enclosing loop and starts its next iteration. (Spec: JLS §14.7, §14.15, §14.16.) continue label; ends the current pass of the labelled outer loop and goes on to its next iteration (an unlabelled continue does this for the innermost loop).
LT operational sequencing ruleWhen `break outer;` executes: the rest of the inner body, the inner increment/test, the rest of the outer body and the outer increment/test are all skipped. Execution resumes at the first statement after the outer loop. With `continue outer;`, the outer increment and test run next.
OP evaluation / result ruleNo value is produced. The visible result is fewer passes: for a search over a 2D grid, the loop indices keep the position of the first match when the labeled break fires.
OS state-transition ruleOne execution changes no variables; it only transfers control to after the labeled statement (break) or to its next iteration (continue).
R composition rule (with a neighbour)with break_statement: An unlabeled break exits only the innermost loop or switch. Adding a label lets break exit any enclosing labeled statement, and so end several nested loops at once.
R composition rule (with a neighbour)with nested_loops: A label is needed only when an inner loop must end or advance an outer loop. The label goes on the outer loop header, and both loops share the outer variables, which keep the values they had at the exit.
P plan / role rulePlan: early exit from a nested search (find the first (i, j) that matches and stop both loops). It replaces a flag that the outer loop would otherwise test.
C conservation ruleRemoving the label (plain `break;`) keeps the inner exit but lets the outer loop continue, and the search may find later matches. Replacing the labeled break with a one-way flag tested by both loops keeps the result.
D error rulerule broken: The label must belong to a statement that encloses the break or continue. (compile-time)
D error rulerule broken: `continue label;` must name a loop. (compile-time)
D error rulerule broken: Unlabeled break exits only the innermost loop. (silent logic error)
X applicability ruleUse a labeled break or continue only in nested loops where the inner loop decides that the outer loop should end or skip ahead. In a method, `return` is usually clearer; in single loops plain break suffices.
