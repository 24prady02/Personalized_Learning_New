Rules of the concept (13)

Book (SW-1e, p. 47 (pdf 57)): “One way to understand control flow is to visualize it with a diagram called a flowchart.”
Rule typeRule
E folk-meaning ruleFolk meaning: an everyday flowchart is a static picture or a decision tree read top to bottom once, so a novice reads a loop-back arrow as decoration and the diamond as a one-time question. In a program flowchart, each path is a possible execution, and an arrow returning to a diamond means the test is evaluated again.
T uneven-application ruleApplies the path-following rule unevenly: on some passes the trace takes the yes branch without re-evaluating the diamond, or does not follow the back arrow to the test. Loops are then traced as ifs (one pass).
N identity ruleDiagram: a flowchart is a diagram of control flow. Boxes are statements, diamonds are boolean tests with yes/no exits, and arrows show the order of execution.
S declarative ruleEvery path through the flowchart corresponds to a flow-of-control path through the program. An if is a diamond whose branches rejoin; a while is a diamond whose yes branch runs the body and returns to the diamond.
LT operational sequencing ruleExecution order: start at the entry; execute each box when reached; at a diamond evaluate the condition and follow the yes or no arrow; follow back arrows to re-test; stop at the exit.
OP evaluation / result ruleThe result of reading a flowchart for given inputs is the path taken (the sequence of boxes and branch choices) and so the output. For `if (x > y) max = x; else max = y;` with x = 2, y = 5, the path goes to the no branch and sets max = 5.
OS state-transition ruleOne step moves along one arrow: either execute one box (changing the variables it assigns) or evaluate one diamond (changing nothing, choosing yes or no).
R composition rule (with a neighbour)with control_flow: The flowchart's arrows are the program's control flow: sequence = a straight chain, if = branch and rejoin, loop = a back arrow to the test. Nesting a loop draws a loop inside a loop, and the diagram quickly becomes complex.
P plan / role rulePurpose: to visualise and understand the control flow of basic building blocks (if, while, for) and to check where each path leads. It is not a way to design whole modern programs.
C conservation ruleMoving the back arrow from the diamond to the body box changes a while into a do-while (test after). Removing the back arrow turns the loop into an if. Swapping the yes and no labels swaps the branches.
D error rulerule broken: A loop's back arrow must return to the test, not straight to the body. (silent logic error)
D error rulerule broken: A diamond must have both yes and no exits. (silent logic error)
X applicability ruleUse a flowchart to understand a single if, while, for or a small nesting. For larger programs, use indentation, traces and a limited set of structured constructs instead: flowcharts of complex control flow are hard to read.
