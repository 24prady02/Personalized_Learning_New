Rules of the concept (13)

Book (SW-1e, p. 95 (pdf 105)): “Precomputing values in this way is an example of a space-time tradeoff”
Rule typeRule
E folk-meaning ruleFolk meaning: saving results is always better, and storing data is free. Rule: precomputation spends memory proportional to the number of saved values to save time, which pays off only when values are reused and the table fits in memory.
T uneven-application rulePoints to LT: precompute every value once, then answer each query by lookup. Inconsistent application: the trace recomputes some values despite the table, or reads entries before they are computed.
N identity ruleIdentity: a space-time tradeoff invests memory (an array of saved values) to save computation time.
S declarative ruleDeclarative: by investing in space (saving values) we save time (no recomputation). PrimeSieve trades a boolean array of size N for speed over the two-variable trial-division method.
LT operational sequencing ruleSequencing: a precompute phase (one pass storing N values) runs first, then a use phase in which each query is one array read.
OP evaluation / result ruleResult: the same answers as recomputation, using about N extra memory cells and much less time per query.
OS state-transition ruleState transition: during precomputation each step stores one value in the table; during use each lookup changes nothing.
R composition rule (with a neighbour)with lookup_table: The lookup table is the stored space: each value is computed once and then read by index.
P plan / role rulePlan/role: speed up programs that need the same values many times (harmonic numbers, primes up to N).
C conservation ruleConservation: results are unchanged by precomputing. Memory grows linearly with N, so for huge N or for values used only once the tradeoff stops paying.
D error rulerule broken: The table must fit in the memory Java allows. (run-time exception)
D error rulerule broken: Precomputation pays only when values are reused. (silent logic error)
X applicability ruleApplicability: precompute when the values are needed for small N many times and memory is ample. Recompute when N is huge, memory is tight, or each value is used once.
