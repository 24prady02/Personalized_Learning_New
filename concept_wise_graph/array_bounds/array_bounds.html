Rules of the concept (16)

Book (SW-1e, p. 91 (pdf 101)): “It is your responsibility to use legal indices when accessing an array element.”
Book (SW-1e, p. 89 (pdf 99)): “Note that the last element of an array is always a[a.length-1].”
Book (SW-1.4, p. 91 (pdf 101)): “It is your responsibility to use legal indices when accessing an array element.”
Rule typeRule
E folk-meaning ruleFolk meaning: in English, 'items 1 to 10' or 'up to n' includes the end point, and reading past the end of a list just gives 'nothing'. Java rule: the legal indices are 0..length-1, and any other index throws ArrayIndexOutOfBoundsException instead of returning a value.
M wrong rule / right ruleOffByOneBound: wrong: < vs <= and 0..n vs 0..n-1 are interchangeable. | right: for (i = 0; i < n; i++) runs n times with i going up to n - 1; with <= it runs n + 1 times and reaches i = n, which is out of bounds for an array of length n.
M wrong rule / right ruleOutOfBoundsElementsAreNull: wrong: An out-of-bounds read returns null (or 0). | right: Reading or writing any index outside 0 to a.length - 1 throws ArrayIndexOutOfBoundsException and returns no value.
T uneven-application rulePoints to LT: the bounds check runs at every access, at run time. Inconsistent application: the trace accepts an index of a.length on the last pass (or -1 on the first) but rejects it elsewhere, or reads 'some value' there.
N identity ruleIdentity: the bounds of an array are its legal index range, 0 to length-1.
S declarative ruleDeclarative: an index less than 0 or greater than length-1 makes the program terminate with an ArrayIndexOutOfBoundsException; it is the programmer's responsibility to use legal indices.
LT operational sequencing ruleSequencing: at each access the index expression is evaluated first and then compared with 0 and a.length. Only if it is in range is the element read or written; otherwise the exception is thrown before any element changes.
OP evaluation / result ruleResult: a legal access yields the element. An illegal one yields no value; the program stops with ArrayIndexOutOfBoundsException naming the bad index (old JVMs print ': 10', current ones 'Index 10 out of bounds for length 10').
OS state-transition ruleState transition: an out-of-bounds write changes no element, because the exception is raised before the store. Control leaves the statement, and main terminates unless the exception is caught.
R composition rule (with a neighbour)with indexing: Every index value used in a[i] must satisfy 0 <= i <= a.length-1; the last element is a[a.length-1].
R composition rule (with a neighbour)with loop_guard: Because an out-of-bounds index stops the program, the loop test checks the bounds before the body uses the index (e.g. x > 0 && x < N-1 before a[x-1], a[x+1]).
P plan / role rulePlan/role: run-time bounds checking makes an indexing mistake a visible error instead of silent memory corruption (buffer overflow).
C conservation ruleConservation: a loop bounded by i < a.length stays within bounds when the array size changes. Changing < to <= adds one pass that throws, and starting at 1 or ending at a.length-1 silently skips an element.
D error rulerule broken: Indices must be in 0..a.length-1. (run-time exception)
D error rulerule broken: A traversal must reach the last valid index a.length-1. (silent logic error)
X applicability ruleApplicability: check indices explicitly (or restrict the loop range) whenever an index is computed from data, a random number or a neighbour (i-1, i+1). A plain i < a.length traversal or an enhanced for loop needs no extra check.
