Rules of the concept (17)

Book (SW-1e, p. 164 (pdf 174)): “The transition matrix is significant because each row represents a discrete probability distribution”
Book (SW-1.6, ): “make that page equally likely to transition to every other page”
Rule typeRule
E folk-meaning ruleIn maths, a/b of two whole numbers is a fraction (2/5 = 0.4); in Java, if both operands are int, / discards the fractional part (2/5 is 0), so a probability computed as counts[i][j]/outDegree[i] is 0 or 1.
M wrong rule / right ruleIntegerProbability: wrong: Probabilities computed with integer division stay correct. | right: counts[i][j]/outDegree[i] with two int operands truncates (0 whenever counts < outDegree); Transition multiplies by .90 first so the division is double, and RandomSurfer casts with (double) freq[i] / T.
M wrong rule / right ruleRowsNeedNotSumToOne: wrong: A page with no outgoing links can have an all-zero row. | right: Normalising requires a non-zero total; a page with no links is given 1/N in every column so its row still sums to 1.
T uneven-application ruleApplies LT (left to right: .90*counts, then / outDegree, then + .10/N) unevenly: e.g. dividing before the double factor on some entries (int division), or adding .10/N once per row instead of to every entry.
N identity ruleA computation: scaling the non-negative weights of a row by their total so that the row becomes a discrete probability distribution summing to 1.
S declarative ruleMultiply counts[i][j] by .90/outDegree[i] and add .10/N to each entry; the resulting entries of each row sum to 1.
LT operational sequencing ruleIn .90*counts[i][j]/outDegree[i] + .10/N, * and / evaluate left to right before +: .90*counts[i][j] first (int promoted to double), then divided by outDegree[i], then .10/N is computed and added.
OP evaluation / result ruleProduces a double in [0, 1]; for tiny.txt page 1 (counts 0 0 2 2 1, outDegree 5) the row is .02 .02 .38 .38 .20, and the row sums to 1 up to floating-point rounding.
OS state-transition ruleOne evaluation reads counts[i][j], outDegree[i] and N and yields one double p; nothing in counts or outDegree changes.
R composition rule (with a neighbour)with transition_matrix: Normalisation is applied row by row: every entry of row i is divided by the same total outDegree[i], which is what makes the row a distribution the matrix requires.
R composition rule (with a neighbour)with integer_division: Type flow decides the result: with a double operand anywhere to the left (.90*...) the division is floating-point; with two ints it truncates (2/5 == 0).
P plan / role ruleTurn raw counts into probabilities (the "divide each count by the total" plan); the same plan turns visit counts freq[i] into rank estimates freq[i]/T.
C conservation ruleInvariant: weights sum to 1, since .90*(sum of counts/outDegree) + N*(.10/N) = .90 + .10. Changing .90 to .80 without changing .10 breaks it; reordering to counts[i][j]/outDegree[i]*.90 breaks it silently via int division.
D error rulerule broken: Division of two ints truncates. (silent logic error)
D error rulerule broken: Divisor (total) must be non-zero. (silent logic error)
D error rulerule broken: Integer division by zero is undefined. (run-time exception)
X applicability ruleUse whenever counts or weights must become probabilities (matrix rows, visit frequencies); not needed when the values already form a distribution, and not possible for a zero total (dangling page) without a special case.
