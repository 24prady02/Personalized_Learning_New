Rules of the concept (18)

Book (SW-1e, p. 31 (pdf 41)): “We have already used the Integer.parseInt() and Double.parseDouble() library methods to convert String values to int and double values, respectively.”
Book (OT-CmdLine, ): “If an application needs to support a numeric command-line argument, it must convert a String argument that represents a number, such as "34", to a numeric value.”
Book (OT-CmdLine, ): “parseInt throws a NumberFormatException if the format of args[0] isn't valid.”
Book (SW-1.5, ): “All of our classes have a main() method that takes a String array args[] as argument. That array is the sequence of command-line arguments that we type.”
Rule typeRule
E folk-meaning ruleFolk meaning: what the user typed, such as 34, already is a number, so a command-line argument can be used in arithmetic or simply cast. Java rule: command-line arguments are Strings; a String is converted to a number only by a parse method such as Integer.parseInt(args[0]) (parse = read and translate).
M wrong rule / right ruleArgsAreNumbers: wrong: Command-line args arrive already typed, so no parsing is needed. | right: args[0] is always a String, so Integer.parseInt(args[0]) is needed to get its number.
M wrong rule / right ruleCastParsesString: wrong: (int) args[0] converts the text "34" into the number 34. | right: A String argument that represents a number must be converted with a method such as Integer.parseInt; a cast from String to int does not compile.
M wrong rule / right ruleParseAnyString: wrong: Integer.parseInt works on any text, e.g. "five" or "12.2". | right: Integer.parseInt throws a NumberFormatException at run time when the string is not an integer written in digits.
T uneven-application rulePoints to LT (the method reads the whole string; it returns a number only if every character fits the format, otherwise it throws). Applied unevenly: the student parses "12" correctly but expects "12.2" to give 12 or "five" to give 5 on another call.
N identity ruleParsing is explicit type conversion from text: a library method such as Integer.parseInt or Double.parseDouble reads a String and translates it into a value of a primitive type.
S declarative ruleint Integer.parseInt(String s), double Double.parseDouble(String s) and long Long.parseLong(String s) convert s to an int, double or long; if s is not a valid representation they throw NumberFormatException.
LT operational sequencing ruleThe argument expression (e.g. args[0]) is evaluated to a String, the method scans its characters and either returns the number or throws; then the value is used, typically assigned to a typed variable.
OP evaluation / result ruleInteger.parseInt("123") is the int 123 (same as typing the literal 123); Double.parseDouble("-3.0") is the double -3.0; Integer.parseInt("12.2") or ("five") produces no value but a NumberFormatException.
OS state-transition ruleThe String is left unchanged; the only state change is the assignment of the result, e.g. int N = Integer.parseInt(args[0]); sets N.
R composition rule (with a neighbour)with command_line_args: Because args[k] is always a String, a numeric argument must be passed through a parse method before it can be used in arithmetic or comparisons.
R composition rule (with a neighbour)with type_conversion: SW classifies parse methods as explicit type conversion: a method takes an argument of one type and produces a result of another.
P plan / role ruleInput-conversion plan: at the top of main, parse each command-line argument once into a typed variable (Sajaniemi role: fixed value) and use that variable afterwards.
C conservation ruleChanging Integer.parseInt to Double.parseDouble widens the accepted inputs ("2.5") and changes the variable's type to double; changing the input text from "34" to "34.0" or "thirty" turns a working run into a NumberFormatException; converting a number back to a String always succeeds.
D error rulerule broken: The string passed to a parse method must be a valid number of that type. (run-time exception)
D error rulerule broken: args[k] exists only if at least k+1 arguments were typed. (run-time exception)
D error rulerule broken: A String cannot be cast to a number. (compile-time)
X applicability ruleUse parse methods whenever numbers arrive as text (command-line arguments, tokens of a line); StdIn.readInt() already parses its token; use casts, not parse methods, between numeric types.
