Rules of the concept (19)

Book (SW-1e, p. 6 (pdf 16)): “The first line of a method specifies its name and other information; the rest is a sequence of statements enclosed in braces and each followed by a semicolon.”
Book (OT-Expressions, ): “A block is a group of zero or more statements between balanced braces and can be used anywhere a single statement is allowed.”
Book (GJS, ): “Each time a new block or block-like construct is opened, the indent increases by two spaces.”
Book (JLS-14, ): “A block is a sequence of statements, local class declarations, and local variable declaration statements within braces.”
Rule typeRule
E folk-meaning ruleEveryday/visual reading: indentation or line position tells you what belongs together, as in an outline. Java rule: only braces delimit a block; indentation is ignored, and without braces an if or loop body is just the next single statement.
M wrong rule / right ruleLocalVarOutsideScope: wrong: A variable declared inside a block can be used anywhere in the program, like a global. | right: A local variable's scope runs from its declaration to the end of the enclosing block.
M wrong rule / right ruleStatementAfterIfInBranch: wrong: A statement placed after the if statement belongs to its branch, so it runs only when the condition is true. | right: The branch ends at its closing brace (or after its single statement); the next statement runs whatever the condition was.
M wrong rule / right ruleLoopBodyStatementOutsideLoop: wrong: Some statements inside the loop braces are not repeated; they run once, before or after the loop. | right: Every statement inside the loop braces is part of the body and runs on every pass.
M wrong rule / right ruleStatementAfterLoopInBody: wrong: A statement written after the loop is repeated with the loop body. | right: The body ends at the closing brace (or after its single statement); code after it runs once, after the loop ends.
T uneven-application ruleApplies the block rule (LT: all statements of the block in order, the whole block as one unit) unevenly: includes the statement after the closing brace in the body on one pass but not another, or runs only part of the body.
N identity ruleA block (statement block) is a sequence of statements enclosed in braces { }; it counts as one statement where a single statement is expected.
S declarative ruleA block is a sequence of statements and local variable declarations within braces; a variable declared in a block is in scope only from its declaration to the end of that block.
LT operational sequencing ruleA block executes each of its statements in order from first to last; if a statement completes abruptly, the rest of the block is skipped.
OP evaluation / result ruleA block has no value; its result is the combined effect of its statements, in order.
OS state-transition ruleEntering a block makes room for its local variables; leaving it (at the closing brace) ends their scope, so they can no longer be used.
R composition rule (with a neighbour)with statement: A block is built from statements, each ended by ;, and is itself usable as a single statement (e.g. a loop body).
R composition rule (with a neighbour)with program_layout: Indentation should show block nesting, but only braces define it; layout that disagrees with the braces misleads the reader, not the compiler.
P plan / role rulePurpose: group several statements so they act as one body (of main, an if branch or a loop) and limit the scope of variables to where they are needed.
C conservation ruleAdding braces around a single-statement body keeps behaviour; adding a second statement to a braceless body changes it (the new statement runs outside); moving a declaration into a block makes later uses outside the block fail to compile.
D error rulerule broken: Every { must be matched by a } (compile-time)
D error rulerule broken: Without braces only one statement is the body (silent logic error)
D error rulerule broken: A local variable is visible only inside its block (compile-time)
X applicability ruleUse a block whenever a body has more than one statement (S&W and TJ advise braces even for one), and declare variables in the innermost block that needs them.
