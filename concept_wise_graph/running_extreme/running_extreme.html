Rules of the concept (14)

Book (SW-1e, p. 89 (pdf 99)): “find the maximum of the array values double max = Double.NEGATIVE_INFINITY;”
Book (SW-1e, p. 154 (pdf 164)): “Write a program that reads in integers (as many as the user enters) from standard input and prints out the maximum and minimum values.”
Book (SW-1.5, ): “first value read initialized min and max”
Book (CSA, ): “If you want to set a value to the smallest possible int values use Integer.MIN_VALUE.”
Rule typeRule
E folk-meaning ruleFolk meaning: 'the biggest so far' starts from nothing, i.e. 0, because everyday quantities are positive. Rule: the running maximum must start at a value no data can be below (Double.NEGATIVE_INFINITY, Integer.MIN_VALUE) or at the first element, so that the first value read replaces it.
M wrong rule / right ruleExtremeStartsAtZero: wrong: The running maximum can always start at 0. | right: Start the running maximum at the most negative possible value (Double.NEGATIVE_INFINITY, or the smallest int) so that the first value read replaces it.
T uneven-application rulePoints to LT: on each pass, compare a[i] with max and assign max = a[i] only if a[i] is larger. Inconsistent application: max is overwritten without the comparison on some passes, or compared with a stale value.
N identity ruleIdentity: a running maximum (or minimum), a variable holding the largest (smallest) value seen so far in a pass over the data; Sajaniemi's most-wanted holder.
S declarative ruleDeclarative: double max = Double.NEGATIVE_INFINITY; for (int i = 0; i < N; i++) if (a[i] > max) max = a[i];.
LT operational sequencing ruleSequencing: initialize max before the loop; in each pass evaluate a[i] > max, and if it is true assign max = a[i]; read max only after the loop ends.
OP evaluation / result ruleResult: the largest element (of the element type). For an empty array (or no input) max stays at its start value: NEGATIVE_INFINITY, or MIN_VALUE for int.
OS state-transition ruleState transition: one pass changes max only when a[i] > max; otherwise nothing changes.
R composition rule (with a neighbour)with array_traversal: The maximum is found in one traversal, keeping the largest value seen so far, starting from Double.NEGATIVE_INFINITY.
P plan / role rulePlan/role: most-wanted holder (Sajaniemi). It finds the extreme in one pass with constant extra memory; the same plan tracks the minimum with <.
C conservation ruleConservation: replacing > by >= keeps the maximum value but changes which tied position is the last one recorded. Remembering the index of the extreme instead of its value conserves the specification.
D error rulerule broken: The start value must not exceed every possible data value. (silent logic error)
D error rulerule broken: Update only when the new value beats the current extreme. (silent logic error)
X applicability ruleApplicability: use a running extreme when only the max or min (or its position) is needed, in a single pass. For further facts such as how many items equal the maximum, keep the data (an array) and make a second pass.
