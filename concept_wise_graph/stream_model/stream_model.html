Rules of the concept (15)

Book (SW-1e, p. 126 (pdf 136)): “One of the key features of the standard input stream is that your program consumes values when it reads them.”
Book (SW-1.5, ): “Our StdIn library takes data from a standard input stream that contains a sequence of values separated by whitespace ... your program consumes values when it reads them.”
Rule typeRule
E folk-meaning ruleEveryday 'reading' (a page, a list) leaves the text in place so you can glance back at it; a Java input stream is consumed: each read removes the next value, and there is no going back.
M wrong rule / right ruleStdInRereads: wrong: Calling StdIn.readInt() twice returns the same value twice. | right: Each read consumes the value it returns, so a second StdIn.readInt() returns the next value in the stream (input 3 5 gives 3, then 5).
T uneven-application rulePoints to LT (reads take values from the front in order; prints append at the end in order). An uneven trace reuses an already-consumed value on some reads, or writes some output out of execution order.
N identity ruleA stream is an I/O abstraction: an ordered sequence of values or characters, with no length limit from the program's point of view. Input is read from the front and output is appended at the end.
S declarative ruleA Java program turns a standard input stream and command-line arguments into a standard output stream (plus drawing and audio). It consumes values when it reads them, so it cannot back up.
LT operational sequencing ruleInput values are delivered strictly in stream order: each read removes the next value from the front. Output appears in the order the output calls execute, because each call appends to the end.
OP evaluation / result ruleA read returns the next unread value, converted to the requested type. With input `3 5 7`, three StdIn.readInt() calls return 3, 5, 7. The output stream is the concatenation of all printed text in execution order.
OS state-transition ruleOne read advances the input position past exactly one value and returns it. One print appends its text to the output and returns nothing (void). No other state changes.
R composition rule (with a neighbour)with standard_input: All StdIn calls in a program share one input position. A read before a loop and reads inside the loop therefore take successive values, never the same one.
R composition rule (with a neighbour)with standard_output: All StdOut/System.out calls write to one output stream in execution order, and text already written cannot be taken back.
P plan / role ruleStreams let a program process an amount of data that is unbounded and not known in advance. They also decouple the program from the device. Plan: input-process-output (the 'filter' plan).
C conservation ruleChanging where a stream comes from or goes to (keyboard, file, pipe, another device) keeps the program's behaviour. Changing the order of two reads swaps which value lands in which variable.
D error rulerule broken: A read must be preceded by available input (the stream is finite and cannot be re-read). (run-time exception)
D error rulerule broken: Values are consumed once; to use a value again it must be stored in a variable or array. (silent logic error)
X applicability ruleUse the stream model when data are processed in one sequential pass, possibly of unknown or huge length. If the program must revisit values (sorting, k-th smallest), first save them in an array.

Trigger class: Code that calls a read a second time expecting the same value (e.g. readInt() in a test and again in the body), so it silently skips values.
