Rules of the concept (17)

Book (SW-1e, p. 7 (pdf 17)): “Each Java program must reside in a file whose name matches the one after the word class on the first line, and it also must have a .java extension.”
Book (SW-1.1, ): “Create the program by typing it into a text editor and saving it to a file named, say, MyProgram.java.”
Rule typeRule
E folk-meaning ruleEveryday reading: a 'program' is a document you can save under any name, like a letter or an essay, and a misspelt word does not stop a reader from understanding it. Java rule: the file must be named exactly after its public class plus .java (HelloWorld.java for public class HelloWorld), and every character, including case and punctuation, is significant to the compiler.
M wrong rule / right ruleClassNameMatchesFile: wrong: The class name and the file name are independent, so public class HelloWorld can be saved as hello.java or Program.java. | right: A public class Name must be saved in a file called exactly Name.java (same spelling and case).
M wrong rule / right ruleComputerFillsInIntent: wrong: The computer fills in steps or values the programmer meant but did not write. | right: The program text is all the computer has: it executes only what the code states, so every step and value must be written.
T uneven-application ruleApplies the reading rule (LT for program_text: the compiler reads the file Name.java character by character from top to bottom, ignoring comments and whitespace between tokens) unevenly: e.g. reads the code but also the comments as if they ran, or treats the file name as irrelevant on one pass and as the program name on another.
N identity ruleProgram text (source code) is the sequence of characters typed into a text file Name.java that holds one Java program; S&W call it code.
S declarative ruleA Java program is a sequence of characters stored in a file with a .java extension whose name matches the name after the word class on the first line (public class HelloWorld lives in HelloWorld.java).
LT operational sequencing ruleDevelopment order: (1) edit Name.java, (2) javac Name.java translates the whole text, (3) java Name runs it. Within the text, the compiler reads tokens in order; at run time main's statements execute top to bottom.
OP evaluation / result ruleThe program text itself produces no output; its result is the file Name.class produced by javac when the text is legal, and the program's output appears only when java Name runs it.
OS state-transition ruleOne edit-save of the text changes only the file Name.java; the existing Name.class (and so the behaviour of java Name) does not change until javac is run again.
R composition rule (with a neighbour)with class_declaration: The name after 'public class' constrains the file name: public class Name must be in Name.java, or javac rejects it.
R composition rule (with a neighbour)with comment: Comments are part of the program text but are discarded when it is compiled: they may appear anywhere a whitespace may appear and never change Name.class's behaviour.
R composition rule (with a neighbour)with compile: javac takes the text file Name.java as input and produces Name.class; the text must be lexically and syntactically legal for any .class to be produced.
P plan / role ruleThe program text is the human-readable statement of a computation: it records exactly what the computer must do so that it can be compiled, run, read and modified (copy HelloWorld.java, rename the class, replace the statements).
C conservation ruleRenaming the class without renaming the file (or vice versa) breaks compilation; changing whitespace between tokens or editing comments keeps the behaviour unchanged; changing any character inside quotes changes the output.
D error rulerule broken: public class Name must be in Name.java (compile-time)
D error rulerule broken: java Name runs a class, not a file name (launch error)
X applicability ruleUse one source file per program (one public class per Name.java) and edit the text rather than the .class file; do not expect the text to carry meaning that is not written in it.
