Rules of the concept (16)

Book (OT-Op2, ): “Use the ?: operator instead of an if-then-else statement if it makes your code more readable;”
Rule typeRule
E folk-meaning ruleFolk meaning: in everyday text '?' marks a question and ':' introduces an explanation or list, so `x > y ? x : y` reads as 'is x > y? x, y' with no clear meaning, or as a statement that does something. In Java `c ? a : b` is an expression whose value is a if c is true and b otherwise.
M wrong rule / right ruleMapToBooleanWithConditionalOperator: wrong: To map a boolean expression to a boolean, a conditional operator is necessary (`ok = (x > y) ? true : false;`). | right: A comparison already has type boolean, so `ok = (x > y);` gives the same value; the ? : is redundant.
T uneven-application ruleApplies the LT rule unevenly: on a trace, both the second and third operands are evaluated (so side effects like `i++` happen twice), or the operand chosen does not match the condition.
N identity ruleOperator: the conditional operator `? :`, Java's only ternary operator. `c ? a : b` is an expression that picks one of two values.
S declarative ruleThe first operand must be boolean. If it is true the value is the second operand, otherwise the third. The two value operands must have compatible types; for numeric operands, binary numeric promotion applies. (Spec: JLS §15.25.)
LT operational sequencing ruleOrder: evaluate the condition first; then evaluate exactly one of the other operands (the second if true, the third if false); the unchosen operand is never evaluated. ? : groups right to left and has lower precedence than + and the comparisons.
OP evaluation / result ruleThe result is a value, not an action. `(x > y) ? x : y` with x = 3, y = 7 is 7. Numeric operands are promoted, so `true ? 1 : 2.0` is 1.0 (a double), and its type must fit the target of the assignment.
OS state-transition ruleEvaluating ? : changes no variable itself; it returns the chosen operand's value. Only side effects inside the condition or the chosen operand happen (in `c ? i++ : j++`, exactly one of i, j changes).
R composition rule (with a neighbour)with if_else_statement: `v = c ? a : b;` is the expression form of `if (c) v = a; else v = b;`. It can be used inside a larger expression (an argument or concatenation), but it cannot replace an if-else whose branches are statements without values.
P plan / role rulePlan: select-a-value. It picks one of two values in one expression: max/min (`m = a > b ? a : b`, a most-wanted-holder update), absolute value, singular/plural wording, or a default for a missing value.
C conservation ruleNegating the condition and swapping the two value operands keeps the result. Changing a value operand's type can change the result type (int to double) and break an assignment to an int. Nesting ? : inside ? : keeps meaning but quickly harms readability.
D error rulerule broken: The first operand of ? : must be boolean. (compile-time)
D error rulerule broken: A conditional expression is not a statement. (compile-time)
D error rulerule broken: The result type is the promoted type of both value operands. (compile-time)
D error rulerule broken: ? : has lower precedence than + and comparisons. (compile-time)
X applicability ruleUse ? : for a short choice between two values inside an expression (max, a label, a default). Use an if-else statement when the branches do actions, are long, or nest. Use the boolean expression itself when the choice is between true and false.
