Rules of the concept (16)

Book (SW-1e, p. 89 (pdf 99)): “Misunderstanding this convention often leads to off-by one-errors that are notoriously difficult to avoid and debug, so be careful!”
Book (TJ-2e, p. 230 (pdf 252)): “off-by-one: A common programming mistake that results in iterating one time too many, or too few.”
Rule typeRule
E folk-meaning ruleEveryday counting starts at 1 and 'up to N' includes N. Java arrays start at index 0 and end at N-1, and a loop with i < N runs N times while i <= N runs N+1 times.
M wrong rule / right ruleOffByOneBound: wrong: < and <= (and 0..n versus 0..n-1) are interchangeable in a loop bound. | right: i < N runs N times from 0 and i <= N runs N+1 times; with an array of length N only i < N stays inside the indices 0..N-1.
T uneven-application ruleApplies the bound rule unevenly: writes i < a.length in one loop and i <= a.length in the next one over the same array.
N identity ruleOff-by-one error: a loop or index that is one step too far or too short.
S declarative ruleIndices run from 0 to N-1; a loop for (int i = 0; i < N; i++) runs exactly N times. Misunderstanding the 0-based convention leads to off-by-one errors, which are hard to avoid and debug.
LT operational sequencing ruleSequencing: to check a bound, trace the first pass (the start value) and the last pass (the value that makes the condition false), not only a middle pass.
OP evaluation / result ruleResult: for (i = 0; i < 5; i++) gives i = 0..4, five passes; i <= 5 gives six passes, and a[5] on an array of length 5 throws ArrayIndexOutOfBoundsException.
OS state-transition ruleState transition: one extra pass reads or writes one element past the end (an exception) or adds one term too many; one missing pass leaves the last element unprocessed.
R composition rule (with a neighbour)with indexing: Because indexing starts at 0, the last valid index is length-1, and that is the bound most often missed by one.
R composition rule (with a neighbour)with loop_control: The start value and the condition together fix the number of passes; changing either by one changes the count by one.
R composition rule (with a neighbour)with fencepost_loop: When one action must happen once more (or less) than the other, the fencepost plan handles the extra case explicitly instead of risking an off-by-one.
P plan / role rulePlan: choose the bounds from the meaning (count N things, valid indices 0..N-1) and check the first and last pass, rather than guessing.
C conservation ruleConservation: changing < to <= adds exactly one pass; starting at 1 instead of 0 removes exactly one; both keep the loop otherwise the same.
D error rulerule broken: A traversal of an array of length N must use indices 0..N-1. (run-time exception)
D error rulerule broken: A loop meant to run N times must run exactly N times. (silent logic error)
X applicability ruleWhenever writing a loop over a range or an array, write the bound from the count (i < N for N passes from 0) and check the first and last values of the index by hand.
