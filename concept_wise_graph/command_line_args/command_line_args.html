Rules of the concept (19)

Book (SW-1e, p. 9 (pdf 19)): “In the meantime, you can use args[0] within your program's body to represent the string that you type on the command line when it is executed”
Book (OT-CmdLine, ): “When an application is launched, the runtime system passes the command-line arguments to the application's main method via an array of Strings.”
Book (OT-CmdLine, ): “This is because the space character separates command-line arguments.”
Book (SW-1.5, ): “All of our classes have a main() method that takes a String array args[] as argument. That array is the sequence of command-line arguments that we type.”
Rule typeRule
E folk-meaning ruleEveryday/maths reading: '1234' typed on the command line is a number, and the first item in a list is item 1. Java rule: every command-line argument arrives as a String in args, and the first is args[0].
M wrong rule / right ruleArgsAreNumbers: wrong: Command-line arguments arrive already typed as numbers, so no parsing is needed. | right: args[0] is always a String, so Integer.parseInt(args[0]) is needed to get its number.
T uneven-application ruleApplies the args rule unevenly: maps the first typed word to args[0] on one run but to args[1] on another, or treats a numeric argument as a String in one place and as an int in another.
N identity ruleCommand-line arguments are the strings typed after the class name in java Name a b c; they reach main as the String array args.
S declarative ruleargs[0] represents the first string typed on the command line, args[1] the second, and so on (counting starts at 0); every element is a String.
LT operational sequencing ruleAt launch the JVM splits the words after java Name at spaces, stores them in order in args, then calls main(args); the program reads args[k] whenever that expression is evaluated.
OP evaluation / result ruleargs[k] evaluates to the k-th typed string, e.g. java UseArgument Alice gives args[0] = "Alice" and prints Hi, Alice. How are you?
OS state-transition ruleReading args[k] changes nothing; args is set once at launch and the same program gives different outputs only because different arguments were typed.
R composition rule (with a neighbour)with parsing: args[k] is always a String, so Integer.parseInt(args[k]) or Double.parseDouble(args[k]) must convert it before arithmetic.
R composition rule (with a neighbour)with main_method: The arguments arrive in main's parameter args (String[] args).
R composition rule (with a neighbour)with args_length: args.length is the number of arguments typed (0 if none), so valid indices are 0 to args.length-1.
R composition rule (with a neighbour)with black_box_model: In the black-box view the command-line argument is the input string and what the program prints is the output string.
P plan / role rulePurpose: give the program its input at launch so the same compiled program can be tailored to different data without editing or recompiling.
C conservation ruleChanging the typed arguments changes the output but not the program; typing fewer arguments than the program reads causes ArrayIndexOutOfBoundsException; extra arguments are ignored unless read.
D error rulerule broken: args[k] exists only if at least k+1 arguments were typed (run-time exception)
D error rulerule broken: Counting starts at 0: the first argument is args[0] (silent logic error)
D error rulerule broken: Arguments are Strings; numbers must be parsed (compile-time)
D error rulerule broken: Integer.parseInt needs digits (run-time exception)
X applicability ruleUse command-line arguments for a few small inputs known at launch (sizes, names, seeds); use standard input for long or interactive input.
