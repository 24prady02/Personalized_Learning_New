Rules of the concept (15)

Book (TJ-2e, p. 84 (pdf 106)): “short circuit: A way of evaluating logical operators that evaluates the second operand only if necessary.”
Book (OT-Op2, ): “These operators exhibit "short-circuiting" behavior, which means that the second operand is evaluated only if needed.”
Book (Eck, ): “the computer will never perform the division, since when the computer evaluates (x != 0), it finds that the result is false”
Rule typeRule
E folk-meaning ruleFolk meaning: in maths and logic the value of 'p and q' is read off a truth table with both sides known, so both sides are always 'computed'. Java rule: && and || evaluate left to right and skip the right operand when the left already decides the result (false && x, true || x).
M wrong rule / right ruleNoShortCircuit: wrong: Logical AND/OR always evaluate both sides. | right: In p && q, q is evaluated only when p is true; in p || q, q is evaluated only when p is false.
M wrong rule / right ruleSingleAmpersandForAnd: wrong: & and | are the same as && and || for conditions, so either can be used. | right: && and || skip the right operand when the left decides the result; & and | always evaluate both, which fails when the right side depends on the left (e.g. x != 0 & y / x > 1).
T uneven-application rulePoints to LT (evaluate the left operand; stop if it decides; otherwise evaluate the right). Applied unevenly: on some passes of a loop the student counts the side effect of the right operand (e.g. ++i) although the left operand was already false, or lets a guarded index be read on the pass where the guard failed.
N identity ruleShort-circuit evaluation is the way Java evaluates the logical operators && and ||: the second operand is evaluated only if necessary.
S declarative ruleIn a && b, b is evaluated only if a is true (false && b is false); in a || b, b is evaluated only if a is false (true || b is true). &, | and ^ do not short-circuit.
LT operational sequencing ruleEvaluate the left operand fully; if it is false (for &&) or true (for ||) the whole expression takes that value immediately; otherwise evaluate the right operand, whose value is the result.
OP evaluation / result ruleThe value is the same as under full evaluation whenever the right operand would have completed normally; with n = 0, (n != 0 && 10 / n > 1) is false and throws no exception.
OS state-transition ruleWhen the right operand is skipped, none of its side effects happen: with i = 0, after (false && ++i > 0) i is still 0, while (true && ++i > 0) makes i 1.
R composition rule (with a neighbour)with logical_operators: Short-circuiting is the defining evaluation order of && and || only; the book's other boolean operators (! and ^, and & / | if used) evaluate all their operands.
P plan / role ruleGuard plan: put the safety test first so the risky test runs only when it is safe, e.g. (i < a.length && a[i] != 0), (count != 0 && sum / count > 5), (str == null || str.isEmpty()).
C conservation ruleSwapping the operands of a guard (a[i] != 0 && i < a.length) keeps the truth table but lets the risky test run first and throw; replacing && by & removes the protection; moving a needed side effect into the right operand makes it happen only sometimes.
D error rulerule broken: The protecting test must be the left operand of && / ||. (run-time exception)
D error rulerule broken: The right operand of && / || is not always evaluated. (silent logic error)
X applicability ruleRely on short-circuiting when the second test is only valid or meaningful if the first holds (bounds, zero, null) or is expensive; do not put side effects you need into the right operand.
