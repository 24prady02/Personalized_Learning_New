Rules of the concept (17)

Book (SW-1.5, ): “reads in nonnegative integers (representing rainfall) one at a time until 999999 is entered, and then prints out the average of value (not including 999999)”
Rule typeRule
E folk-meaning ruleIn everyday lists the last number written is part of the data. A sentinel such as 99999 is a stop marker, not data, so it must not be summed or counted.
M wrong rule / right ruleSentinelProcessed: wrong: The sentinel value (e.g. 99999) is added to the total like the other values. | right: The value is tested against the sentinel before it is processed. The loop stops at the sentinel, which is never added or counted.
T uneven-application rulePoints to LT (read, test for the sentinel, then process). An uneven trace processes before testing on the last pass, so the sentinel is included that time.
N identity ruleA sentinel loop is a read loop that stops when it reads a designated stop value that cannot occur as real data (the Rainfall problem).
S declarative ruleRead a value; while it is not the sentinel, process it and read the next one. The sentinel is never processed.
LT operational sequencing ruleA priming read comes before the loop, then each pass runs: test value != SENTINEL, process (sum += v; count++), then read the next value at the end of the body. An equivalent form is while (true) { v = read; if (v == SENTINEL) break; process; }.
OP evaluation / result ruleWith input 3 -1 5 99999 7, keeping only non-negative values, the Rainfall average is (3+5)/2 = 4.0. The 7 after the sentinel is never read.
OS state-transition ruleOne pass reads one value. If it is the sentinel, the loop ends with sum and count unchanged; otherwise the (valid) value updates sum and count.
R composition rule (with a neighbour)with read_loop_idiom: The sentinel test replaces, or is added to, the isEmpty() test. If the sentinel may be missing, keep !StdIn.isEmpty() in the condition so the program does not read past the end.
R composition rule (with a neighbour)with accumulator_pattern: sum (a gatherer) and count must change only for values that are not the sentinel and pass the filter. The average is computed once, after the loop.
P plan / role rulePlan: Soloway's sentinel-controlled running-total loop (Rainfall). Roles: sum is a gatherer, count a stepper, and the value read a most-recent holder.
C conservation ruleChanging the sentinel keeps the behaviour only if the new value cannot occur in the data. Moving the test after the processing step breaks the invariant that the sentinel is never processed.
D error rulerule broken: Check count > 0 before computing sum / count. (run-time exception)
D error rulerule broken: Only values in the range of interest may be processed. (silent logic error)
D error rulerule broken: The sentinel must appear, or the loop must also test isEmpty(). (run-time exception)
D error rulerule broken: The sentinel must not be included in the computation. (silent logic error)
X applicability ruleUse a sentinel when the data stream marks its own end with a value outside the valid range (keyed entry with no end-of-file). If every value could be real data, use isEmpty() or a count instead.
