Rules of the concept (14)

Book (SW-1e, p. 127 (pdf 137)): “String readLine() read the rest of the line”
Book (TJ, ): “the Scanner doesn't see input as multiple lines, like we do. Instead, it gets a 'stream of characters'”
Rule typeRule
E folk-meaning ruleEveryday 'read a line' means the next full line you see. readLine() returns the rest of the current line from the read position. A preceding readInt() stops right after the number, so the 'line' may be empty.
M wrong rule / right ruleNextLineAfterNextInt: wrong: A line read after a number read returns the next line typed. | right: After readInt(), the position is just past the number. readLine() returns the rest of that line ("" if nothing follows) and consumes the line separator; a second readLine() is needed for the next line.
T uneven-application rulePoints to LT (token reads stop after the token; readLine reads to the end of the current line). An uneven trace skips the leftover line separator after a token read on some passes.
N identity ruleStdIn's read methods come in two categories: token-based (readInt, readDouble, readString, ... separated by whitespace) and line- or text-based (readLine, readAll).
S declarative ruleA token is a maximal run of non-whitespace characters. readLine() reads and returns the rest of the line without its separator. It is best not to mix the two categories in one program.
LT operational sequencing ruleA token read skips whitespace, including line breaks, before the token and stops immediately after it. readLine() collects characters from the current position up to the line separator, consumes the separator, and returns them without it.
OP evaluation / result ruleFor input `42\nhello world\n`: readInt() gives 42, then readLine() gives "", then readLine() gives "hello world". readString() on `hello world` gives "hello".
OS state-transition ruleA token read advances past one token and leaves the line separator. A readLine() advances past exactly one line separator. Each returns what it consumed (minus the separator).
R composition rule (with a neighbour)with standard_input: Both kinds of call share the single StdIn position, so a token read changes what the next readLine returns. Mixing them needs care.
P plan / role ruleToken reads suit streams of numbers or words. Line reads suit line-structured records, e.g. a name with spaces followed by numbers on each line.
C conservation ruleReplacing line breaks with spaces in the input leaves every token read unchanged but changes what readLine returns.
D error rulerule broken: A token read leaves the rest of its line unread. (silent logic error)
D error rulerule broken: Line reads must stop at end of input. (run-time exception)
X applicability ruleUse token reads when values are separated by arbitrary whitespace. Use readLine when line boundaries or spaces inside a value matter. Avoid mixing the two in one program.
