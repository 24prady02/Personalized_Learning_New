Rules of the concept (22)

Book (SW-1e, p. 6 (pdf 16)): “The first line of a method specifies its name and other information; the rest is a sequence of statements enclosed in braces and each followed by a semicolon.”
Book (OT-Expressions, ): “A statement forms a complete unit of execution. The following types of expressions can be made into a statement by terminating the expression with a semicolon (;).”
Book (JLS-14, ): “Certain kinds of expressions may be used as statements by following them with semicolons.”
Rule typeRule
E folk-meaning ruleEveryday reading: a program is read like a text or a list of wishes that the computer takes in all at once, so line order, goals of later lines or what the writer meant can matter. Java rule: each statement is one step, ended by ;, executed once, in written order, using only the current state.
M wrong rule / right ruleStatementsRunInAnyOrder: wrong: Statements in a program can run in any order, so their order makes no difference. | right: Without control statements, statements run once each, top to bottom, in the order written.
M wrong rule / right ruleWhitespaceIsSignificant: wrong: Line breaks and indentation change what the program does, so each statement must be on its own line. | right: Java compilers treat all whitespace outside quotes as equivalent; statements are separated by ;, not by line breaks.
M wrong rule / right ruleProgramLooksAhead: wrong: The program knows what later lines will do and acts on that goal at the current line. | right: Each statement executes using only the current state; later lines have no effect until control reaches them.
M wrong rule / right ruleComputerFillsInIntent: wrong: The computer fills in omitted steps or values the programmer meant. | right: The computer executes only the statements written; every needed step and value must be written.
T uneven-application ruleApplies the sequencing rule (LT) unevenly: executes the statements in order on some lines but lets a later statement's effect leak into an earlier one, or skips or repeats a statement on one pass.
N identity ruleA statement is one step of a program (a declaration, assignment, method call such as System.out.println(...), or control statement), ended by a semicolon when it is a simple statement.
S declarative ruleA method body is a sequence of statements enclosed in braces and each followed by a semicolon; statements are executed for their effect and have no value; an expression statement evaluates its expression and discards any value.
LT operational sequencing ruleStatements run one at a time, from first to last; each completes (normally or abruptly) before the next starts.
OP evaluation / result ruleA statement has no value; its result is its effect: a changed variable, printed output, or a change of control flow.
OS state-transition ruleExecuting one statement applies its single effect to the current state (e.g. prints one string, or stores one value) and then control moves to the next statement.
R composition rule (with a neighbour)with main_method: Statements live in main's body; running the program executes main's statements in order.
R composition rule (with a neighbour)with block: A block groups a sequence of statements in braces; the body of main() is such a block.
R composition rule (with a neighbour)with print: System.out.print(s); is a statement, so its output appears exactly at its place in the sequence, with no newline.
R composition rule (with a neighbour)with println: System.out.println(s); is a statement, so its line of output appears at its place in the sequence; swapping two println statements swaps the output lines.
R composition rule (with a neighbour)with control_flow: Control flow is the order in which statements run; without control statements it is straight-line, each once in order.
R composition rule (with a neighbour)with empty_statement: A lone ; is the empty statement, which does nothing; it can fill a for-loop part or, by accident, end an if or loop header.
P plan / role rulePurpose: a statement is the unit of action; a program is characterized by its sequence of statements, each doing one step of the algorithm.
C conservation ruleSwapping two statements that touch the same variable or the output generally changes the result; swapping independent statements, or changing only whitespace between them, keeps it.
D error rulerule broken: Each simple statement must end with ; (compile-time)
D error rulerule broken: A ; directly after an if/while/for header is an empty statement (silent logic error)
X applicability ruleWrite one statement per step and order them as the algorithm requires; straight-line sequence suffices when every step runs once, otherwise use conditionals or loops.
