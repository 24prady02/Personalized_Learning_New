Rules of the concept (12)

Book (SW-1e, p. 17 (pdf 27)): “study a table of the variable values after each statement (such a table is known as a trace).”
Book (SW-1e, p. 78 (pdf 88)): “Even an expert programmer will tell you that the only way to understand a program like this is to trace it”
Rule typeRule
E folk-meaning ruleFolk meaning: code is read like prose or a set of maths equations, all true at once, and 'tracing' means sketching it over. Java (notional machine) rule: statements execute one at a time in order and change variable values, so a trace is a table with one row per executed statement showing each variable's current value.
T uneven-application rulePoints to LT (one row per executed statement, in execution order, computed from the previous row's values). Applied unevenly: the student uses a stale or wrong value of a variable in some rows, skips rows for repeated loop passes, or records a value change that the statement did not make.
N identity ruleA trace is a table of the values of the program's variables after each statement, used to examine what code does.
S declarative ruleA trace has one column per variable and one row per executed statement, in execution order; each row shows the value of every variable after that statement, with a declared but unassigned variable shown as undefined.
LT operational sequencing ruleFollow the flow of control: take the next statement to execute (re-visiting loop bodies on each pass), evaluate it using the current row's values, and write a new row with the variables it changed; continue until the program ends.
OP evaluation / result ruleThe last row gives the final values (and any printed output follows from them): for int t = a; a = b; b = t; starting from a = 1234, b = 99, the final row is a = 99, b = 1234, t = 1234.
OS state-transition ruleEach row differs from the previous one only in the variable(s) assigned by that statement; all other columns are copied unchanged.
R composition rule (with a neighbour)with assignment: Each assignment statement produces the next row of the trace, changing exactly the column of the variable on its left-hand side.
P plan / role ruleUsed to check or discover what a piece of code does (e.g. convince yourself that three statements swap a and b) and to debug; tracing a few rows often reveals the purpose of the whole.
C conservation ruleA trace shows the effect of a change: reordering the swap's statements (int t = a; b = t; a = b;) produces a different final row in which both variables hold the original a; the trace of the correct swap keeps the invariant that the old value of a is saved in t before a is overwritten.
D error rulerule broken: Each row must be computed from the current values, in execution order. (silent logic error)
X applicability ruleTrace small or unfamiliar code, loops and suspected bugs by hand; for larger programs, reason about what the parts compute (roles, invariants) or let the program print its variables, since a mental trace can hold only a few values at once.
