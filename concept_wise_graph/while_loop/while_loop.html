Rules of the concept (38)

Book (SW-1e, p. 49 (pdf 59)): “The while statement has the same form as the if statement (the only difference being the use of the keyword while instead of if), but the meaning is quite different.”
Book (OT-While, ): “The while statement continues testing the expression and executing its block until the expression evaluates to false.”
Book (SW-1.3, ): “The while loop enables us to execute a group of statements many times.”
Rule typeRule
E folk-meaning ruleFolk meaning: English 'while' means 'during the time that', so the activity stops the instant the condition stops holding (the 'while demon'). A Java while tests its condition only before each pass; a pass that has started always finishes.
M wrong rule / right ruleIfIsLoop: wrong: an if body repeats while its condition holds | right: An if body runs at most once; only a loop repeats its body.
M wrong rule / right ruleLoopBodyAlwaysOnce: wrong: The loop body always runs at least once, even if the condition is false at the start. | right: A while or for body runs zero times when the condition is false at the start.
M wrong rule / right ruleLoopForOneTimeTest: wrong: Uses a loop where a condition needs to be tested only once. | right: A test made once is an if; a loop repeats.
M wrong rule / right ruleLoopTerminatingCondition: wrong: For and while loops end when the condition becomes true. | right: A for or while loop ends when its condition becomes false.
M wrong rule / right ruleWhileStopsMidBody: wrong: The loop stops the moment the condition becomes false, even in the middle of the body. | right: The condition is tested only before each pass, so the whole body finishes before the loop can stop.
M wrong rule / right ruleInfiniteLoopUnnoticed: wrong: a condition that never goes false still terminates | right: A while loop stops only when its condition is false at a check, so if no pass changes the variables in the condition, it never stops.
M wrong rule / right ruleJavaDetectsInfiniteLoops: wrong: If my loop never ends, the compiler or Java will warn me. | right: Java cannot detect infinite loops in general; you must check that the loop condition eventually becomes false.
M wrong rule / right ruleForWhileNotInterchangeable: wrong: Some loops can only be written with for, others only with while. | right: Any for loop can be rewritten as a while loop and vice versa; for just packages init, test and update.
M wrong rule / right ruleLoopImpliedByOneTest: wrong: Testing one case is enough; Java will repeat the test for the other values by itself. | right: A statement runs once each time control reaches it; repeating a test for many values needs a loop.
M wrong rule / right ruleProgramEndsAfterLoop: wrong: When a loop finishes the program ends, so code after the loop never runs. | right: When the loop condition becomes false, control continues with the first statement after the loop.
M wrong rule / right ruleFalseLoopRepeatsNextCode: wrong: A loop is an iterative if-else: while the condition is true the body repeats, and when it is false the code after the loop repeats. | right: Only the body is repeated; once the condition is false the code after the loop runs once.
M wrong rule / right ruleLoopCountByIntent: wrong: How many times a loop runs is decided by what the program is meant to do, so it may go on after its condition is false. | right: The loop runs only while its condition is true when tested; it stops at the first false test.
M wrong rule / right ruleLoopConditionValidatedLater: wrong: If a loop condition is false at first but would become true later, the loop still runs (it repeats or skips until the condition is true, then runs until it is false). | right: A while loop whose condition is false at the first test runs zero times; nothing later revives it.
M wrong rule / right ruleLoopVariableNotUpdated: wrong: A while loop ends by itself even if nothing in the body changes the variable tested in the condition. | right: If no statement in the body changes a variable in the condition, a condition that was true stays true and the loop never ends.
M wrong rule / right ruleSingleIterationInsteadOfLoop: wrong: A task that must be repeated is written once, without a loop, as if one pass were enough. | right: A step that must happen several times (or an unknown number of times) needs a loop such as while or for; code without a loop runs once.
T uneven-application ruleApplies the while rule (LT) unevenly: tests the condition before some passes but not others, stops in the middle of a body on one pass, or runs the first pass without testing.
N identity ruleThe while statement is a loop (iteration statement): it repeats a body as long as a boolean condition is true.
S declarative ruleSyntax: while (<boolean expression>) { <statements> } (braces optional for one statement). Meaning: if the expression is false do nothing; if true, execute the body, then check the expression again, and continue as long as it is true.
LT operational sequencing rule1. Evaluate the condition. 2. If false, skip the body and continue after the loop. 3. If true, execute the whole body, then go back to step 1.
OP evaluation / result ruleA while statement has no value; its result is the state and output after the passes it made: e.g. TenHellos with i = 4 and i <= 10 prints 4th to 10th Hello (7 passes) and leaves i = 11.
OS state-transition ruleOne pass: test the condition with the current values, then (if true) apply every body statement once in order; the variables assigned in the body change and nothing else; a false test ends the loop with the state unchanged.
R composition rule (with a neighbour)with boolean_expression: The loop condition is a boolean expression evaluated before every pass; the loop stops the first time it is false, so the body must eventually make it false.
R composition rule (with a neighbour)with do_while_loop: do { body } while (c); means the same as while (c) { body } except that the first test is omitted, so the body runs at least once.
R composition rule (with a neighbour)with break_statement: break exits the loop immediately, so a while loop can end either by a false test or by a break; while (true) needs a break (or is infinite).
R composition rule (with a neighbour)with animation: An animation repeats clear/draw/show/pause steps inside a loop, typically one that runs indefinitely.
R composition rule (with a neighbour)with convergence_test: A convergence test is the while condition that keeps refining an estimate until the error is within tolerance, e.g. while (Math.abs(t - c/t) > epsilon * t).
R composition rule (with a neighbour)with loop_body: The body is the block that the while repeats; it runs only after a true test and is completed before the next test.
R composition rule (with a neighbour)with loop_variable: The while condition usually tests a loop variable that is initialized before the loop and updated in the body; if the body never changes it, the loop never ends.
R composition rule (with a neighbour)with loop_invariant_reasoning: To trust a while loop, state what stays true on every pass and why the condition eventually becomes false (e.g. v is always a power of 2, v increases, so the loop terminates).
R composition rule (with a neighbour)with number_conversion: Binary conversion uses while loops: one to find the largest power of 2 <= N, and one to cast out powers of 2 in decreasing order.
P plan / role rulePlan: indefinite (event-controlled) repetition - repeat until something happens whose number of passes is not known in advance (until convergence, until broke or goal); the condition variable is often a stepper or most-recent holder.
C conservation ruleChanging < to <= adds exactly one pass at the boundary; removing the update from the body makes a loop that was entered never end; a condition that is false initially gives zero passes whatever the body does. Rewriting as for (init; cond; update) preserves behaviour if no continue is involved.
D error rulerule broken: A ; right after if (...) is an empty statement that forms the whole then branch; the following statement or block is no longer part of the if. (silent logic error)
D error rulerule broken: A ; right after while (...) or for (...) is an empty statement that is the whole loop body; the block written next is not repeated. (silent logic error)
D error rulerule broken: A while loop tests its condition before the first pass, using the values set before the loop. (silent logic error)
D error rulerule broken: The body must eventually make the condition false. (silent logic error)
X applicability ruleUse while when the number of passes depends on what happens during the loop (convergence, input, simulation) or the loop variable is needed after the loop; use for for counted loops, do-while when the body must run at least once, and if when the test is needed only once.
