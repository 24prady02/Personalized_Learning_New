Rules of the concept (13)

Book (LI, ): “The else clause always matches the most recent unmatched if clause in the same block.”
Rule typeRule
E folk-meaning ruleFolk meaning: on paper the layout shows which 'if' an 'otherwise' answers, so an else lined up with the outer if is read as belonging to it. Java ignores indentation and attaches each else to the innermost if to which it might possibly belong.
M wrong rule / right ruleElseMatchesIndentation: wrong: The else belongs to the if it is lined up with. | right: The else belongs to the most recent unmatched if, whatever the indentation.
T uneven-application ruleApplies the matching rule (LT) unevenly: attaches the else to the inner if in one fragment but to the outer if in a similarly indented one.
N identity ruleThe dangling else is the ambiguity of an else after two nested ifs without braces: it could belong to either if.
S declarative ruleJava decrees that an else clause belongs to the innermost if to which it might possibly belong: if <e1> if <e2> A else B means if <e1> { if <e2> A else B }.
LT operational sequencing ruleParse first: match each else with the nearest preceding unmatched if; then execute: test e1; only if true test e2, running A if e2 is true and B if e2 is false; if e1 is false nothing runs.
OP evaluation / result ruleFor if (x > 0) if (y > 0) A; else B;: x > 0, y > 0 runs A; x > 0, y <= 0 runs B; x <= 0 runs neither, even if the else was indented under the outer if.
OS state-transition ruleOne execution tests e1 and, only if it is true, e2; it runs at most one of A and B.
R composition rule (with a neighbour)with nested_conditionals: The dangling else arises only when ifs are nested without braces; adding braces around the inner if lets the else belong to the outer if.
P plan / role rulePurpose: not a technique but a pitfall to recognise; braces state the intended pairing explicitly.
C conservation ruleAdding braces { if (e2) A } before the else moves the else to the outer if and changes the behaviour for e1 false; re-indenting the code changes nothing.
D error rulerule broken: An else belongs to the innermost unmatched if. (silent logic error)
X applicability ruleWhenever an if without braces contains another if and an else follows, add braces to state which if the else belongs to; coding standards require brackets for this reason.
