Rules of the concept (19)

Book (SW-1e, p. 108 (pdf 118)): “we code the loop exit test in the while statement as a guard against an illegal statement in the body of the loop”
Rule typeRule
E folk-meaning ruleFolk meaning: in English, 'while the dog is in the city, keep walking' is monitored continuously, so the walk stops the instant it leaves. Java rule: the while condition is tested only before each pass, so the guard must make every index used in the body legal at that moment.
M wrong rule / right ruleBodyChangeIgnoredByCondition: wrong: Changing the loop variable inside the body does not affect the loop condition; the loop still runs its planned number of times. | right: The condition is tested with the current value of the variable, including changes made in the body.
M wrong rule / right ruleLoopCountByIntent: wrong: How many times a loop runs is decided by what the program is meant to do, so it may go on after its condition is false. | right: The loop runs only while its condition is true when tested; it stops at the first false test.
M wrong rule / right ruleLoopConditionValidatedLater: wrong: If a loop condition is false at first but would become true later, the loop still runs. | right: A while loop whose condition is false at the first test runs zero times; nothing later revives it.
M wrong rule / right ruleLessGreaterSwapped: wrong: < and > mean the same thing (or a < b means a is greater than b). | right: a < b is true when a is smaller than b; a > b when a is larger.
M wrong rule / right ruleLoopVariableNotUpdated: wrong: A while loop ends by itself even if nothing in the body changes the variable tested in the condition. | right: If no statement in the body changes a variable in the condition, a condition that was true stays true and the loop never ends.
T uneven-application rulePoints to LT: the guard is tested before every pass, and the body runs only if it is true. Inconsistent application: the trace applies the bounds test only at the first pass, or after the body has already used the out-of-range index.
N identity ruleIdentity: a loop guard is a loop-continuation test that also guards the body against an illegal statement, typically an out-of-bounds array access.
S declarative ruleDeclarative: code the loop exit test so that whenever the body runs, all indices it uses are legal, e.g. while (x > 0 && x < N-1 && y > 0 && y < N-1) before reading a[x-1][y], a[x+1][y], ...
LT operational sequencing ruleSequencing: before each pass the guard is evaluated left to right, and && stops at the first false operand; the body runs only if the whole guard is true; after the body the guard is tested again with the updated values.
OP evaluation / result ruleResult: the loop ends normally, with no exception, when an index reaches the boundary; in SelfAvoidingWalk that means the dog has escaped.
OS state-transition ruleState transition: one guard evaluation changes no variable; it either admits one more pass with legal indices or ends the loop.
R composition rule (with a neighbour)with array_bounds: Because an out-of-bounds index stops the program, the guard tests the bounds before the body uses the index, and it must cover every neighbour index (x-1, x+1) the body reads.
P plan / role rulePlan/role: the guard-before-use plan. A single test both terminates the loop (event: reached the edge) and protects every array access in the body.
C conservation ruleConservation: inside the body the guard's invariant holds (0 < x < N-1, so x-1 and x+1 are legal indices). Weakening the guard (x >= 0) or putting the array test before the bounds test in && breaks it.
D error rulerule broken: The guard must make every index in the body legal. (run-time exception)
D error rulerule broken: The body must change a variable in the guard. (silent logic error)
D error rulerule broken: The relational operators must express the intended bound. (silent logic error)
X applicability ruleApplicability: use a guarded while loop when iteration continues until a data-dependent event and the body indexes an array with a moving position (walks, searches). For a full traversal, a for loop with i < a.length is the simpler guard.
