Rules of the concept (15)

Book (SW-1e, p. 21 (pdf 31)): “if the result is too large to fit into int's 32-bit representation, then it will be truncated in a well-defined manner.”
Book (SW-1e, p. 21 (pdf 31)): “This situation is known as overflow.”
Book (OT-Datatypes, ): “By default, the int data type is a 32-bit signed two's complement integer”
Rule typeRule
E folk-meaning ruleEveryday arithmetic assumes a bigger result just takes more digits. A Java int keeps only 32 bits, so a result that is too large wraps silently to a wrong (often negative) value.
M wrong rule / right ruleIntOverflowWidensAutomatically: wrong: An int result that is too large is automatically stored as a bigger number. | right: int arithmetic is 32-bit; a result outside the range wraps around.
T uneven-application rulePoints to LT (each int operation wraps as soon as it leaves the range). Applied unevenly, a student wraps one step but writes a + 1 for a = Integer.MAX_VALUE as 2147483648.
N identity ruleOverflow: the situation where an integer result is too large or too small for its type's fixed bits and is truncated, wrapping around.
S declarative ruleint and long arithmetic is done in 32-bit and 64-bit two's complement. An out-of-range result keeps only its low-order bits, and no error or exception is raised.
LT operational sequencing ruleOverflow happens in the single operation whose result leaves the range, before any later widening. With int a and b, long x = a * b; overflows in 32-bit int arithmetic before the result is converted to long.
OP evaluation / result ruleInteger.MAX_VALUE + 1 is -2147483648, 2 * Integer.MAX_VALUE is -2, and Math.abs(-2147483648) is -2147483648.
OS state-transition ruleThe variable receives the wrapped value and nothing signals the error, so later statements carry on with it.
R composition rule (with a neighbour)with int: Overflow is possible because int has a fixed 32-bit range, -2^31 to 2^31 - 1.
R composition rule (with a neighbour)with integer_constants: Integer.MAX_VALUE and Integer.MIN_VALUE mark the edges of the range. Testing a > Integer.MAX_VALUE - b before computing a + b avoids overflow.
P plan / role ruleKnowing about overflow lets you guard against it: use long for products, factorials and large sums, or check against MAX_VALUE before computing.
C conservation ruleChanging int to long moves the overflow point (to about 9.2e18) but does not remove it. Dividing before multiplying can avoid overflow at the cost of truncation. Casting a result that has already overflowed does not repair it.
D error rulerule broken: int results are limited to 32 bits, and overflow is not reported. (silent logic error)
D error rulerule broken: An all-int expression is computed in int even when its result is stored in a long. (silent logic error)
X applicability ruleThink about overflow whenever values can reach the billions. Use long (or a long operand, such as 1000L) for those, BigInteger for unbounded integers, and plain int for small counts and indices.
