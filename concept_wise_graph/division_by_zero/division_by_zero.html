Rules of the concept (17)

Book (SW-1e, p. 37 (pdf 47)): “The first generates a run-time exception for division by zero (which stops your program because the value is undefined); the second is legal and has the value Infinity.”
Book (SW-1.2, ): “(17 / 0) and (17 % 0) result in a division by zero exception; (17.0 / 0.0) results in a value Infinity; (17.0 % 0.0) results in a value NaN that stands for 'not a number.'”
Rule typeRule
E folk-meaning ruleFolk meaning: in maths division by zero is 'impossible', so every x / 0 must be rejected, ideally by the compiler. Java rule: the compiler accepts it; int or long / and % by zero throw ArithmeticException at run time, while double division by zero is legal and gives Infinity or NaN.
M wrong rule / right ruleDivisionByZeroIsCompileError: wrong: System.out.println(5 / 0); is rejected by the compiler. | right: It compiles; the ArithmeticException (/ by zero) is thrown when the program runs and reaches the division.
M wrong rule / right ruleZeroDivisionAlwaysCrashes: wrong: Dividing by zero always stops the program with an error. | right: Only integer division (and remainder) by zero throws; 1.0/0.0 is Infinity and 0.0/0.0 is NaN, and the program keeps running.
T uneven-application rulePoints to LT (both operands are evaluated, promotion decides whether the division is int or double, and only then is the divisor checked). Applied unevenly: the student lets 1/0.0 crash because the 1 is an int, or lets 1/0 give Infinity on one line and an exception on another.
N identity ruleDivision by zero is the evaluation of x / 0 or x % 0: a run-time error for integer types and a special value (Infinity or NaN) for floating-point types.
S declarative ruleAn integer / or % throws ArithmeticException if the right operand is zero; floating-point arithmetic follows IEEE 754, so a nonzero double divided by zero is Infinity or -Infinity and 0.0/0.0 is NaN. With doubles, 1.0 / 0.0 is Infinity and 0.0 / 0.0 (or Math.sqrt(-1.0)) is NaN; NaN is not equal to anything, not even itself.
LT operational sequencing ruleLeft operand, then right operand are fully evaluated; then the division itself runs: for int it checks the divisor and throws at that moment, so the rest of the statement (the assignment or the println) never happens; for double it produces the special value and evaluation continues.
OP evaluation / result rule1/0 and 1%0 produce no value: the program stops with Exception in thread "main" java.lang.ArithmeticException: / by zero; 1.0/0.0 is Infinity, -1.0/0.0 is -Infinity, 0.0/0.0 is NaN, and 1/0.0 is Infinity (the 1 is promoted).
OS state-transition ruleFor int, no variable changes: the exception aborts the statement and (uncaught) ends the program. For double, the target gets Infinity or NaN; NaN then propagates through later arithmetic and every comparison with it (even ==) is false.
R composition rule (with a neighbour)with arithmetic_operators: The zero check belongs to the int / and % operators: they always produce an int except when the divisor is zero, in which case they throw; + - * never throw.
R composition rule (with a neighbour)with double: Once either operand is a double the division follows IEEE 754 rules instead, so the same zero divisor gives Infinity or NaN rather than an exception.
P plan / role rulePlan: guard the division (if (count > 0) average = sum / count;), a guard test placed before the risky operation; Infinity is used on purpose as an initial value for a minimum search (Double.POSITIVE_INFINITY).
C conservation ruleChanging an operand from int to double turns a crash into a silent Infinity or NaN (and changing it back turns the silent value into a crash); adding a zero guard leaves results for nonzero divisors unchanged.
D error rulerule broken: A divisor must be checked to be nonzero before dividing; an average of zero values is undefined. (run-time exception)
D error rulerule broken: Integer / and % require a nonzero right operand. (run-time exception)
D error rulerule broken: A floating-point division by zero yields Infinity or NaN instead of a number. (silent logic error)
X applicability ruleGuard every integer division whose divisor could be zero; rely on Infinity only when it is the intended value (e.g. as a sentinel for min); when the result is undefined (empty input) handle the case explicitly instead of printing NaN.
