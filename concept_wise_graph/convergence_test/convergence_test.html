Rules of the concept (16)

Book (SW-1e, p. 76 (pdf 86)): “The number of iterations depends on an equality test between double values, which may not always give the result that you expect.”
Book (SW-1.3, ): “If t is equal to x/t (up to machine precision)…”
Rule typeRule
E folk-meaning ruleFolk meaning: in maths a converging sequence reaches its limit, and 'equal' means exactly equal, so a novice writes `while (t != c/t)` and expects it to stop at the root. Java doubles are approximations, so exact equality may never occur and the test has to be 'close enough': `Math.abs(t - c/t) > epsilon * t`.
M wrong rule / right ruleFloatingPointIsExact: wrong: `Math.sqrt(2) * Math.sqrt(2) == 2` is true. | right: A double is an approximation, so the product is close to 2 but not equal to it (the expression is false). Loop tests on doubles therefore compare an error against a tolerance instead of testing equality.
T uneven-application ruleApplies the LT rule (compute the error, compare it with the tolerance, then refine) unevenly: refines once more after the test has gone false, or tests the old estimate against the new c/t, so the traced number of iterations or the final t is wrong.
N identity ruleLoop-termination idiom: a while condition that keeps refining a floating-point estimate until its error falls below a tolerance epsilon.
S declarative ruleStop on a relative-error tolerance, not on equality: `while (Math.abs(t - c/t) > epsilon * t) t = (c/t + t) / 2.0;` with `epsilon = 1e-15`.
LT operational sequencing ruleBefore each pass: evaluate c/t, then t - c/t, then Math.abs, then epsilon * t, then compare. If the error is greater, run the body once (replace t) and test again. If it is not greater, leave the loop with the current t.
OP evaluation / result ruleThe loop leaves a double t whose relative error is at most epsilon. For Sqrt 2.0 it prints 1.414213562373095 after 5 iterations; the result is not exactly the mathematical value.
OS state-transition ruleOne pass changes only the estimate t, replacing it by (c/t + t)/2.0 (2.0 becomes 1.5, then 1.4166666666666665). c and epsilon stay fixed. The test itself changes nothing and yields a boolean.
R composition rule (with a neighbour)with floating_point_precision: Because doubles are approximate, the stopping condition has to be a tolerance test, and the tolerance has to be relative (`epsilon * t`). An absolute 1e-15 is smaller than the spacing between doubles near large values such as 1595.16, so the test might never succeed (t and c/t can keep differing by one unit in the last place).
R composition rule (with a neighbour)with while_loop: The convergence test is the while condition, evaluated before every pass. The body must move the estimate closer (t = (c/t + t)/2.0), or the condition stays true and the loop never ends.
P plan / role rulePlan: iterate-until-converged (Newton's method). The estimate t is repeatedly replaced by a better one until it is close enough. Used to compute functions like sqrt, kth roots and Taylor sums.
C conservation ruleMaking epsilon smaller adds a few iterations and keeps the answer; making it 0, or replacing the test with `t != c/t`, may stop the loop from ever ending. Switching the relative test `epsilon * t` to an absolute `epsilon` keeps behaviour for small c but can hang for large c. Changing the starting t changes only the iteration count.
D error rulerule broken: Do not test doubles for exact equality in a loop condition. (silent logic error)
D error rulerule broken: The tolerance must be achievable at the magnitude of the result (relative error). (silent logic error)
D error rulerule broken: The iteration converges only for inputs that have a root. (silent logic error)
X applicability ruleUse a convergence test when an iterative numeric method has no fixed number of steps (Newton's method, series that are summed until `sum == sum + term`). For a known number of steps use a counted for loop, and in practice call the library method (Math.sqrt) when one exists.
