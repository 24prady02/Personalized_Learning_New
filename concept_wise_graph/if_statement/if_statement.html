Rule typeRule
E folk-meaning ruleFolk meaning: English 'if' (and 'whenever') states a standing rule that stays in force and fires whenever its condition becomes true. A Java if is evaluated once, when control reaches it, and then is 'taken off the books'; changing the variables later does not re-trigger it.
M wrong rule / right ruleAssignCompares: wrong: = compares two values instead of assigning | right: x = y copies the value of y into x; x == y is what compares them.
M wrong rule / right ruleCodeAfterIfSkipped: wrong: When the then branch runs, the code after the if is skipped. | right: After the if finishes, execution continues with the next statement either way.
M wrong rule / right ruleFalseConditionEndsProgram: wrong: A false condition with no else ends the program. | right: When an if condition is false and there is no else, execution continues with the statement after the if.
M wrong rule / right ruleIfIsLoop: wrong: an if body repeats while its condition holds | right: An if body runs at most once; only a loop repeats its body.
M wrong rule / right ruleIfRequiresElse: wrong: Every if statement requires an else. | right: An if statement may stand alone; the else part is optional.
M wrong rule / right ruleLoopForOneTimeTest: wrong: Uses a loop where a condition needs to be tested only once. | right: A test made once is an if; a loop repeats.
M wrong rule / right ruleMapToBooleanWithIf: wrong: you need an if to turn a boolean expression into a boolean | right: ok = (x > y); stores the result of the comparison directly.
M wrong rule / right ruleNextStatementIsElse: wrong: In if (c) A; B; the statement B runs only when c is false. | right: B is not part of the if; it runs every time.
M wrong rule / right ruleThenAlwaysExecutes: wrong: The then branch always runs. | right: The then branch runs only when the condition is true.
M wrong rule / right ruleIfWaitsForCondition: wrong: An IF statement earlier in the program stays active and fires later, e.g. inside a later loop, when its condition becomes true. | right: An if is evaluated once when control reaches it; afterwards it is inactive unless control returns to it.
M wrong rule / right ruleProgramLooksAhead: wrong: The program knows or sees what later lines will do and acts on those goals at the current line, e.g. it stops 'at ten' because it wants to draw a box. | right: Each statement executes using only the current state; later lines have no effect until control reaches them.
M wrong rule / right ruleBranchChosenByIntent: wrong: Which branch runs is decided by what the programmer meant or by code outside the if, not by whether the condition is true. | right: The then branch runs exactly when the condition evaluates to true at the moment it is tested; otherwise the else branch (if any) runs.
M wrong rule / right ruleStatementAfterIfInBranch: wrong: A statement placed after the if statement belongs to its branch, so it runs only when the condition is true. | right: The branch ends at its closing brace (or after its single statement); the next statement runs whatever the condition was.
M wrong rule / right ruleFalseConditionRestartsProgram: wrong: When an if condition is false (and there is no else), control jumps back to the start of the program. | right: A false condition skips the then branch and execution continues with the statement after the if statement.
M wrong rule / right ruleIfConditionWatched: wrong: An if statement watches its condition while the program runs and fires as soon as the condition becomes true (if = whenever). | right: An if condition is tested once, when control reaches the if statement; later changes to the variables do not trigger the branch.
M wrong rule / right ruleIfConditionCheckedInHindsight: wrong: Whether the branch runs is decided by the condition after the branch, or from the point inside the body where the condition becomes true. | right: The condition is tested once, before the branch; the whole branch runs if it was true at that moment and none of it runs otherwise.
M wrong rule / right ruleSequentialIfsAreNested: wrong: Of two if statements one after the other, the second runs its body only if both conditions are true. | right: Two ifs in sequence are independent: each tests only its own condition.
M wrong rule / right ruleIfInLoopUnchecked: wrong: An if inside a loop body runs its branch on every pass without testing its condition. | right: The if condition is tested again on every pass, with the current values, so the branch runs only on passes where it is true.
T uneven-application ruleApplies the if rule (LT) unevenly: tests the condition on some visits but not others (e.g. runs the branch on every loop pass without testing), runs the branch after a false test, or re-checks the condition after the branch has run.
N identity ruleThe if statement is a conditional (selection) statement: it runs a statement or block only when a boolean condition is true.
S declarative ruleSyntax: if (<boolean expression>) <statement or { block }>; the braces are optional when the body is a single statement. The expression must have type boolean (or Boolean), and the body is executed if and only if the expression is true.
LT operational sequencing ruleEvaluate the condition once; if true, execute the body; then, in either case, continue with the statement after the if.
OP evaluation / result ruleAn if produces no value; its observable result is that the body's effects (assignments, output) happen exactly once when the condition is true and not at all when it is false; e.g. if (x < 0) x = -x; leaves x = 5 for 5 and gives 5 for -5.
OS state-transition ruleOne execution reads the variables in the condition, changes nothing by the test itself (unless the condition has a side effect), and, when true, applies the body's changes once; control then moves to the next statement.
R composition rule (with a neighbour)with boolean_expression: The condition must be a boolean expression; a non-boolean condition such as if (t = goal) with int t is a compile-time error, while if (b = false) with boolean b compiles and assigns.
R composition rule (with a neighbour)with if_else_statement: if-else extends if with a second branch that runs exactly when the condition is false; a lone if has an implicit empty else-case.
R composition rule (with a neighbour)with control_flow: An if is a fork in the control flow: one path through the body, one around it, both rejoining at the next statement.
P plan / role rulePlan: guard / conditional action - do something only for the inputs that need it (absolute value, put two values in order, error check before dividing).
C conservation ruleNegating the condition swaps which inputs run the body; changing < to <= changes only the boundary value. Adding a statement under a braceless if does not put it in the body. Whatever the condition, code after the if still runs exactly once.
D error rulerule broken: The if template is if (<boolean expression>) <statement>: the condition must be enclosed in parentheses. (compile-time)
D error rulerule broken: A ; right after if (...) is an empty statement that forms the whole then branch; the following statement or block is no longer part of the if. (silent logic error)
D error rulerule broken: Without braces, the body of an if, while or for is exactly one statement; indentation does not add statements to it. (silent logic error)
D error rulerule broken: The condition of an if must have type boolean. (compile-time)
D error rulerule broken: With boolean operands, = is assignment, not comparison. (silent logic error)
X applicability ruleUse an if when an action is needed for some inputs only and the test happens once at that point; use a loop if the action must repeat while the condition holds, and assign a boolean directly (ok = x > y;) when you only need the truth value.
