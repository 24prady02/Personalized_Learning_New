primitive_vs_reference (id primitive_vs_reference, section 1.4 Arrays, topic 1.4.b Memory representation and bounds checking)

Description: a primitive variable holds its value; an array (or String) variable holds a reference to the object stored elsewhere
Contained in topic: topic1.4.b

Rules of the concept (15)

Book (SW-1e, p. 97 (pdf 107)): “it just performs the standard operation as if the array name were a variable whose value is the memory address of the array.”
Book (TJ-2e, p. 147 (pdf 169)): “Not everything in Java is an object: int, double, char, and boolean are primitive types. When you declare a variable with a primitive type, Java reserves a small amount of memory to store its value.”
Book (TJ-2e, p. 148 (pdf 170)): “As you learned in Section 7.2, an array variable stores a reference to an array.”
Rule typeRule
E folk-meaning ruleEveryday thinking pictures a variable as a box that holds the thing itself. That is true for int, double, char and boolean; an array variable holds only the address of the array, which is stored elsewhere.
M wrong rule / right ruleVariablesHoldObjects: wrong: A reference variable holds the whole object, not a reference. | right: An array variable stores a reference (the memory address) to the array, not the elements.
M wrong rule / right ruleStringIsPrimitive: wrong: String is a primitive type like int. | right: Java has eight primitive types; String is not one of them, and a String variable holds a reference.
T uneven-application ruleApplies the model unevenly: treats int x = y as copying a value (correct) but also treats b = a for arrays as copying all the elements.
N identity rulePrimitive versus reference variable: the first holds its value, the second holds the address of an object.
S declarative ruleWhen you declare a variable of a primitive type, Java reserves memory that stores its value. An array variable stores a reference to the array: Java treats the array name as a variable whose value is the memory address of the array.
LT operational sequencing ruleSequencing: x = y copies the value of y into x; b = a copies the address in a into b. In both cases the right side is evaluated first and its value stored, but the value of an array variable is an address.
OP evaluation / result ruleResult: after int y = x; y++, x is unchanged; after int[] b = a; b[0]++, a[0] has changed too, because a and b refer to the same array.
OS state-transition ruleState transition: assigning to a primitive variable changes only that variable; assigning to an element through a reference changes the array that every reference to it sees.
R composition rule (with a neighbour)with primitive_type: The eight primitive types are the ones whose variables hold the value itself.
R composition rule (with a neighbour)with array_reference: An array variable is the standard example of a reference: its value is the memory address of the array.
P plan / role rulePlan: the model predicts when an assignment shares data (arrays, Strings) and when it copies it (primitives), which decides when a copy is needed.
C conservation ruleConservation: changing a primitive copy never affects the original; changing an array through any reference affects every alias.
D error rulerule broken: == on references compares addresses. (silent logic error)
X applicability ruleDraw a memory diagram (value in a box for primitives, an arrow to the array for references) whenever code assigns or compares arrays.
