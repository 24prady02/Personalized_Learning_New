Rules of the concept (24)

Book (SW-1e, p. 8 (pdf 18)): “Some errors, known as compile-time errors, are caught when you compile the program, because they prevent the compiler from doing the translation.”
Book (SW-1.1, ): “These errors are caught by the system when we compile the program,”
Rule typeRule
E folk-meaning ruleEveryday reading: 'error' means the program will do something wrong when used, and a message points exactly at the mistake. Java rule: a compile-time error is a breach of the language rules found by javac before any execution; no .class is produced, and the reported line is where javac noticed it.
M wrong rule / right ruleCompilesMeansWorks: wrong: Code that compiles is code that works. | right: Compiling only checks the language rules; code that compiles can still have run-time and logic errors.
M wrong rule / right ruleErrorLineIsFaultLine: wrong: The line number in a javac error is always the line that has the mistake. | right: The compiler reports where it noticed the problem, which can be after the real fault (omitting HelloWorld's second left brace gives errors on later lines).
M wrong rule / right ruleCompilerSuggestionIsFix: wrong: Doing exactly what the compiler message suggests will fix the error. | right: An error message is evidence that something is wrong, but its suggested remedy may be wrong; find the actual cause.
T uneven-application ruleApplies the 'javac checks before running' rule unevenly: predicts output for a program that would not compile, or expects a compile error from a fault (such as division by zero) that only shows at run time.
N identity ruleA compile-time error (syntax error) is an error in the source code, caught by javac, that prevents the program from being translated.
S declarative ruleCompile-time errors occur when the code violates the rules of the Java language (syntax, names, types); they are caught when you compile and prevent the translation.
LT operational sequencing rulejavac reads the whole file, reports each error with file name, line number and message, tries to recover and continue, and prints a count; the first message is the most reliable.
OP evaluation / result ruleResult: messages such as Bad.java:4: ';' expected ... 3 errors, and no Name.class; nothing of the program runs.
OS state-transition ruleA failed compile leaves the file system without a new Name.class (an older one, if any, is not updated) and changes no program state.
R composition rule (with a neighbour)with compile: A compile-time error is reported while javac compiles Name.java, so no new Name.class is produced.
R composition rule (with a neighbour)with reading_error_messages: Each compile-time error comes with a message; reading it (first error first, line may be late) is how it is found and fixed.
R composition rule (with a neighbour)with run_time_error: A compile-time error is found by javac before the program runs; a run-time error only while it runs, so code that compiles can still crash.
P plan / role rulePurpose (of the check): catch rule violations automatically before running, so they cannot cause wrong behaviour; S&W say treat the compiler as a friend.
C conservation ruleFixing the first error and recompiling can remove many messages at once; a single missing brace or semicolon can cause several messages.
D error rulerule broken: Library static methods are called with the class name, e.g. Math.sqrt(x) (compile-time)
D error rulerule broken: Every name must be spelled exactly, including capitalization (compile-time)
D error rulerule broken: Each statement must end with ; (compile-time)
D error rulerule broken: Every { must be matched by a } (compile-time)
D error rulerule broken: A /* comment needs its closing */ (compile-time)
D error rulerule broken: A String literal is enclosed in a pair of double quotes (compile-time)
D error rulerule broken: A final variable cannot be reassigned after it is initialized (compile-time)
D error rulerule broken: Required keywords (class, static, void...) must be present and spelled right (compile-time)
X applicability ruleExpect compile-time errors for anything the compiler can check from the text alone (syntax, names, types, final); expect run-time or logic errors for faults that depend on input values or on what the program was meant to do.
