Rule typeRule
E folk-meaning ruleFolk meaning: in everyday life two people swap objects simultaneously, and in maths 'a = b, b = a' reads as a symmetric relation. Java rule: assignments run one at a time, so the first overwrites a value that must be saved in a temporary first.
M wrong rule / right ruleSwapWithoutTemp: wrong: a[i] = a[j]; a[j] = a[i]; exchanges the two values. | right: A temporary variable must save a[i] before it is overwritten: t = a[i]; a[i] = a[j]; a[j] = t;.
T uneven-application rulePoints to LT: save a[i] in t, copy a[j] into a[i], copy t into a[j], in that order. Inconsistent application: the trace performs the second assignment with the old a[i] (as if both happened at once) on some passes.
N identity ruleIdentity: the exchange idiom, three assignments through a temporary variable that trade the values of two array elements.
S declarative ruleDeclarative: T t = a[i]; a[i] = a[j]; a[j] = t; where t has the element type T.
LT operational sequencing ruleSequencing: (1) t receives a[i]; (2) a[i] receives a[j]; (3) a[j] receives t. Each statement uses the state left by the previous one.
OP evaluation / result ruleResult: the values at i and j have traded places. With i = 1 and j = 4 in the deck, 3 of Clubs ends in deck[1] and 2 of Diamonds in deck[4].
OS state-transition ruleState transition: exactly two elements (and t) change; when i == j nothing changes.
R composition rule (with a neighbour)with indexing: The exchange reads and writes elements only through their indices a[i] and a[j], which must both be in bounds.
R composition rule (with a neighbour)with assignment: Each of the three steps is an ordinary assignment whose left side is a single variable (here an array element), executed in order.
R composition rule (with a neighbour)with shuffle: Shuffling is a loop of exchanges with random partner positions; using exchanges guarantees the same cards before and after.
R composition rule (with a neighbour)with array_reversal: Reversal exchanges a[i] with a[N-1-i] for each i in the first half.
P plan / role rulePlan/role: t is a Sajaniemi temporary. The exchange reorders an array (the array as organizer) without changing its set of values, the building block of shuffling, reversing and sorting.
C conservation ruleConservation: the set of values in the array is unchanged; doing the same exchange again restores the original order; i == j leaves the array unchanged. Changing the order of the three statements breaks it.
D error rulerule broken: The old value must be saved before it is overwritten. (silent logic error)
D error rulerule broken: The temporary must have the element type. (compile-time)
D error rulerule broken: Both indices must be legal. (run-time exception)
X applicability ruleApplicability: use the exchange whenever two elements must change places (shuffle, reverse, sort, permute). It is not a copy: to duplicate a value, use one assignment.
