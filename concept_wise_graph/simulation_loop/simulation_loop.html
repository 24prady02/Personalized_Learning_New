Rules of the concept (21)

Book (SW-1e, p. 166 (pdf 176)): “It counts the number of times that the surfer visits each page.”
Book (SW-1.6, p. 166 (pdf 176)): “Dividing that count by the number of moves yields an estimate of the probability that a random surfer winds up on the page. This probability is known as the page's rank”
Rule typeRule
E folk-meaning ruleEveryday "simulate" suggests replaying a known process to get its answer; here each run of RandomSurfer draws fresh random numbers and gives different estimates (100 moves: 0.24 0.23 0.16 0.25 0.12), which only approach the page ranks as T grows.
M wrong rule / right ruleFewTrialsAreExact: wrong: A short simulation gives the exact page ranks. | right: A simulation only estimates the ranks: about 10^n moves for n-digit precision, tens of thousands of moves for two accurate places and millions for three.
M wrong rule / right ruleLoopBodyScopeImpliesLoopLifetime: wrong: A variable declared in the loop body lives across all iterations. | right: r and sum are declared inside the t-loop body and are created anew on every move; freq and page must be declared before the loop to persist.
M wrong rule / right ruleOffByOneBound: wrong: < vs <= and 0..n vs 0..n-1 are interchangeable. | right: for (int t = 0; t < T; t++) makes exactly T moves; with <= it makes T + 1, while the ranks are still divided by T.
T uneven-application ruleApplies LT (draw r, find next page, then freq[page]++) unevenly: e.g. counting the current page before the move on some passes, or resetting sum only on the first pass.
N identity ruleA Monte Carlo simulation: a for loop over t = 0..T-1 that makes one random move per pass and tallies the page reached.
S declarative ruleRandomSurfer reads a transition matrix, starts at page 0, makes T moves (T from the command line) according to the matrix, and counts the visits to each page.
LT operational sequencing rulePer pass: r = Math.random(); sum = 0.0; inner j loop picks the next page; freq[page]++; t++ and test t < T. After the loop, each freq[i] is divided by T and printed.
OP evaluation / result rulePrints N doubles (%8.5f) that sum to about 1 and vary between runs; 1,000,000 moves on tiny.txt gave 0.27324 0.26568 0.14581 0.24737 0.06790.
OS state-transition ruleOne pass changes page (to the next page) and increases freq[page] by 1; t increases by 1.
R composition rule (with a neighbour)with random_move: The loop body is one random move; page carries state from one pass to the next, so each move uses the row of the page reached last.
R composition rule (with a neighbour)with frequency_counting: freq[page]++ must come after the move and inside the loop, once per pass, so the counts total T.
R composition rule (with a neighbour)with for_loop: A counted for loop with t < T fixes the number of moves at T; the loop variable t is scoped to the loop.
R composition rule (with a neighbour)with power_method: Both compute the same page ranks; the power method gets them exactly with far fewer iterations.
P plan / role ruleMonte Carlo estimation plan: repeat a random experiment many times and count outcomes; t is a stepper, page a most-recent holder, freq[] the per-page gatherers.
C conservation ruleChanging the start page keeps the limit (mixing); increasing T keeps the estimates but makes them more accurate (about 10x moves per extra digit); changing < to <= or the division by T breaks the normalisation.
D error rulerule broken: Loop must run t = 0..T-1. (silent logic error)
D error rulerule broken: A variable declared in the body is recreated each pass. (silent logic error)
D error rulerule broken: freq[i] / T must be floating-point division. (silent logic error)
D error rulerule broken: The number of moves is args[0]. (run-time exception)
X applicability ruleUse when the process is easy to simulate and a rough estimate suffices (or no matrix is available); not for accurate ranks or large models, where a huge number of trials is needed and the power method is far more efficient.
