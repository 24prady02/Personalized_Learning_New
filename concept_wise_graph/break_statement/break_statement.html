Rules of the concept (22)

Book (SW-1e, p. 70 (pdf 80)): “In some situations, we want to immediately exit a loop without letting it run to completion.”
Book (SW-1e, p. 70 (pdf 80)): “Java provides the break statement for this purpose.”
Book (OT-Branch, ): “An unlabeled break statement terminates the innermost switch, for, while, or do-while statement, but a labeled break terminates an outer statement.”
Rule typeRule
E folk-meaning ruleFolk meaning: in English 'break' means to pause, or to stop or break out of whatever you are in, so a novice reads it as leaving the enclosing if, as starting the next round, or as stopping the whole program. In Java, `break;` ends only the innermost enclosing loop or switch, and execution continues with the statement after it.
M wrong rule / right ruleBreakExitsIf: wrong: break leaves the if statement it is written in. | right: An if is not a break target: break immediately exits the innermost enclosing loop (or switch) without letting it run to completion.
M wrong rule / right ruleBreakIsContinue: wrong: break starts the next iteration of the loop. | right: break exits the loop immediately; continue is the statement that skips to the next iteration.
M wrong rule / right ruleBreakEndsProgram: wrong: break ends the whole program. | right: break ends only the innermost loop (or switch); execution continues with the statement after it.
M wrong rule / right ruleBreakIgnored: wrong: break has no effect; the loop body just carries on. | right: break leaves the innermost loop at once: the rest of the body, the increment, and all later passes are skipped.
T uneven-application ruleApplies the LT rule unevenly: on some passes the trace continues the body after break, or runs the increment and the test once more after break, so the final loop variable is one too large (e.g. i = 4 instead of 3 when 3 divides N).
N identity ruleJump statement: `break;` immediately ends the innermost enclosing while, for, do or switch.
S declarative rule`break;` may appear only inside a loop or switch. When executed, it completes that innermost loop or switch at once, and control passes to the statement after it. (Spec: JLS §14.15.)
LT operational sequencing ruleWhen `break` executes: the remaining statements of the body are skipped, the for-loop increment and the condition are not evaluated again, and control continues at the first statement after the loop. In `for (i = 2; i <= N/i; i++) if (N % i == 0) break;` it runs right after the test that found a divisor.
OP evaluation / result rulebreak is a statement and produces no value. Its effect shows in the variables it leaves: after the primality loop for N = 15, i is 3 (the smallest divisor), so `i > N/i` is false and 'is prime' is not printed.
OS state-transition ruleOne execution of break changes no variable. It changes only the point of control (to after the loop), so every variable keeps its value at the moment of the break.
R composition rule (with a neighbour)with while_loop: break gives a while loop a second exit, in the middle of the body. After the loop, the program has to tell which exit was taken by re-testing the state (as in `if (i > N/i)`), so any variable used for that test must be declared before the loop.
R composition rule (with a neighbour)with labeled_break: Plain break reaches only the innermost loop. In nested loops, ending the outer loop needs `break label;` on a labeled outer statement (or a flag tested by the outer loop).
R composition rule (with a neighbour)with continue_statement: Both skip the rest of the current body. break then leaves the loop (no increment, no further test); continue goes on to the increment and the next test.
R composition rule (with a neighbour)with switch_statement: In a switch, break ends the switch body; without it, execution falls through into the next case. A break inside a switch that is inside a loop exits only the switch, not the loop.
P plan / role rulePlan: early-exit search (Soloway 'loop-and-a-half' or exit-on-found). Stop scanning as soon as the answer is known, e.g. at the first divisor; the loop variable is a stepper whose value at exit reports the find.
C conservation ruleRemoving the break keeps the loop finite but lets it run to completion. In the prime test, i then ends above N/i for every N, so composites are reported as prime. Invariant kept with break: after the loop, `i <= N/i` holds exactly when the break was taken.
D error rulerule broken: break must be inside a loop or switch. (compile-time)
D error rulerule broken: Statements after break in the same block can never run. (compile-time)
D error rulerule broken: break exits only the innermost loop or switch. (silent logic error)
D error rulerule broken: A variable used after the loop to tell how it ended must be in scope. (compile-time)
X applicability ruleUse break when the reason to stop is discovered in the middle of a pass (first divisor, sentinel found) and folding it into the loop condition would be awkward. Prefer a plain loop condition when the exit can be stated up front. In a method, `return` is often clearer. S&W use break rarely.
