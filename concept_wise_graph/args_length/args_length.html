Rules of the concept (14)

Book (TJ-2e, p. 152 (pdf 174)): “Now that you know about strings, arrays, and wrapper classes, we can finally explain the args”
Book (SW-1.4, ): “takes a variable number of command-line arguments and prints how many there are.”
Rule typeRule
E folk-meaning ruleFolk meaning: like a conversation partner, the program is thought to 'get' the input it expects; arguments are always there. Java rule: args holds exactly the strings typed after the class name, so args.length can be 0 and args[0] exists only when args.length >= 1.
T uneven-application rulePoints to LT: args is built before main runs, and its length is fixed for the run. Inconsistent application: args[0] is read on one line, and args.length is checked only later (or never), as if checking were needed only sometimes.
N identity ruleIdentity: args.length is the length field of main's String[] parameter args; it counts the command-line arguments.
S declarative ruleDeclarative: args is a String[] whose elements args[0] .. args[args.length-1] are the typed arguments, as strings; numbers must be converted with Integer.parseInt or Double.parseDouble.
LT operational sequencing ruleSequencing: the command line is split at whitespace, and the pieces are stored in order in args before main's first statement runs. Reading args.length then behaves like any length field.
OP evaluation / result ruleResult: an int equal to the number of typed arguments: 'java Max' gives 0, and 'java Max 10 -3 55 0 14' gives 5.
OS state-transition ruleState transition: reading args.length changes nothing; args itself is fixed for the whole run.
R composition rule (with a neighbour)with command_line_args: args[i] may be read only for i < args.length; with no arguments even args[0] is out of bounds.
R composition rule (with a neighbour)with length_field: args.length is the ordinary array length field applied to the String[] args.
P plan / role rulePlan/role: validate input before use (print a usage message and return when args.length is too small), or loop over a variable number of arguments.
C conservation ruleConservation: extra arguments do not break code that reads args[0]; fewer arguments than the code reads break it at run time. Adding an args.length check keeps behaviour for correct input and only changes what happens for bad input.
D error rulerule broken: args[i] exists only if i < args.length. (run-time exception)
D error rulerule broken: An argument is a String and must be a valid numeral to be parsed. (run-time exception)
X applicability ruleApplicability: use args.length to validate or iterate over a small, variable number of command-line values. For large or open-ended input, read standard input instead.
