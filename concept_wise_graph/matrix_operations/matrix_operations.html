Rules of the concept (20)

Book (SW-1e, p. 103 (pdf 113)): “We use nested for loops for many array-processing operations.”
Book (SW-1.4, ): “is computed by taking the dot product of row i of a[] with column j of b[].”
Book (LA-Nicholson, ): “If the order of the factors in a product of matrices is changed, the product matrix may change (or may not be defined).”
Rule typeRule
E folk-meaning ruleFolk meaning: 'multiply two tables' suggests multiplying matching entries (as addition adds them), and ordinary multiplication commutes. Rule: each product entry c[i][j] is the dot product of row i of a and column j of b, and AB generally differs from BA.
M wrong rule / right ruleMatrixProductCommutes: wrong: A * B and B * A are the same matrix. | right: Matrix multiplication is not commutative; changing the order may change the product, and for non-square matrices one order may not even be defined.
M wrong rule / right ruleMatrixProductIsElementwise: wrong: c[i][j] = a[i][j] * b[i][j] computes the matrix product. | right: c[i][j] is the dot product of row i of a with column j of b: the sum over k of a[i][k]*b[k][j].
M wrong rule / right ruleWholeArrayArithmetic: wrong: a = a + b adds the arrays element by element. | right: Java has no arithmetic on whole arrays; write nested loops that compute c[i][j] = a[i][j] + b[i][j].
M wrong rule / right ruleColumnLikeRow: wrong: Column j of a 2-D array can be picked out as a 1-D array, just like row a[i]. | right: There is no column expression; the product reads column j of b element by element as b[k][j] in the k loop.
T uneven-application rulePoints to LT: the innermost k loop finishes accumulating c[i][j] before j moves on. Inconsistent application: c[i][j] is reset inside the k loop on some passes, or a[k][i] is used instead of a[i][k].
N identity ruleIdentity: matrix addition and multiplication implemented with nested for loops over 2-D arrays.
S declarative ruleDeclarative: sum c[i][j] = a[i][j] + b[i][j]; product c[i][j] = sum over k of a[i][k]*b[k][j]; the product is defined only when the columns of a equal the rows of b.
LT operational sequencing ruleSequencing: create c (all 0.0); for each i, for each j, for k = 0..N-1 add a[i][k]*b[k][j] into c[i][j]. The k loop completes for each (i, j) before j increases.
OP evaluation / result ruleResult: a new N-by-N double matrix c. In the book's example c[1][2] = .3*.5 + .6*.1 + .1*.4 = .25.
OS state-transition ruleState transition: one innermost step adds one product a[i][k]*b[k][j] to c[i][j]; nothing else changes.
R composition rule (with a neighbour)with two_dimensional_array: Matrices are stored as 2-D arrays and read entry by entry as a[i][j].
R composition rule (with a neighbour)with nested_loops: Addition uses two nested loops (i, j); multiplication adds a third inner loop over k for each dot product.
R composition rule (with a neighbour)with power_method: The power method repeats vector-matrix multiplication rather than matrix-matrix multiplication, because that is all it needs.
P plan / role rulePlan/role: c[i][j] is a gatherer (running sum) for one dot product. The whole computation implements linear-algebra operations used throughout science and engineering.
C conservation ruleConservation: reordering the i, j, k loops keeps the product (only the summation order changes); swapping a and b changes it. Reusing a c that is not zeroed adds the old values in.
D error rulerule broken: The product sums a[i][k]*b[k][j] over k. (silent logic error)
D error rulerule broken: Columns of a must equal rows of b. (run-time exception)
D error rulerule broken: Arrays have no arithmetic operators. (compile-time)
X applicability ruleApplicability: use nested-loop matrix code for small and moderate matrices. When only a vector times a matrix is needed (power method), use vector-matrix multiplication, which is far cheaper than matrix-matrix.
