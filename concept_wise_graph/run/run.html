Rules of the concept (17)

Book (SW-1e, p. 5 (pdf 15)): “Once you compile the program, you can run it.”
Book (SW-1e, p. 7 (pdf 17)): “When you type java followed by a class name in your terminal application, the system calls the main() method that you defined in that class”
Book (SW-1.1, ): “Execute (or run) it by typing "java MyProgram" in the terminal window.”
Rule typeRule
E folk-meaning ruleEveryday meaning: 'run the program' as if the file ran itself, or the program 'looks at all of itself at once'. Java rule: java Name starts the JVM, which calls Name's main() and executes its statements one at a time, in order.
M wrong rule / right ruleCompileRunsProgram: wrong: Compiling also executes the program. | right: The program runs only when java Name is typed; javac only translates it.
T uneven-application ruleApplies the run rule (LT: main's statements execute in order, one by one, each once) unevenly: e.g. executes the print statements in written order on one trace but skips one or reorders them on another.
N identity ruleRunning (executing) a program is launching it with java Name so that the Java Virtual Machine follows its instructions.
S declarative ruleTyping java followed by a class name makes the system call the main() method defined in that class and execute its statements; java Name args... also passes the command-line arguments to main. The development cycle is the same in any environment (terminal or IDE): edit the .java file, compile it with javac, run it with java.
LT operational sequencing ruleThe JVM starts at the first statement of main and ends when it finishes the last statement; statements run one by one, in order, and control returns to the system when main finishes.
OP evaluation / result ruleThe result of a run is what the program prints to the terminal (for java HelloWorld: Hello, World), or an exception message if a run-time error occurs.
OS state-transition ruleOne execution step runs one statement of main, which changes the program state (a variable or the output) and passes control to the next statement.
R composition rule (with a neighbour)with compile: java Name runs the Name.class that javac produced, so compiling must succeed first; the run reflects the source as of the last successful compile.
R composition rule (with a neighbour)with run_time_error: A run-time error appears only while java Name executes; the JVM stops the program and prints the exception.
R composition rule (with a neighbour)with logical_error: A logic error is seen only by running the program and comparing its output with the intended output.
P plan / role rulePurpose: make the computer carry out the program on particular inputs; running the same compiled program with different command-line arguments gives different results.
C conservation ruleRunning again with the same arguments reproduces the same output (for programs without randomness or input); changing the arguments changes the output without recompiling; editing the source changes nothing until recompiled.
D error rulerule broken: In the book's setup a StdAudio program should end main() with System.exit(0) (silent logic error)
D error rulerule broken: Run only after a successful compile; java takes a class name (launch error)
D error rulerule broken: A required command-line argument must be typed (run-time exception)
X applicability ruleRun the program to test it on chosen inputs and to see run-time and logic errors that compiling cannot find; adding print statements and rerunning is a simple way to check what is actually executing.
