Rules of the concept (23)

Book (SW-1e, p. 30 (pdf 40)): “its name followed by arguments of the specified type, enclosed in parentheses and separated by commas”
Book (SW-1.2, ): “You can call a method by typing its name followed by arguments,”
Rule typeRule
E folk-meaning ruleFolk meaning: maths function notation f(x) or sqrt(x), where the name alone suffices, a constant needs no brackets, and the reader infers which argument is which from meaning. Java rule: a library method is called as ClassName.name(arguments) (Math.sqrt(x)), the parentheses are always required, and arguments are matched to parameters by position and type.
M wrong rule / right ruleArrayHasLengthMethod: wrong: You call length() instead of using the length field. | right: An array's size is the field a.length, written without parentheses (String has the method s.length()).
M wrong rule / right ruleEqualsComparesReferences: wrong: .equals() compares references, not contents. | right: s.equals(t) checks whether the two Strings contain the same characters.
M wrong rule / right ruleParenthesesOnlyIfArgument: wrong: () are optional on a no-argument call like println. | right: A method call always needs parentheses, so an empty line is printed with System.out.println(); and a random number is Math.random().
M wrong rule / right ruleOutsideInMethodNesting: wrong: Nested calls run outside-in, not arguments-first. | right: In f(g(x)), g(x) is evaluated first and its result is passed to f.
M wrong rule / right ruleArgumentOrderInferred: wrong: Java works out from the variable names which argument goes where, so Math.pow(n, 2) and Math.pow(2, n) mean the same. | right: Arguments are matched to parameters by position, in the order the signature lists them; Math.pow(a, b) raises a to the bth power.
M wrong rule / right ruleParameterTypesInCall: wrong: A method call lists the parameter types, as in Math.pow(double a, double b). | right: A call passes only argument expressions, e.g. Math.pow(a, b); types appear only in the signature/declaration.
T uneven-application rulePoints to LT (arguments are evaluated left to right, then the method runs, then its return value replaces the call). Applied unevenly: in f(g(x)) the student calls the outer method before the inner one on some lines, or keeps the argument expression unevaluated in one trace step.
N identity ruleA method call is an expression that invokes a (library) method by its name, with arguments in parentheses, and evaluates to the value the method returns.
S declarative ruleA library method is used by typing its (class-qualified) name followed by arguments of the specified types, in parentheses and separated by commas; the call can be used in expressions like a variable or literal; void methods return no value.
LT operational sequencing ruleEvaluate the argument expressions from left to right (inner calls first), convert each to its parameter type if needed, transfer control to the method, and when it returns substitute the returned value for the call in the enclosing expression.
OP evaluation / result ruleThe call's value has the method's return type: Math.sqrt(5.0*5.0 - 4.0*4.0) is double 3.0, Math.round(3.14159) is long 3, Integer.parseInt("123") is int 123; a void method such as println has no value.
OS state-transition ruleCalling a Math method changes none of the caller's variables (arguments are passed as values); the program's state changes only if the returned value is stored or used, e.g. double d = Math.sqrt(x);.
R composition rule (with a neighbour)with expression: Arguments may be arbitrary expressions of the right type, and the call itself is an expression usable inside larger ones (Math.sin(x) * Math.cos(y)).
R composition rule (with a neighbour)with math_library: Math methods are called through the class name, Math.sqrt(x); without the prefix the compiler looks for the method in the current class and reports cannot find symbol.
R composition rule (with a neighbour)with api: The call must match a signature in the API (name, number, order and types of arguments), and the API's return type tells how the value can be used.
P plan / role ruleDelegates a computation to existing library code used as a black box, and composes computations by passing one call's result into another, e.g. Math.exp(Math.log(10.0)).
C conservation ruleChanging an argument changes only the returned value, never the argument variable; swapping arguments changes the meaning (Math.pow(2, n) vs Math.pow(n, 2)); replacing a call by its value keeps behaviour for mathematical functions but not for Math.random().
D error rulerule broken: Library methods are called with the class name, e.g. Math.sqrt(x). (compile-time)
D error rulerule broken: Each argument must have (or automatically widen to) the type the method's API lists. (compile-time)
D error rulerule broken: A value-returning call does not change its argument; its result must be stored or used. (silent logic error)
D error rulerule broken: A call needs parentheses and passes only argument expressions. (compile-time)
X applicability ruleCall a library method whenever a well-specified computation exists in an API (square roots, powers, conversions); write your own code only when no method fits; store a result in a variable rather than repeating an identical call.
