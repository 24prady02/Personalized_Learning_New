Rules of the concept (23)

Book (SW-1e, p. 25 (pdf 35)): “The most important operations defined for booleans are and (&&), or (||), and not (!)”
Book (SW-1.2, ): “The most important operators defined for the boolean are for and, or, and not.”
Rule typeRule
E folk-meaning ruleFolk meaning: English 'or' is often exclusive ('tea or coffee') and 'and' can join alternatives ('x is 1 and 2' meaning either value). Java rule: || is inclusive (true when either or both operands are true) and && is true only when both operands are true, so x == 1 && x == 2 is always false.
M wrong rule / right ruleBooleanPrecedence: wrong: a || b && c is evaluated left to right as (a || b) && c. | right: && binds tighter than ||, so a || b && c means a || (b && c); with a = true, b = false, c = false the value is true, not false.
M wrong rule / right ruleNoSingleLogicAnd: wrong: & is only a bitwise operator. | right: Java also has a & operator, which the book does not use; on boolean operands it is a logical and that always evaluates both operands; logical and is written &&.
M wrong rule / right ruleNestedIfsInsteadOfLogicalOperators: wrong: A condition on several values has to be written as nested if statements, one value per if. | right: Several conditions combine into one boolean expression with && and ||, e.g. if (x == 0 && y == 0).
M wrong rule / right ruleSingleAmpersandForAnd: wrong: & and | are the same as && and || for conditions, so either can be used. | right: && and || skip the right operand when the left decides the result; & and | always evaluate both, which fails when the right side depends on the left (e.g. x != 0 & y / x > 1 throws when x is 0).
T uneven-application rulePoints to LT (! first, then &&, then ||; left operand first; right operand of && / || only if needed). Applied unevenly: in one row of a trace the student evaluates the right operand of && although the left was false (or reads || as exclusive when both operands are true) and in another row applies the rule correctly.
N identity ruleLogical (boolean) operators: && (and), || (or) and ! (not), which take boolean operands and produce a boolean.
S declarative rulea && b is true if both operands are true and false otherwise; a || b is false if both are false and true otherwise; !a is the opposite of a; these definitions are given in full by truth tables.
LT operational sequencing rule! is applied before && and ||, and && before ||; the left operand is evaluated first, and for && and || the right operand is evaluated only when the left has not already decided the result.
OP evaluation / result ruleThe result is a boolean: with x = 10, x > 0 && x < 10 is false and x < 0 || x > 10 is false; true || anything is true.
OS state-transition ruleThe operators themselves change no variable; any side effect inside the right operand (i++, a method call) happens only if that operand is evaluated.
R composition rule (with a neighbour)with boolean_expression: Combining boolean sub-expressions with &&, || and ! yields another boolean expression, so arbitrarily complex conditions can be built with parentheses.
R composition rule (with a neighbour)with short_circuit: && and || are the short-circuit operators: in a guard such as (x != 0 && y / x > 1) the operand order matters, because the right test runs only when the left one allows it.
R composition rule (with a neighbour)with comparison_operators: Comparisons bind tighter than && and ||, so comparisons are evaluated first and their boolean results are then combined (month >= 1 && month <= 12).
R composition rule (with a neighbour)with exclusive_or: ^ on booleans is a further logical operator, true exactly when the operands differ (it equals (a || b) && !(a && b)), but unlike && and || it always evaluates both operands.
R composition rule (with a neighbour)with de_morgan: De Morgan's laws rewrite negated && / || expressions: !(A && B) is !A || !B and !(A || B) is !A && !B.
R composition rule (with a neighbour)with boolean: The operands must be boolean, and the result is boolean; int operands are a compile-time error.
P plan / role ruleUsed to combine several conditions into one test: a range check (lo <= x && x <= hi), alternatives (x == 0 || y == 0), a guard followed by the real test (i < n && a[i] != 0), or a rule built step by step as in LeapYear.
C conservation ruleSwapping && for || changes the meaning; negating a whole condition requires De Morgan (negate each term and flip the operator); swapping the operands of && or || keeps the truth value but can change which side effects or exceptions occur.
D error rulerule broken: Conditions are combined with && and ||; & and | evaluate both operands. (run-time exception)
D error rulerule broken: && has higher precedence than ||. (silent logic error)
D error rulerule broken: Logical operators take boolean operands only. (compile-time)
X applicability ruleUse && and || to combine conditions into a single test, ordering operands so that cheap or protective tests come first; use nested ifs only when the cases need different actions; do not use & and | for conditions.
