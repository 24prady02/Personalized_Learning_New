Rules of the concept (19)

Book (SW-1e, p. 25 (pdf 35)): “The boolean type has just two values: true and false.”
Book (OT-Datatypes, ): “The boolean data type has only two possible values: true and false.”
Book (SW-1.2, ): “The boolean type has just two values: true or false.”
Rule typeRule
E folk-meaning ruleFolk meaning: true and false are yes/no answers that, as in C, spreadsheets or maths logic, can be written as 1 and 0 and added or multiplied. Java rule: boolean is a separate primitive type with only the two values true and false; they are not numbers, cannot take part in arithmetic and cannot be cast to or from int.
M wrong rule / right ruleArithmeticInsteadOfBoolean: wrong: A true/false question is answered with arithmetic (e.g. 1 for true). | right: A logic question is written as a boolean expression whose value is true or false, e.g. boolean isLeapYear = (year % 4 == 0);.
M wrong rule / right ruleBooleanIsNumber: wrong: true and false are the numbers 1 and 0, so a boolean can be used in arithmetic. | right: The boolean type has only the values true and false; they are not numbers in Java, so true + 1 and (int) true do not compile.
T uneven-application rulePoints to LT (boolean operators are evaluated from their truth tables, left operand first). Applied unevenly: the student uses the truth table for && in one row of a trace but an everyday reading (e.g. exclusive 'or', or 1/0 arithmetic) in another.
N identity ruleboolean is a primitive data type whose only values are the literals true and false.
S declarative ruleThe boolean type has exactly two values, true and false; its operations are && (and), || (or) and ! (not); comparisons produce booleans; only boolean expressions can control if, while and for; no cast converts between boolean and a numeric type.
LT operational sequencing ruleA boolean variable's value is fetched when the expression that contains it is evaluated; !, && and || then combine those values by their truth tables, left operand first, skipping the right operand of && or || when the left already decides the result.
OP evaluation / result ruleThe value is true or false, and println prints the words true or false; e.g. LeapYear prints true for 2004 and false for 1900.
OS state-transition ruleAn assignment replaces the variable's value with true or false; a = !a flips it, so three flips starting from true leave false.
R composition rule (with a neighbour)with int: int and boolean never convert into each other; an int becomes a boolean only through a comparison (year % 4 == 0), and an int condition such as if (n) does not compile.
R composition rule (with a neighbour)with double: A double reaches the boolean world only through a comparison such as (x < 3.1), which yields a boolean; there is no cast between double and boolean.
R composition rule (with a neighbour)with char: char is a numeric (integral) type whose values can be compared ('a' < 'b' is a boolean), whereas boolean is not numeric; neither converts to the other.
R composition rule (with a neighbour)with logical_operators: &&, || and ! accept only boolean operands and return a boolean; applying them to ints (if (x && y) with int x, y) is a compile-time error.
R composition rule (with a neighbour)with comparison_operators: Comparisons are the main producers of boolean values: they take two numbers and return true or false, which can then be stored in a boolean variable.
R composition rule (with a neighbour)with primitive_type: boolean is one of the eight primitive types and the only non-numeric one.
P plan / role ruleA boolean variable plays the flag role: it records whether a condition holds (isLeapYear) or, as a one-way flag (Sajaniemi), whether something has happened yet, e.g. found = true inside a search loop and never reset.
C conservation ruleApplying ! twice restores the value (negation is its own inverse), so an even number of a = !a statements leaves a unchanged and an odd number flips it; changing a one-way flag's initial value from false to true breaks the search it records.
D error rulerule broken: Conditions and boolean variables require boolean values; numbers are not booleans. (compile-time)
X applicability ruleUse boolean to hold a yes/no fact or a flag that later code tests; do not use it for counts or for more than two states (use int), and do not encode it as 0/1 ints.
