Rules of the concept (26)

Book (SW-1e, p. 17 (pdf 27)): “An expression that is enclosed in parentheses is another expression with the same value.”
Book (OT-Expressions, ): “An expression is a construct made up of variables, operators, and method invocations, which are constructed according to the syntax of the language, that evaluates to a single value.”
Rule typeRule
E folk-meaning ruleIn maths an expression such as 7/2 or x + y names an exact number, and 'expression' means a formula with operators. In Java, any code that evaluates to a typed value is an expression, including a lone literal or variable, and with ints 7/2 evaluates to 3.
M wrong rule / right ruleAssignmentNotExpression: wrong: an assignment cannot be used inside a larger expression | right: An assignment is an expression whose value is the value assigned, so (x = v) both stores v in x and gives v.
M wrong rule / right ruleNoAtomicExpression: wrong: a single literal or variable "isn't an expression" | right: A single variable or literal is an expression whose value is just that value.
M wrong rule / right ruleParenthesesOnlyIfArgument: wrong: () are optional on a no-argument call like println | right: A method call always needs parentheses, so an empty line is printed with System.out.println();.
M wrong rule / right ruleTargetTyping: wrong: The type of a numerical expression depends on the type expected by the surrounding context, so double d = a / b; keeps the fraction. | right: The type of a numerical expression is determined by the expression, so double d = a / b; with int a and b still divides as ints.
M wrong rule / right ruleVariablesHoldExpressions: wrong: = stores the expression itself, not its computed value | right: y = x + k; stores the value that x + k has at that moment, so later changes to x do not change y.
M wrong rule / right ruleOutsideInMethodNesting: wrong: nested calls run outside-in, not arguments-first | right: In f(g(x)), g(x) is evaluated first and its result is passed to f.
M wrong rule / right ruleAssignmentIsEquation: wrong: An assignment states a lasting equality between its two sides, so y = x - y can be solved like the equation x = 2y and x = x + 5 relates two equal quantities. | right: An assignment is a one-time action: evaluate the right side with current values, then store the result in the left variable.
T uneven-application rulePoints to LT (replace each variable with its current value, then apply operators in precedence order). Applied unevenly, a student substitutes current values for some variables and old or future values for others, or respects precedence in one subexpression only.
N identity ruleExpression: a literal, a variable, or a sequence of operations (operators, method calls) on them that produces one value.
S declarative ruleEach operand of an operator can itself be any expression, and a parenthesized expression has the same value as the expression inside. Every expression has a type, determined by its operators and operands.
LT operational sequencing ruleOperands are evaluated left to right, each fully before its operator is applied. Precedence and parentheses decide the grouping, and a method's arguments are all evaluated before the method is called.
OP evaluation / result ruleAn expression produces one value of a type fixed by its operands: hour * 60 + minute with hour = 11 and minute = 59 is the int 719.
OS state-transition ruleEvaluating an expression changes no variable unless it contains an assignment, ++/-- or a method with side effects. The value goes to the enclosing statement, and an expression statement discards it.
R composition rule (with a neighbour)with variable: A variable name inside an expression contributes the variable's value at the moment of evaluation.
R composition rule (with a neighbour)with arithmetic_operators: Operators combine operand values into a new value, and the operand types choose the operation (int / truncates, double / does not).
R composition rule (with a neighbour)with operator_precedence: With several operators, precedence and left associativity decide the grouping, and parentheses override both.
R composition rule (with a neighbour)with comparison_operators: A comparison takes numeric expressions and yields a boolean expression, and it has lower precedence than arithmetic, so a + b < c compares the sum.
R composition rule (with a neighbour)with method_call: A method call is an expression usable wherever a value of its return type is, and its arguments are expressions evaluated before the call.
P plan / role ruleExpressions compute new values from existing ones. They form the right side of every assignment, every condition, every method argument and every printed value.
C conservation ruleAdding parentheses that match the default grouping keeps the value, and rewriting with an equivalent formula (4 * (x - 3) as 4*x - 12) keeps it for ints. Changing one operand's type (3 to 3.0) can change both the result's type and its value.
D error rulerule broken: The left-hand side of = must be a single variable; only the right-hand side may be an arbitrary expression. (compile-time)
D error rulerule broken: Only assignments, increments, method calls and object creation can stand alone as statements. (compile-time)
D error rulerule broken: Operators accept only operands of suitable types. (compile-time)
D error rulerule broken: An int division or remainder by zero cannot be evaluated. (run-time exception)
X applicability ruleUse an expression wherever a value is needed. Split a long or unclear expression into named intermediate variables, and add parentheses wherever the grouping is not obvious.
