Rules of the concept (37)

Book (SW-1e, p. 55 (pdf 65)): “This alternate notation is not fundamentally different from the basic while loop, but it is widely used because it often allows us to write more compact and more readable programs than if we used only while statements.”
Book (OT-For, ): “The initialization expression initializes the loop; it's executed once, as the loop begins.”
Book (OT-For, ): “When the termination expression evaluates to false, the loop terminates.”
Book (OT-For, ): “The increment expression is invoked after each iteration through the loop; it is perfectly acceptable for this expression to increment or decrement a value.”
Book (SW-1.3, ): “Java's for loop is a direct way to express such loops.”
Rule typeRule
E folk-meaning ruleFolk meaning: English 'for each ...' or 'for 10 times' names a whole collection or a count to be handled at once, and a maths reading treats the header as simultaneous conditions. A Java for is a while loop in compact form: one init, then test-body-update repeated, one pass at a time.
M wrong rule / right ruleForIsConditional: wrong: The body of a for statement executes at most once. | right: The body of a for statement runs once for every pass on which the condition is true, which can be many times.
M wrong rule / right ruleDoubleLoopIndexCount: wrong: for (double x = 0.0; x <= 1.0; x += 0.1) runs exactly 11 times. | right: Using a double as a for-loop index is legal but bad practice: the number of iterations depends on an equality test between double values, which may not give the result you expect.
M wrong rule / right ruleForWhileNotInterchangeable: wrong: Some loops can only be written with for, others only with while. | right: Any for loop can be rewritten as a while loop and vice versa; for just packages init, test and update.
M wrong rule / right ruleLoopImpliedByOneTest: wrong: Testing one case is enough; Java will repeat the test for the other values by itself. | right: A statement runs once each time control reaches it; repeating a test for many values needs a loop.
M wrong rule / right ruleIdiomOverridesCode: wrong: An array loop processes the whole array from index 0 to length-1 and increments its index at the end of the body, whatever the code says. | right: The loop visits exactly the indices that its initialisation, guard and update produce, in the order in which its statements are written.
M wrong rule / right ruleLoopHeaderIsEquations: wrong: The initialization, condition and update of a for header are equations that all hold at the same time. | right: The three header parts are statements run at different moments: init once, then condition test, body, update, repeated.
M wrong rule / right ruleLoopCountIsStatementCount: wrong: The repeat count of a counted loop says how many of the body statements are executed. | right: The repeat count is how many times the whole body runs; every pass runs all body statements.
M wrong rule / right ruleProgramEndsAfterLoop: wrong: When a loop finishes the program ends, so code after the loop never runs. | right: When the loop condition becomes false, control continues with the first statement after the loop.
M wrong rule / right ruleFalseLoopRepeatsNextCode: wrong: A loop is an iterative if-else: while the condition is true the body repeats, and when it is false the code after the loop repeats. | right: Only the body is repeated; once the condition is false the code after the loop runs once.
M wrong rule / right ruleForLoopPartSkipped: wrong: A pass of a loop may leave out one of its parts (the condition test, the body, the update, or the initialization). | right: Each pass of a for loop runs test, then body, then update, every time; the initialization runs once, at the start.
M wrong rule / right ruleForInitRepeats: wrong: The initialization of a for loop runs again after a pass of the body. | right: The initialization runs exactly once, before the first condition test.
M wrong rule / right ruleForUpdateBeforeBody: wrong: The update part of a for header (e.g. i = i - 4) runs before the body on each pass, so the first pass already sees the updated value. | right: The update runs after the body, before the next condition test; the first pass uses the initial value.
M wrong rule / right ruleLoopStepAlwaysOne: wrong: A loop variable always goes up or down by 1, whatever the update says (so i = i - 4 is read as i--). | right: The loop variable changes exactly as the update expression says (i += 2, i = i - 4, i *= 2, ...).
T uneven-application ruleApplies the for sequencing rule (LT) unevenly: updates before the body on the first pass only, re-runs the init after a pass, or skips the test on some passes.
N identity ruleThe for statement is a loop that packages an initialization, a loop-continuation condition and an increment in its header around a body.
S declarative ruleSyntax: for (<initialize>; <boolean expression>; <increment>) { <statements> }, with the three parts separated by semicolons; it is, with only a few exceptions, equivalent to <initialize>; while (<boolean expression>) { <statements> <increment>; }.
LT operational sequencing ruleRun the initializer once; then repeatedly: test the condition (stop if false), execute the body, run the update.
OP evaluation / result ruleA for statement has no value; the passes it makes are fixed by its header: for (int i = 1; i <= N; i++) sum += i; leaves sum = N(N+1)/2, and for (int i = 2; i <= 8; i += 2) prints 2, 4, 6, 8,.
OS state-transition ruleOne pass: the test reads the loop variable; the body applies its changes once; the update then changes the loop variable by its rule; the initializer changes state only once, before the first test.
R composition rule (with a neighbour)with loop_control: The for header is exactly the three loop-control slots; the body runs after the test and before the update on each pass.
R composition rule (with a neighbour)with nested_loops: A for may be the body of another for: the inner for runs its complete set of passes for every single pass of the outer one.
R composition rule (with a neighbour)with array_traversal: for (int i = 0; i < N; i++) gives i each valid index 0..N-1 exactly once in increasing order, the standard way to process every array element.
R composition rule (with a neighbour)with simulation_loop: A simulation runs a fixed number of trials with an outer for loop (for (int t = 0; t < T; t++)), each trial simulated inside the body.
R composition rule (with a neighbour)with continue_statement: In a for loop, continue skips the rest of the body and transfers control directly to the increment, then the next test; this is one of the few places where the for/while equivalence fails.
R composition rule (with a neighbour)with loop_scope: A variable declared in the for header is in scope only in the header and the body, so it cannot be used after the loop.
R composition rule (with a neighbour)with fencepost_loop: A fencepost loop is a for loop that handles one item (the first or last) outside the loop so that separators come out n-1 times for n items.
R composition rule (with a neighbour)with flag_search_loop: A flag search loop is a for loop that sets a boolean flag when some pass finds the target and leaves it set afterwards; the flag must be declared before the loop.
P plan / role rulePlan: counted loop / counter-controlled repetition - do the body a known number of times, with the loop variable as a stepper (index, term number, trial number).
C conservation ruleRewriting a for as the equivalent while (init before, update at the end of the body) keeps behaviour, except that continue then skips the update and the loop variable stays in scope after the loop. Changing the bound or the step changes the pass count predictably (< to <= adds one pass).
D error rulerule broken: The three parts of a for header are separated by semicolons; commas only separate several statements inside the init or the update. (compile-time)
D error rulerule broken: A ; right after if (...) is an empty statement that forms the whole then branch; the following statement or block is no longer part of the if. (silent logic error)
D error rulerule broken: A ; right after while (...) or for (...) is an empty statement that is the whole loop body; the block written next is not repeated. (silent logic error)
D error rulerule broken: The number of passes is fixed by the init, the test and the update together. (silent logic error)
D error rulerule broken: Without braces, the body of an if, while or for is exactly one statement; indentation does not add statements to it. (silent logic error)
D error rulerule broken: A variable declared in the for initializer exists only inside the for statement. (compile-time)
X applicability ruleUse for when there is an initialization, an increment and a continuation test and the loop variable is not needed after the loop; use while when the loop variable is needed later or the number of passes depends on what happens in the body.
