Rules of the concept (17)

Book (SW-1e, p. 70 (pdf 80)): “When a continue is executed within a loop body, the flow of control transfers directly to the increment statement for the next iteration of the loop.”
Book (OT-Branch, ): “The continue statement skips the current iteration of a for, while , or do-while loop.”
Rule typeRule
E folk-meaning ruleFolk meaning: in English 'continue' means carry on with what you are doing, so a novice reads `continue;` as 'keep executing the rest of the body' (no effect) or as 'continue after the loop'. In Java it abandons the rest of the current pass and goes straight to the next iteration.
M wrong rule / right ruleContinueExitsLoop: wrong: continue ends the loop. | right: continue skips only the rest of the current pass: in a for loop, control transfers directly to the increment and then the next test, and the loop goes on while the test is true.
M wrong rule / right ruleContinueIgnored: wrong: continue means carry on with the rest of the loop body, so it has no effect. | right: continue skips every statement after it in the current pass.
T uneven-application ruleApplies the LT rule unevenly: on some passes the trace runs the statements after continue, or skips the for-loop increment, so the traced counts or outputs include items that should be skipped.
N identity ruleJump statement: `continue;` ends the current iteration of the innermost enclosing loop and starts the next one.
S declarative rule`continue;` may appear only inside a loop. When executed, the rest of the body is skipped. In a for loop control goes to the increment; in a while or do-while it goes to the condition test. (Spec: JLS §14.16.)
LT operational sequencing ruleOrder after continue in `for (init; test; inc) body`: skip the remaining body statements, execute inc, evaluate test, and run the next pass if it is true. In a while loop there is no separate inc, so control goes directly to the test.
OP evaluation / result rulecontinue produces no value. Its effect is on what the loop outputs: `for (int i = 0; i < 5; i++) { if (i % 2 == 0) continue; System.out.print(i); }` prints 13.
OS state-transition ruleOne execution changes no variable; it only moves control to the increment (for) or the test (while). The variables keep their values, and the statements skipped in this pass make no changes.
R composition rule (with a neighbour)with for_loop: In a for loop the increment still runs after continue, so the loop always advances. This is why the for/while equivalence has an exception: in the rewritten while, a continue jumps past the `<increment>;` at the end of the body.
R composition rule (with a neighbour)with break_statement: Both abandon the rest of the body; continue proceeds to the next pass (increment and test), break leaves the loop with no increment or test.
P plan / role rulePlan: skip/filter plan. It guards the rest of the body against items that should not be processed (e.g. skip non-matching or invalid entries), avoiding a deeply nested if.
C conservation ruleReplacing `if (c) continue; rest;` with `if (!c) { rest; }` keeps the behaviour. Moving the continue below the update in a while loop, or the update below the continue, changes whether the loop advances.
D error rulerule broken: continue must be inside a loop. (compile-time)
D error rulerule broken: In a while loop continue goes straight to the test, skipping an update placed later in the body. (silent logic error)
D error rulerule broken: Statements after continue in the same block can never run. (compile-time)
X applicability ruleUse continue to skip items early in a long loop body when the alternative is a deeply nested if. Avoid it in while loops whose update is at the end of the body, and avoid it when a simple if around the work is clearer. S&W rarely use it.
