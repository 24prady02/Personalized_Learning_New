Rules of the concept (15)

Book (SW-1e, p. 107 (pdf 117)): “For instance, we can declare and initialize a three-dimensional array with the code double[][][] a = new double[N][N][N]”
Book (SW-1.4, p. 107 (pdf 117)): “double[][][] a = new double[n][n][n]; and then refer to an entry with code like a[i][j][k].”
Rule typeRule
E folk-meaning ruleFolk meaning: '3-D' suggests three elements, or one solid block. Java rule: each bracket pair adds one level of nesting, so double[][][] is an array of 2-D arrays, and its length is set at creation.
M wrong rule / right ruleArrayRankIsLength: wrong: The number of dimensions of an array is its length. | right: Rank (number of bracket pairs) and length are different: new double[5][5][5] has rank 3 and a.length 5.
M wrong rule / right ruleArrayBracketCountIsLength: wrong: The number of brackets in an array type or initializer is the array's length. | right: Brackets give the number of dimensions; the length of each level is set at creation.
T uneven-application rulePoints to LT: a[i][j][k] is evaluated left to right, each index selecting a sub-array of one lower dimension. Inconsistent application: the trace mixes up which index selects which level.
N identity ruleIdentity: a multidimensional array, an array with three or more indices built as nested arrays of arrays.
S declarative ruleDeclarative: double[][][] a = new double[N][N][N]; refer to an entry as a[i][j][k].
LT operational sequencing ruleSequencing: a[i] (a 2-D array) is evaluated, then [j] (a 1-D row), then [k] (the element); each step is bounds-checked against the length of that level.
OP evaluation / result ruleResult: new double[N][N][N] holds N*N*N doubles, all 0.0; a.length is N, and a[i] is a double[][].
OS state-transition ruleState transition: a[i][j][k] = v changes one element; nothing else changes.
R composition rule (with a neighbour)with two_dimensional_array: A 3-D array generalizes 2-D: a[i] is itself a 2-D array, and the same declaration, creation and indexing rules apply one level deeper.
P plan / role rulePlan/role: model data with three or more coordinates, e.g. a 3-D lattice for self-avoiding walks or physical space.
C conservation ruleConservation: adding a dimension multiplies memory and creation time by the new extent (N^3 values for N per side), because creation time is proportional to the number of elements.
D error rulerule broken: The total size must be a non-negative int and fit in memory. (run-time exception)
D error rulerule broken: Each index must be within its own level. (run-time exception)
X applicability ruleApplicability: use one when data naturally has three or more integer coordinates and N is small enough for N^3 storage. Use 2-D or 1-D arrays when fewer indices suffice.
