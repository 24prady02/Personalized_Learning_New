Rule typeRule
E folk-meaning rule"Power" suggests strength or Math.pow on a number; here it means raising the transition matrix to the t-th power by multiplying a probability vector by p[][] t times.
M wrong rule / right ruleMatrixProductCommutes: wrong: A * B and B * A are the same matrix. | right: Matrix multiplication is not commutative: c[i][j] is row i of the left factor dotted with column j of the right; rank * p (row vector times matrix) is the page-rank update, p * rank is a different vector.
M wrong rule / right ruleOneIterationSuffices: wrong: One vector-matrix multiplication gives the exact page ranks. | right: One multiplication gives the probabilities after one move ([.02 .92 .02 .02 .02] from page 0); about 20 multiplications give two decimal places and 20 more give three.
M wrong rule / right ruleStartPageMatters: wrong: The page ranks depend on which page the surfer starts from. | right: The iteration converges to the same vector no matter where it starts; Markov starts from [1.0 0 0 0 0] only for convenience.
T uneven-application ruleApplies LT (compute all of newRank from the old rank, then copy) unevenly: e.g. on some passes writing rank[j] directly so later j use partly updated values, or forgetting to recreate newRank so sums accumulate.
N identity ruleAn iterative algorithm: repeated vector-matrix multiplication of a probability vector by the transition matrix.
S declarative ruleThe vector of probabilities after t steps is the vector after t-1 steps times the transition matrix; by the basic limit theorem this converges to the same vector from any start.
LT operational sequencing rulerank = [1, 0, ..., 0]; for each t: create newRank (zeros); for each j, for each k, newRank[j] += rank[k]*p[k][j]; then copy newRank into rank. Finally print rank.
OP evaluation / result rulePrints the page-rank vector after T multiplications: Markov 20 gives 0.27245 0.26515 0.14669 0.24764 0.06806 and Markov 40 gives 0.27303 0.26573 0.14618 0.24723 0.06783.
OS state-transition ruleOne iteration replaces every rank[j] with the dot product of the old rank and column j of p; the vector still sums to 1.
R composition rule (with a neighbour)with matrix_operations: Each iteration is a vector-matrix product: newRank[j] is the dot product of rank[] and column j of p[][], computed with nested for loops.
R composition rule (with a neighbour)with markov_chain: Each multiplication is one move of the chain; convergence is the chain's mixing.
R composition rule (with a neighbour)with two_models: Gives the move probabilities exactly (up to floating-point precision), whereas the simulation only estimates them.
R composition rule (with a neighbour)with convergence_rate: The number of iterations T controls accuracy: about 20 for two decimals and 20 more for three on tiny.txt.
R composition rule (with a neighbour)with simulation_loop: Computes the same ranks far more efficiently than simulating moves.
P plan / role ruleIterative-refinement plan: repeat the same update until the vector stops changing; newRank[j] is a gatherer (dot product), rank is the state vector replaced each pass.
C conservation ruleChanging the start vector keeps the limit; more iterations keep the result and add digits; updating rank in place, or using p[j][k] instead of p[k][j], breaks the computation.
D error rulerule broken: The new vector must be computed from the old vector only. (silent logic error)
D error rulerule broken: newRank must start at zero each iteration. (silent logic error)
D error rulerule broken: The update is rank (row) times p: use column j of p, p[k][j]. (silent logic error)
D error rulerule broken: Many iterations are needed for convergence. (silent logic error)
X applicability ruleUse when the transition matrix fits in memory and accurate ranks are needed: far more efficient than simulation; still too slow for the whole web, and repeated squaring is an alternative.
