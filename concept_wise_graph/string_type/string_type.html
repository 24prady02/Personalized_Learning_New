Book (SW-1e, p. 19 (pdf 29)): “A String is a sequence of characters.”

Rule typeRule
E folk-meaning ruleIn everyday writing, quotes only mark words, "10" is the number ten, and two texts are 'equal' when they read the same. In Java a String is an object reached through a reference: "10" is text, + concatenates, and == compares references rather than contents.
M wrong rule / right ruleEqualsComparesReferences: wrong: .equals() compares references, not contents | right: s.equals(t) checks whether the two Strings contain the same characters.
M wrong rule / right ruleStringIsPrimitive: wrong: String is a primitive type like int. | right: String is not a primitive type; it is a class whose values are objects, although Java gives it some built-in support (literals, +).
M wrong rule / right ruleStringLiteralNoObject: wrong: a string literal isn't a String object until the constructor is called | right: A string literal is already a String object, so "text".length() works directly.
M wrong rule / right ruleEqualityOperatorComparesObjectsValues: wrong: == compares contents (the String == bug) | right: s == t is true only when s and t refer to the same object; s.equals(t) compares the text.
M wrong rule / right ruleStringRelationalComparison: wrong: s < t compares two Strings alphabetically. | right: < and > are defined only for primitive types; comparing Strings with them does not compile.
M wrong rule / right ruleArithmeticOnNumericStrings: wrong: "10" - 1 or "6" * "2" works because the strings look like numbers. | right: Arithmetic operators other than + are not defined for Strings; a String of digits must first be converted to a number, e.g. with Integer.parseInt.
T uneven-application rulePoints to LT (String expressions produce references to String objects, and operations build new strings). Applied unevenly, a student compares with equals in one test and == in another, or treats "12" as a number in one + and as text in the next.
N identity ruleString: Java's built-in non-primitive (reference) type for a sequence of characters.
S declarative ruleA String literal is characters in double quotes and denotes a String object. + concatenates. Contents are compared with equals, not ==. < and > are not defined for Strings, and Strings are immutable.
LT operational sequencing ruleA String expression is evaluated left to right. At each + with a String operand, the other operand is converted to a String and a new String object is made. Methods such as toUpperCase return a new String and leave the original unchanged.
OP evaluation / result rule"Hi, " + "Bob" is "Hi, Bob" and "1234" + "99" is "123499". s.equals(t) is true exactly when the characters match, while "abc" == "ab" + x can be false for x = "c".
OS state-transition ruleNo operation changes an existing String. s = s + "x" makes s refer to a new String, and other variables still referring to the old one are unaffected.
R composition rule (with a neighbour)with string_concatenation: + produces a new String whenever at least one operand is a String; the other operand is converted to text first.
P plan / role ruleStrings handle all text: messages, labels, formatted output and command-line arguments (args[] are Strings and must be parsed before arithmetic).
C conservation ruleReplacing equals with == may still pass for two identical literals but fails for computed or input strings. Changing "5" to 5 turns concatenation into addition.
D error rulerule broken: String contents are compared with equals; == compares references. (silent logic error)
D error rulerule broken: < and > (and - * /) are defined only for primitive types, not for Strings. (compile-time)
D error rulerule broken: A String variable can hold only a String (or null). (compile-time)
D error rulerule broken: A method cannot be called through a null reference. (run-time exception)
X applicability ruleUse String for any text: names, messages, tokens and output lines. Convert to int or double with Integer.parseInt or Double.parseDouble before arithmetic. Use char for a single character whose code matters.
