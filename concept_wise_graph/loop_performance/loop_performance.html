Rules of the concept (14)

Book (SW-1e, p. 69 (pdf 79)): “Loops give us the ability to solve difficult problems, but they also give us the ability to construct simple programs that run slowly”
Rule typeRule
E folk-meaning ruleFolk meaning: 'computers are so fast it doesn't matter how many steps', so any correct loop is good enough. In fact running time grows with the number of iterations: an n-step loop over 10^18 values never finishes, while a √n-step loop finishes in seconds.
T uneven-application ruleApplies the iteration-counting rule unevenly: one loop's passes are counted while an inner loop's passes are left out, or the loop is assumed to run N times when its condition (i <= n/i) stops it near √n, so the cost estimate is off by orders of magnitude.
N identity rulePerformance concept: the running time of a loop program is roughly (number of iterations) × (cost per iteration), and the loop condition determines the number of iterations.
S declarative ruleRunning time is proportional to the total number of times the innermost statements execute. Nested loops multiply their counts, so Gambler takes T × (average bets), and changing a bound from n to √n changes the feasible input from about 10^9 to about 10^18.
LT operational sequencing ruleOrder of the estimate: count the passes of the outer loop; for each, count the passes of the inner loop; multiply (or sum); multiply by the cost of one pass of the innermost body.
OP evaluation / result ruleThe result is an iteration count or time estimate. `for (i = 2; i <= n/i; i++)` runs about √n times, against about n times for `i < n`. Gambler 500 2500 100 makes about 100 × 10^6 bets (nearly 100 million random numbers).
OS state-transition ruleEach extra pass adds a constant amount of work. Adding 1 to the bound of a single loop adds one pass, while adding 1 to the bound of an outer loop adds a full run of the inner loop.
R composition rule (with a neighbour)with loop_control: The loop's condition and update set the iteration count. A tighter test that keeps correctness (i <= n/i instead of i < n) or a faster update (doubling instead of incrementing) can make the program dramatically faster with identical output.
P plan / role rulePurpose: to predict whether a program will finish in reasonable time for its inputs, and to choose among correct loop formulations (bounds, nesting, reuse of previous results).
C conservation ruleChanging the factoring test from `i < n` to `i <= n/i` keeps the output identical (by the invariant) and cuts iterations from about n to about √n. Reusing the previous term in the e^x loop keeps the sum and removes the inner loop.
D error rulerule broken: Iteration count must be kept feasible for the input size. (silent logic error)
D error rulerule broken: Do not recompute in an inner loop what the previous pass already computed. (silent logic error)
D error rulerule broken: Nested-loop cost is the product of the counts. (silent logic error)
X applicability ruleThink about loop performance whenever the iteration count grows with large inputs (factoring, prime counting, simulations, nested loops). For small fixed counts (TenHellos), clarity matters more than speed. Experiment with timings to compare formulations.

  • [3] diagnose_an_error (D): rule broken: Do not recompute in an inner loop what the previous pass already computed. Kind: silent logic error. Trigger class: Recomputing each Taylor term from scratch in a nested loop: correct output but needlessly slow.
  • [4] diagnose_an_error (D): rule broken: Nested-loop cost is the product of the counts. Kind: silent logic error. Trigger class: Large T times long trials in a simulation (Gambler 100000 200000 100): run time explodes.
