Rules of the concept (22)

Book (SW-1e, p. 8 (pdf 18)): “Other errors, known as run-time errors, do not show up until you execute the program.”
Book (SW-1.1, ): “These errors are caught by the system when we execute the program, because the program tries”
Rule typeRule
E folk-meaning ruleEveryday reading: if the program compiled, the computer has accepted it, so any problem would have been reported then. Java rule: run-time errors are detected only while the program executes, on particular data (e.g. no argument, a divisor of 0), and stop it with an exception.
M wrong rule / right ruleCompilesMeansWorks: wrong: Code that compiles is code that works. | right: Code that compiles can still fail at run time (an exception) or give wrong output.
M wrong rule / right ruleDivisionByZeroIsCompileError: wrong: System.out.println(5 / 0); is rejected by the compiler. | right: It compiles; integer division by zero throws ArithmeticException when the statement runs.
M wrong rule / right ruleParseAnyString: wrong: Integer.parseInt works on any text, e.g. "five" or "12.2". | right: Integer.parseInt throws a NumberFormatException at run time when the string is not an integer written in digits.
T uneven-application ruleApplies the exception rule (LT: execution stops at the faulty statement) unevenly: lets the program keep printing after the failing statement on one trace, or reports the error before any earlier output on another.
N identity ruleA run-time error (exception) is an error that does not show up until the program is executed and makes it impossible to run to completion.
S declarative ruleWhen a run-time error occurs, the program 'crashes' (terminates) and the JVM prints the exception name, a message, and the method, file and line where it happened.
LT operational sequencing ruleStatements before the faulty one run normally (their output appears); the faulty statement throws; no later statement runs.
OP evaluation / result ruleOutput: any earlier output, then Exception in thread "main" java.lang.<Name>: <detail> at Class.main(Class.java:<line>).
OS state-transition ruleThe throwing step changes no variable it was meant to set (the operation does not complete) and transfers control out of main, ending the program.
R composition rule (with a neighbour)with run: A run-time error appears only while java Name executes, after compiling has succeeded.
R composition rule (with a neighbour)with compile_time_error: javac cannot detect it because it depends on run-time values (the argument typed, the divisor's value).
R composition rule (with a neighbour)with logical_error: A run-time error stops the program with an exception message; a logic error lets it finish with wrong output and no message.
P plan / role rulePurpose (of exceptions): stop the program at the point where something impossible was asked, instead of continuing with an undefined value, and report what and where.
C conservation ruleThe same compiled program may run fine on one input and throw on another (UseArgument with and without an argument); adding a guard such as checking args.length removes the trigger without changing correct runs.
D error rulerule broken: args[k] exists only if at least k+1 arguments were typed (run-time exception)
D error rulerule broken: main is written public static void main(String[] args) (launch error)
D error rulerule broken: Array length must be >= 0 (run-time exception)
D error rulerule broken: StdIn.readInt() needs the next token to be an int (run-time exception)
D error rulerule broken: Integer division and remainder by zero are undefined (run-time exception)
D error rulerule broken: Integer.parseInt needs an integer written in digits (run-time exception)
X applicability ruleExpect a run-time error when correctness depends on data (array indices, divisors, parsed input, presence of arguments); validate such data before use. Errors that depend only on the text are compile-time; wrong-but-legal results are logic errors.
