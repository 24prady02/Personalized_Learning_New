Rules of the concept (17)

Book (SW-1e, p. 70 (pdf 80)): “We could use a sequence or a chain of if-else statements, but the Java switch statement provides a direct solution.”
Book (OT-Switch, ): “The break statements are necessary because without them, statements in switch blocks fall through:”
Book (OT-Switch, ): “The default section handles all values that are not explicitly handled by one of the case sections.”
Book (LI, ): “Once a case is matched, the statements starting from the matched case are executed until a break statement or the end of the switch statement is reached. This is referred to as fall-through behavior.”
Rule typeRule
E folk-meaning ruleFolk meaning: everyday 'switch' means flip to one setting, and 'case' reads like 'in case of X do Y', a self-contained rule. Novices therefore expect only the matching case to run. In a Java switch statement, the case labels are only entry points: execution starts at the matching label and falls through the following cases until a break.
M wrong rule / right ruleSwitchNoFallThrough: wrong: After the matching case runs, the switch ends even without break. | right: Without break, all the statements after the matching label run, including those under later case labels, until a break or the end of the switch.
T uneven-application ruleApplies the LT rule unevenly: on a trace the selector is matched correctly but execution stops at the next case label on some runs and falls through on others, or default is run even though a case matched.
N identity ruleSelection statement: `switch (expr) { case v1: ...; break; ... default: ... }` chooses among many alternatives by the value of one expression.
S declarative ruleThe selector is an int-like (char, byte, short, int), String or enum expression. Case labels are distinct constants of that type, and default is optional. Control jumps to the matching label (or to default, or past the switch), and the case statements usually end with break. Without a break, execution falls through into the statements of the next case; default runs when no case matches.
LT operational sequencing ruleOrder: evaluate the selector once; compare it with the case constants; jump to the matching label (else default, else skip the switch). Then execute the statements from there in order, through later labels, until a break or the closing brace.
OP evaluation / result ruleA switch statement has no value. Its result is the effect of the case(s) run: with `day = 3`, the S&W day switch prints Wed. Without breaks, day = 5 would print Fri, then Sat.
OS state-transition ruleOne execution evaluates the selector once (any side effect in it happens once) and runs the statements of one entry point and any cases it falls into. It changes only what those statements change.
R composition rule (with a neighbour)with nested_conditionals: A switch replaces an if-else chain only when every test is `expr == constant` on the same expression. Range tests such as the income-bracket chain (`income < 47450`) must stay an if-else chain.
R composition rule (with a neighbour)with break_statement: Each case is normally ended by break, which exits the switch body. Leaving it out makes that case fall into the next. Inside a loop, that break exits the switch, not the loop.
P plan / role rulePlan: multiway dispatch or lookup. It maps one discrete value (day number, menu choice, character) to one of several actions or results. Grouped labels (`case "apple": case "banana":`) map several values to one action.
C conservation ruleWhen every case ends with break, reordering the cases does not change behaviour (labels are distinct constants). Removing one break changes behaviour for that value only. Adding a default changes only values with no matching label.
D error rulerule broken: Without break, execution falls through into the following cases. (silent logic error)
D error rulerule broken: Values that match no case do nothing unless a default is present. (silent logic error)
D error rulerule broken: Case labels must be distinct compile-time constants of the selector type, and the selector may not be double, float, long or boolean. (compile-time)
D error rulerule broken: A String selector is dereferenced. (run-time exception)
X applicability ruleUse switch for more than two mutually exclusive alternatives decided by equality of one int, char, String or enum value. Use an if-else chain for ranges, doubles or unrelated conditions. Use an array lookup (S&W 1.4) when each case only selects a value.
