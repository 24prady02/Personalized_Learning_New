Rules of the concept (26)

Book (SW-1e, p. 28 (pdf 38)): “Comparison operations, together with boolean logic, provide the basis for decision-making in Java programs.”
Book (SW-1.2, ): “The comparison operators are mixed-type operations that take operands of one type and produce a result of type boolean.”
Rule typeRule
E folk-meaning ruleFolk meaning: maths writes a range as 90 <= grade <= 100 and English says 'if x is 1 or 2'. Java rule: each comparison is a separate boolean expression and they must be joined explicitly: 90 <= grade && grade <= 100, x == 1 || x == 2; 90 <= grade <= 100 does not compile because 90 <= grade is already a boolean.
M wrong rule / right ruleArithmeticInsteadOfBoolean: wrong: A true/false question is answered with arithmetic (e.g. 1 for true). | right: A logic question is written as a boolean expression whose value is true or false, e.g. (year % 4 == 0).
M wrong rule / right ruleChainedComparison: wrong: 90 <= grade <= 100 tests whether grade is between 90 and 100. | right: a < b < c does not compile (a < b is a boolean, which cannot be compared with <); a range test is written 90 <= grade && grade <= 100.
M wrong rule / right ruleComparisonWithBooleanLiteral: wrong: You must write == true / == false to test a boolean. | right: if (b) already tests b, and if (!b) tests that it is false, so == true adds nothing.
M wrong rule / right ruleLoopForOneTimeTest: wrong: Uses a loop where a condition needs to be tested only once. | right: A test made once is an if; a while re-tests its condition and repeats its body for as long as the condition is true.
M wrong rule / right ruleMapToBooleanWithConditionalOperator: wrong: You need ? : to turn a boolean expression into a boolean (ok = x > y ? true : false). | right: ok = (x > y); already gives the boolean, so the ? : is unnecessary.
M wrong rule / right ruleMapToBooleanWithIf: wrong: You need an if to turn a boolean expression into a boolean. | right: ok = (x > y); stores the result of the comparison directly.
M wrong rule / right ruleNestedIfsInsteadOfLogicalOperators: wrong: A condition on several values has to be written as nested if statements, one value per if. | right: Several conditions combine into one boolean expression with && and ||, e.g. if (x == 0 && y == 0).
T uneven-application rulePoints to LT (arithmetic first, then comparisons, then !, &&, ||, left to right, with short-circuit). Applied unevenly: the student evaluates && before a comparison in one sub-expression, or evaluates the right operand of && on a pass where the left was already false.
N identity ruleA boolean expression is any expression whose type is boolean: a boolean literal or variable, a comparison, or such parts combined with &&, || and !.
S declarative ruleA boolean expression has value true or false; it is built from comparisons (lower precedence than arithmetic, higher than boolean operators) and boolean operators; the condition of if, while and for must be one.
LT operational sequencing ruleOperands are evaluated left to right; arithmetic sub-expressions first, then comparisons, then !, then &&, then ||; && and || evaluate their right operand only when the left has not decided the result.
OP evaluation / result ruleThe value is true or false: with year = 1900, (year % 4 == 0) && (year % 100 != 0) || (year % 400 == 0) is false, so LeapYear prints false.
OS state-transition ruleEvaluating a boolean expression changes no variable (unless it contains an assignment, ++ or a method with side effects); state changes only when its value is stored, as in isLeapYear = isLeapYear && (year % 100 != 0);.
R composition rule (with a neighbour)with comparison_operators: Comparisons are the atoms of boolean expressions; because they bind tighter than && and ||, month >= 1 && month <= 12 groups as (month >= 1) && (month <= 12) without parentheses.
R composition rule (with a neighbour)with logical_operators: &&, || and ! combine boolean sub-expressions into a larger one; ! binds tighter than comparisons, so negating a comparison needs parentheses: !(x > 0).
R composition rule (with a neighbour)with if_statement: The if statement evaluates its boolean expression once and runs its block only when the value is true; the expression must have type boolean, so if (x = 5) with int x does not compile.
R composition rule (with a neighbour)with while_loop: The while loop re-evaluates its boolean expression before every pass and stops the first time it is false, so some variable in the expression must change in the body or the loop never ends.
R composition rule (with a neighbour)with random_move: In RandomSurfer the boolean expression r < sum is evaluated for each candidate page j in turn, as sum grows; the first j for which it is true is the chosen page.
R composition rule (with a neighbour)with syntax_template: In the template if (<boolean expression>) { <statements> } the placeholder may be filled by any boolean-typed expression: a literal, a boolean variable, a comparison or a combination with logical operators.
P plan / role ruleExpresses a decision condition or guard (which branch runs, whether a loop continues) or computes a flag; common plans: range test lo <= x && x <= hi, divisibility test n % k == 0, combined rule as in LeapYear.
C conservation ruleRewriting with De Morgan (!(a && b) as !a || !b) keeps the value for every input; swapping the operands of && keeps the truth value but can change whether the right operand is evaluated (and whether a guard still protects it); changing < to <= changes the result only at the boundary value.
D error rulerule broken: else takes no condition; a second condition needs else if (...). (compile-time)
D error rulerule broken: The condition must be a boolean expression; = assigns, == compares. (compile-time)
D error rulerule broken: Comparisons cannot be chained; each must be joined with && or ||. (compile-time)
X applicability ruleUse a boolean expression wherever code must decide or record a yes/no condition, and store it directly (ok = x > y) rather than via if or ? :; when different outcomes are needed for several cases use an if-else chain of such expressions.
