Rules of the concept (18)

Book (SW-1e, p. 56 (pdf 66)): “The scope of a variable is the part of the program where it is defined.”
Book (SW-1e, p. 56 (pdf 66)): “For this purpose, the code in the for loop header is considered to be in the same block as the for loop body.”
Book (OT-For, ): “The scope of this variable extends from its declaration to the end of the block governed by the for statement, so it can be used in the termination and increment expressions as well.”
Book (GJS, ): “Instead, local variables are declared close to the point they are first used (within reason), to minimize their scope.”
Book (SW-1.3, ): “The scope of a variable is the part of the program that can refer to that variable by name.”
Rule typeRule
E folk-meaning ruleFolk meaning: once a name is introduced ('let i be ...') it can be referred to for the rest of the text, and something introduced inside a repeated step keeps existing across repetitions. In Java a local variable exists only from its declaration to the end of its block, and a for header counts as part of the loop's block.
M wrong rule / right ruleForVariableScopeBeyondLoop: wrong: i declared in the for header can still be used after the loop has ended. | right: i declared in the for header exists only inside the loop, so using it after the loop does not compile.
M wrong rule / right ruleLocalVarOutsideScope: wrong: A variable declared inside a block can be used anywhere in the program, like a global. | right: A local variable exists only from its declaration to the end of its block.
M wrong rule / right ruleLoopBodyScopeImpliesLoopLifetime: wrong: a variable declared in the loop body lives across all iterations | right: A variable declared inside the body is in scope only to the end of the body, so each pass declares and initializes it afresh and it does not keep the previous pass's value.
M wrong rule / right ruleLoopVariableLifetimeScope: wrong: The for variable i is a new variable on every pass rather than one variable changed by the update. | right: The for variable i is created once by the init, the update changes that same variable on every pass, and i exists only until the end of the for statement.
T uneven-application ruleApplies the scope rule (LT) unevenly: lets a body variable keep its value from the last pass on some passes but not others, or uses the for variable after the loop in one place but not another.
N identity ruleScope is the part of the program where a variable is defined (can be used); for loops, the header is in the same block as the body.
S declarative ruleA local variable's scope is the rest of the block after its declaration; a variable declared in a for initializer is in scope in the header and the body only; redeclaring a local variable inside its scope is a compile-time error.
LT operational sequencing ruleEach time control enters a block, its declarations run in order, creating and (if initialized) setting those variables; when the block ends they cease to exist. For a loop body this happens on every pass; for the for-header variable once, at the init.
OP evaluation / result ruleA variable declared inside the body starts from its initializer on every pass (int s = 0; inside the body gives s = 0 at the start of each pass); a for-header variable cannot be printed after the loop (compile error).
OS state-transition ruleEntering the body creates its local variables afresh; leaving it removes them; values left in variables declared before the loop persist into the next pass.
R composition rule (with a neighbour)with for_loop: A variable declared in the for header exists only from its declaration to the end of the for statement, so for and while versions differ: in the while version the counter is still available after the loop.
P plan / role rulePlan: keep each variable as local as possible - declare a loop index in the for header when it is not needed afterwards, and declare variables that must survive the loop (accumulators, counters, loop variables needed later) before it.
C conservation ruleMoving a declaration from before the loop into the body re-initializes the variable every pass and makes it unusable after the loop; moving a for-header declaration out (int i; for (i = 0; ...)) keeps the loop's behaviour and makes i usable after it.
D error rulerule broken: A variable declared in the body is in scope only to the end of the body and is re-declared and re-initialized on every pass. (silent logic error)
D error rulerule broken: A for-header variable is out of scope after the loop. (compile-time)
D error rulerule broken: A local variable cannot be redeclared in its own scope. (compile-time)
X applicability ruleDeclare the index in the for header when it is used only inside the loop; declare it before the loop when its final value is needed (as in the break-based primality test) and declare running results before the loop.
