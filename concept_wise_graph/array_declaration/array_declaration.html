Rule typeRule
E folk-meaning ruleFolk meaning: in maths and English, writing 'int[] a' reads as 'a is an array of ints', as if naming a list brings it into existence. Java rule: the declaration only creates a variable that can hold a reference to an int array; no array object or element space exists until new or an initializer creates one.
M wrong rule / right ruleArrayElementsUntyped: wrong: An array can hold elements of any type. | right: Every element of an array has the declared element type: an int[] holds only int values, a String[] only String references.
M wrong rule / right ruleDeclarationCreatesArray: wrong: int[] a; already makes an array that can be indexed. | right: The declaration only names the array variable; until new (or an initializer) creates the array, a[i] gives the compile-time error 'variable a might not have been initialized'.
M wrong rule / right ruleArrayBracketCountIsLength: wrong: The number of brackets in an array type is the array's length. | right: Each bracket pair adds one dimension (int[] is 1-D, int[][] is 2-D); the length is not part of the type and is fixed only when the array is created.
M wrong rule / right ruleElementNameIsWholeArray: wrong: X[i] names the whole array, not one element. | right: The name a (written a[] in the book) denotes the whole array; a[i] denotes the single element at index i.
T uneven-application rulePoints to LT: declare, then create, then initialize, in that order. Inconsistent application: the trace treats a as already created on some lines (reading a[i] straight after 'int[] a;') while requiring new on others.
N identity ruleIdentity: a local variable declaration whose type is T[]; it introduces a name for a reference to an array whose elements have type T.
S declarative ruleDeclarative: 'T[] name;' declares an array variable of element type T (the C-style 'T name[]' is also legal); the length is not part of the type, so 'int[5] a;' is illegal.
LT operational sequencing ruleSequencing: 'double[] a;' only adds the variable a. In 'double[] a = new double[N];' the right side runs first (N is evaluated, the array is allocated and filled with defaults), and then the reference is stored in a.
OP evaluation / result ruleResult: a declaration produces no value and no output. A declared but unassigned local array variable cannot be read at all, so any use of a or a[i] before an assignment is rejected at compile time.
OS state-transition ruleState transition: after 'int[] a;' the state gains a variable a with no value (not definitely assigned). No array object and no element variables exist yet.
R composition rule (with a neighbour)with array_creation: Composition: the declaration fixes the name and element type, and the creation must match it. 'double[] a = new double[N];' is legal, but 'double[] a = new int[N];' is a compile-time type error, because int[] does not convert to double[].
P plan / role rulePlan/role: give one name to a whole sequence of same-type values, so a program reaches any of N values as a[i] instead of declaring N separate variables a0, a1, ...
C conservation ruleConservation: rewriting 'int[] a' as 'int a[]' keeps the meaning. Changing the element type changes which values may be stored and the default values. Deleting the creation step breaks the program at compile time.
D error rulerule broken: An array variable must refer to a created array before it is used (definite assignment). (compile-time)
D error rulerule broken: All elements have the declared element type. (compile-time)
X applicability ruleApplicability: declare an array when a program must hold many values of one type and reach them by position. Do not use one for a single value, for values of different types, or for a collection that must grow as values arrive (a resizing structure such as ArrayList fits that case).
