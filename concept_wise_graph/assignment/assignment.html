Book (SW-1e, p. 16 (pdf 26)): “The left-hand side of an assignment statement must be a single variable; the right-hand side can be an arbitrary expression that produces values of the type.”
Book (OT-Op1, ): “it assigns the value on its right to the operand on its left”

Rule typeRule
E folk-meaning ruleIn maths, = states a symmetric, lasting equality (a = b means b = a, and x = x + 5 is false). In Java, = is a one-time, directed action: evaluate the right side, then store the result in the variable on the left.
M wrong rule / right ruleAssignCompares: wrong: = compares two values instead of assigning | right: x = y copies the value of y into x; x == y is what compares them.
M wrong rule / right ruleAssignmentNotExpression: wrong: an assignment cannot be used inside a larger expression | right: An assignment is an expression whose value is the value assigned, so (x = v) both stores v in x and gives v.
M wrong rule / right ruleAssignmentOppositeDirection: wrong: a = b copies the value of a into b. | right: Assignment stores the value of the right side into the variable on the left.
M wrong rule / right ruleSwapWithoutTemp: wrong: a[i] = a[j]; a[j] = a[i]; exchanges the two values. | right: A temporary variable must save a[i] before it is overwritten.
M wrong rule / right ruleVariablesHoldExpressions: wrong: = stores the expression itself, not its computed value | right: y = x + k; stores the value that x + k has at that moment, so later changes to x do not change y.
M wrong rule / right ruleAssignmentCopiesObject: wrong: assigning a reference copies the object | right: b = a; copies only the reference, so a and b refer to the same array and b[i] = v also changes a[i].
M wrong rule / right ruleAssignmentAddsToTarget: wrong: a = b adds the value of b to the value already in a (the accumulator model). | right: a = b replaces the old value of a with the value of b; the old value is lost.
M wrong rule / right ruleAssignmentIsEquation: wrong: An assignment states a lasting equality between its two sides, so y = x - y can be solved like the equation x = 2y and x = x + 5 relates two equal quantities. | right: An assignment is a one-time action: evaluate the right side with current values, then store the result in the left variable.
M wrong rule / right ruleAssignmentExchangesValues: wrong: b = a exchanges the values of a and b. | right: b = a copies a into b and leaves a unchanged; an exchange needs a temporary variable and three assignments.
M wrong rule / right ruleAssignmentEmptiesSource: wrong: After b = a, a no longer holds a value, as if the value had been moved. | right: Assignment copies; the variable on the right keeps its value.
M wrong rule / right ruleVariableKeepsOldValue: wrong: A variable keeps its first value after a new assignment (the static model). | right: Each assignment or read replaces the variable's current value.
T uneven-application rulePoints to LT (evaluate the right side with current values, then overwrite the left variable). Applied unevenly, a student traces one segment correctly but reads the next as simultaneous equations or as a swap, giving 15 and 15 for one segment and 5 and 10 for the other.
N identity ruleAssignment statement: the statement variable = expression; which stores a data-type value in a variable.
S declarative ruleThe left-hand side must be a single variable. The right-hand side can be any expression whose type is compatible with the variable's type. = is not mathematical equality (a + b = b + a and 1 = a are illegal).
LT operational sequencing ruleFirst the right-hand side is fully evaluated using the variables' current values (left to right). Then that value is stored in the left-hand variable, replacing its old value, and execution moves to the next statement.
OP evaluation / result ruleAs a statement it prints nothing; its result is the new value of the left variable (after c = a + b; with a = 1234 and b = 99, c is 1333). Used as an expression, its value is the value assigned.
OS state-transition ruleExactly one variable, the left one, changes, and its old value is lost. Variables on the right keep their values: x = x + 5; with x = 5 makes x 10.
R composition rule (with a neighbour)with variable: The left side must be a declared variable whose type accepts the value. Assignment is how that variable's value changes.
R composition rule (with a neighbour)with declaration: A declaration can include the first assignment (int x = 5;). Assigning to a variable that was never declared does not compile.
R composition rule (with a neighbour)with array_exchange: Exchanging a[i] and a[j] takes three assignments in a fixed order through a temporary, because each assignment overwrites its target.
R composition rule (with a neighbour)with variable_swap: int t = a; a = b; b = t; works only in this order, because every assignment destroys its left variable's old value.
R composition rule (with a neighbour)with compound_assignment: x op= e is shorthand for x = x op e. The left variable's current value is fetched first and then combined with e.
R composition rule (with a neighbour)with chained_assignment: Because an assignment is an expression whose value is the value stored, and = groups right to left, a = b = 0 first stores 0 in b and then stores that 0 in a.
R composition rule (with a neighbour)with increment_operators: As a statement, i++ has the same effect as the assignment i = i + 1.
R composition rule (with a neighbour)with program_trace: A trace records the value of each variable after each assignment runs, one row per statement.
P plan / role ruleAssignment gives a variable its value in each role: initialization, counter update (n = n + 1), gatherer update (sum = sum + x), most-wanted holder update (max = x), or temporary (t = a).
C conservation ruleSwapping the two sides (a = b versus b = a) changes which variable changes. Reordering assignments changes the final values. An assignment cannot be undone, because the old value is lost unless it was first saved in a temporary.
D error rulerule broken: A local variable may be declared only once in its scope; later changes use an assignment without the type. (compile-time)
D error rulerule broken: The left-hand side of = must be a single variable; only the right-hand side may be an arbitrary expression. (compile-time)
D error rulerule broken: A final variable is assigned exactly once; it cannot be reassigned after initialization. (compile-time)
D error rulerule broken: = assigns and == compares; a condition needs a boolean. (compile-time)
D error rulerule broken: The assigned value's type must fit the variable's type. (compile-time)
X applicability ruleUse assignment whenever a variable's value must be set or updated. Use == to compare, final to forbid updates, and op= or ++ for x = x op e.
