Rules of the concept (17)

Book (SW-1e, p. 11 (pdf 21)): “things within quotes are taken literally so that you can precisely specify what gets printed.”
Book (RS, ): “String literals must not span more than one line of a program.”
Book (SW-1.1, ): “The key line with System.out.println() prints the text "Hello, World" in the terminal window.”
Rule typeRule
E folk-meaning ruleEveryday reading: quotation marks are just decoration, and spacing inside them is tidied up like ordinary text; single and double quotes mean the same thing. Java rule: characters within double quotes are taken literally (every space counts), the quotes are not part of the value, and single quotes are for one char.
T uneven-application ruleApplies the literal rule unevenly: prints the quotes on one line but not another, or collapses spaces inside one string but keeps them in another.
N identity ruleA string literal is a sequence of characters written in double quotes in the source code, e.g. "Hello, World"; it is a value of type String.
S declarative ruleA String literal is enclosed in a pair of double quotes; everything inside is taken literally, special characters such as " and newline are written with escape sequences, and the literal must close on the same source line.
LT operational sequencing ruleThe literal is a constant: it is fixed at compile time and simply supplies its value when the expression containing it is evaluated.
OP evaluation / result ruleValue is the String of the characters between the quotes (escape sequences replaced by the characters they stand for), without the quotes: "Hi, " has 4 characters, and printing it shows Hi, followed by a space.
OS state-transition ruleEvaluating a literal changes no state; it just yields the same String value every time.
R composition rule (with a neighbour)with print: print("s") outputs exactly the characters between the quotes, without the quotes.
R composition rule (with a neighbour)with println: println("s") outputs exactly the characters between the quotes and then ends the line.
R composition rule (with a neighbour)with escape_sequences: Escape sequences (\n, \t, \", \\) are written inside string or char literals to stand for one character that cannot be typed directly.
P plan / role rulePurpose: state fixed text exactly, such as messages, labels and prompts, so you can precisely specify what gets printed.
C conservation ruleChanging any character inside the quotes (including adding a space) changes the output by exactly that character; changing spaces outside the quotes changes nothing.
D error rulerule broken: String literals use double quotes; single quotes are for one char (compile-time)
D error rulerule broken: A string literal must not span source lines (compile-time)
D error rulerule broken: A String literal is enclosed in a pair of double quotes (compile-time)
D error rulerule broken: A double quote inside a string must be escaped (compile-time)
X applicability ruleUse a string literal for fixed text known when the program is written; use args, input or variables for text that varies between runs, and char literals for a single character.
