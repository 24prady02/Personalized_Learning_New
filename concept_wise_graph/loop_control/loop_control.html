Rules of the concept (28)

Book (SW-1e, p. 55 (pdf 65)): “Many loops follow this scheme: initialize an index variable to some value and then use a while loop to test a loop continuation condition involving the index variable”
Book (SW-1.3, ): “Many loops follow the same basic scheme: initialize an index variable to some value and then use a while loop to test an exit condition.”
Rule typeRule
E folk-meaning ruleFolk meaning: in mathematics i = 0, i < n and i = i + 1 are equations or constraints that hold at the same time (and i = i + 1 is nonsense). In Java they are three actions run at different moments: init once, test before each pass, update after each pass.
M wrong rule / right ruleOffByOneBound: wrong: < vs <= and 0..n vs 0..n-1 are interchangeable | right: for (i = 0; i < n; i++) runs n times with i going up to n - 1; with <= it runs n + 1 times and reaches i = n.
M wrong rule / right rulePreIncrementBeforeLoop: wrong: ++i in the for-update runs before the body each pass | right: The update runs after each pass of the body, so with either ++i or i++ the first pass uses i = s.
M wrong rule / right ruleInfiniteLoopUnnoticed: wrong: a condition that never goes false still terminates | right: A while loop stops only when its condition is false at a check, so if no pass changes the variables in the condition, it never stops.
M wrong rule / right ruleDoubleLoopIndexCount: wrong: for (double x = 0.0; x <= 1.0; x += 0.1) runs exactly 11 times. | right: Using a double as a for-loop index is legal but bad practice: the number of iterations depends on an equality test between double values, which may not give the result you expect.
M wrong rule / right ruleIdiomOverridesCode: wrong: An array loop processes the whole array from index 0 to length-1 and increments its index at the end of the body, whatever the code says. | right: The loop visits exactly the indices that its initialisation, guard and update produce, in the order in which its statements are written.
M wrong rule / right ruleLoopHeaderIsEquations: wrong: The initialization, condition and update of a for header are equations that all hold at the same time. | right: The three header parts are statements run at different moments: init once, then condition test, body, update, repeated.
M wrong rule / right ruleForLoopPartSkipped: wrong: A pass of a loop may leave out one of its parts (the condition test, the body, the update, or the initialization). | right: Each pass of a for loop runs test, then body, then update, every time; the initialization runs once, at the start.
M wrong rule / right ruleForUpdateBeforeBody: wrong: The update part of a for header (e.g. i = i - 4) runs before the body on each pass, so the first pass already sees the updated value. | right: The update runs after the body, before the next condition test; the first pass uses the initial value.
M wrong rule / right ruleLoopUpdateChangesDirection: wrong: The update of the loop variable can change from pass to pass (e.g. switch direction) although the code is the same. | right: The update expression is the same on every pass; the loop variable changes by the rule written in the update.
M wrong rule / right ruleLoopStepAlwaysOne: wrong: A loop variable always goes up or down by 1, whatever the update says (so i = i - 4 is read as i--). | right: The loop variable changes exactly as the update expression says (i += 2, i = i - 4, i *= 2, ...).
T uneven-application ruleApplies the init-test-update rule (LT) unevenly: updates before the body on some passes, skips the test or the update on a pass, or re-runs the init.
N identity ruleLoop control is the init / continuation condition / increment scheme on an index variable that decides how many passes a loop makes and with which values.
S declarative ruleInitialize an index variable, test a loop-continuation condition on it before each pass, and increment it as the last action of each pass; for (<initialize>; <boolean expression>; <increment>) packages the three. Choosing the loop: for when the passes are counted by an index, while when the loop runs until a condition changes, do-while when the body must run at least once; any one can be rewritten as another, so choose the clearest.
LT operational sequencing ruleinit (once) -> test -> body -> update -> test -> body -> update ... -> test false -> exit.
OP evaluation / result ruleThe number of passes and the values seen follow from the three parts: for (int i = 0; i <= N; i++) makes N+1 passes with i = 0..N; with i < N it makes N passes; i += 2 visits every second value.
OS state-transition ruleOne update changes only the loop variable, by exactly the rule written (i++ adds 1, i = i - 4 subtracts 4); one test reads it and returns true or false without changing it.
R composition rule (with a neighbour)with loop_variable: All three control parts act on the loop variable: the init sets it, the condition tests it, the update changes it.
R composition rule (with a neighbour)with for_loop: The for header is exactly the three control slots, separated by semicolons; the body runs after the test and before the update.
R composition rule (with a neighbour)with increment_operators: The update i = i + 1 is usually written i++ (or i += k for other steps); as a whole update statement ++i and i++ are equivalent.
R composition rule (with a neighbour)with infinite_loop: A loop is infinite when the update never moves the variable toward making the condition false (e.g. condition i > 3 with update i = i + 1).
R composition rule (with a neighbour)with loop_performance: The continuation condition fixes the number of iterations, so a sharper bound (i <= n/i instead of i < n) can make a program dramatically faster.
P plan / role rulePlan: counter-controlled loop - the loop variable is a stepper that walks a predictable sequence of values (0..N-1, 1..N, every 2nd value) and fixes the number of passes in advance.
C conservation ruleChanging < to <= adds one pass; starting at 1 instead of 0 removes one; doubling the step halves the passes; reversing init and bound with i-- visits the same values in reverse order (and still processes the same set only if both ends are adjusted).
D error rulerule broken: The number of passes is fixed by the init, the test and the update together. (silent logic error)
D error rulerule broken: The update must move the loop variable toward making the condition false. (silent logic error)
D error rulerule broken: Do not control a loop by an equality test on double values. (silent logic error)
X applicability ruleUse explicit init/test/update control when the passes are counted or follow a fixed step; when the number of passes depends on data computed in the body, control the loop by that data (a while condition) instead.
