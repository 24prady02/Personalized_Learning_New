Rule typeRule
E folk-meaning ruleIn everyday reading of `INPUT A` or `readInt`, the command looks like it inputs the letter A, or 'looks at' a number without using it up. In fact a read takes the next token from the input stream, converts it, and returns the value, which the program must store (e.g. int a = StdIn.readInt()).
M wrong rule / right ruleNextLineAfterNextInt: wrong: A line read after a number read returns the next line typed. | right: readInt() stops right after the number and leaves the rest of that line, including the line separator. A following readLine() returns that rest (often ""), not the next line.
M wrong rule / right ruleStdInRereads: wrong: Calling StdIn.readInt() twice returns the same value twice. | right: Each read consumes its value, so the second call returns the next value.
M wrong rule / right ruleRereadIntoVariableInvalid: wrong: Reading a second input value into a variable that already holds one is an error, so the program cannot run. | right: A later read assigns a new value, which overwrites the old one. y = StdIn.readInt(); y = StdIn.readInt(); is legal, and y keeps the second value.
M wrong rule / right ruleInputReadOnceBeforeLoop: wrong: Reading a value once before the loop is enough; the loop will process each new input value. | right: A loop must call a read inside its body on every pass. A single read before the loop gives one value, which is processed over and over.
T uneven-application rulePoints to LT (each call blocks, then consumes exactly one token, in order). An uneven trace gives a variable a value that was already consumed, skips a token on some reads, or merges two READs into one.
N identity ruleStdIn is a booksite library of static methods that read typed values from the standard input stream: isEmpty, readInt, readDouble, readLong, readBoolean, readChar, readString, readLine, readAll.
S declarative ruleStdIn reads from a stream that may be empty or may contain values separated by whitespace. readInt() reads the next token, parses it as an int and returns it, and the token must have the type the method expects. Outside the book's StdIn library, standard Java reads keyboard input with java.util.Scanner (nextInt(), nextDouble(), nextLine()); a token of the wrong type stops the program with InputMismatchException.
LT operational sequencing ruleWhen execution reaches a read, the program blocks until a complete token is available (at the terminal, until <return>). The read then parses the token and returns, the assignment stores the value, and the next statement runs.
OP evaluation / result rulereadInt returns an int, readDouble a double, readString a String, readBoolean a boolean. AddInts 4 with input 144 233 377 1024 prints Sum is 1778.
OS state-transition ruleOne read moves the input position past one token and returns its value. Assigning that value overwrites the variable's previous value. No other variable changes.
R composition rule (with a neighbour)with stream_model: Every StdIn call takes from the same stream position, so values are delivered once, in order.
R composition rule (with a neighbour)with read_loop_idiom: To read an unknown number of values, each read must be guarded by !StdIn.isEmpty() as the condition of a while loop whose body reads.
R composition rule (with a neighbour)with redirection: With `< file` the same StdIn calls read from the file instead of the keyboard. The program text does not change.
R composition rule (with a neighbour)with input_graph: The reads must follow the file's layout: one readInt() for n first, then pairs of readInt() for each link i j until isEmpty().
R composition rule (with a neighbour)with standard_output: The program turns the input stream into the output stream: values read with StdIn are processed and the results are written with StdOut. The two streams are independent.
R composition rule (with a neighbour)with standard_drawing: StdIn values can drive StdDraw output. PlotFilter reads x, y pairs and draws a point for each, after scaling from the first four numbers.
R composition rule (with a neighbour)with input_format: The method called fixes the type the next token must have: readInt needs an int literal, and readDouble accepts 5 or 5.0.
R composition rule (with a neighbour)with interactive_input: Because a read can run at any point in execution, a read inside a loop lets each typed value decide the next branch.
R composition rule (with a neighbour)with token_vs_line_input: Token reads (readInt, readString) and line reads (readLine) share one position. A token read leaves the rest of its line for the next readLine, so it is best not to mix the two.
P plan / role ruleStdIn brings an unbounded amount of data into a running program. The variable that receives each read plays the Sajaniemi role of most-recent holder.
C conservation ruleChanging the input data changes the results without recompiling. Swapping two reads swaps the values the two variables get. Changing readInt to readDouble accepts more inputs; the reverse breaks on tokens like 12.2.
D error rulerule broken: The next token must parse as the requested type. (run-time exception)
D error rulerule broken: A read requires a remaining value; test StdIn.isEmpty() first. (run-time exception)
D error rulerule broken: StdIn/StdOut/StdDraw/StdAudio are not part of Java; their files must be in the working directory or on the classpath. (run-time exception)
X applicability ruleUse StdIn when the amount of data is large or unknown, comes from a file or another program, or must be supplied while the program runs. Use command-line arguments for a few parameters fixed at launch.
