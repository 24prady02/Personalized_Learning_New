Rules of the concept (34)

Book (SW-1e, p. 15 (pdf 25)): “A variable is a name that we use to refer to a data-type value.”
Book (OT-Datatypes, ): “Local variables are slightly different; the compiler never assigns a default value to an uninitialized local variable.”
Rule typeRule
E folk-meaning ruleIn algebra a variable is an unknown that keeps one value throughout an equation (x in x = 2y), and the 'box' metaphor suggests it can hold several things. In Java a variable is a named storage location holding exactly one value at a time, and that value changes as statements run.
M wrong rule / right ruleLocalVarOutsideScope: wrong: A variable declared inside a block can be used anywhere in the program, like a global. | right: A local variable exists only from its declaration to the end of its block.
M wrong rule / right ruleLoopBodyScopeImpliesLoopLifetime: wrong: a variable declared in the loop body lives across all iterations | right: A variable declared inside the body is created anew on every pass and does not keep the previous pass's value.
M wrong rule / right ruleMultiValueVariable: wrong: A variable can contain more than one value. | right: A variable holds exactly one value at a time; assigning a new value replaces the old one.
M wrong rule / right ruleNameGivesMeaning: wrong: Naming a variable max (or average) makes it hold the largest value (or the average) without code that computes it. | right: A name only labels the variable for human readers; only the statements that assign to it decide its value.
M wrong rule / right ruleVariablesHoldExpressions: wrong: = stores the expression itself, not its computed value | right: y = x + k; stores the value that x + k has at that moment, so later changes to x do not change y.
M wrong rule / right ruleVariablesHoldObjects: wrong: a reference variable holds the whole object, not a reference | right: A reference variable holds only a reference to the object, which is stored separately.
M wrong rule / right ruleAnyValueInAnyVariable: wrong: A variable declared int can hold 2.5 or "hi"; the type is only a label. | right: A data type is a set of values and a set of operations defined on them, so an int variable holds only int values.
M wrong rule / right ruleLocalVariablesAutoInitialized: wrong: local variables get a default value on their own | right: A local variable has no value until it is assigned, and using it before then does not compile.
M wrong rule / right ruleNoReservedWords: wrong: keywords may be reused as identifiers | right: Keywords are reserved by Java and cannot be used as variable names.
M wrong rule / right ruleDeclaredVariableHasNoMemory: wrong: int x; without a value sets aside no memory; the variable only exists once something is assigned. | right: A declaration creates the variable (its storage) with its type; assignment later puts a value in it.
M wrong rule / right ruleVariableRolesInferred: wrong: The computer recognises that one variable plays two roles, e.g. input value and running total, and keeps the values apart; it knows which variable is the counter and which the sum. | right: A variable holds one value at a time; each role (input, counter, running total) needs its own variable and explicit update.
M wrong rule / right ruleVariableKeepsOldValue: wrong: A variable keeps its first value after a new assignment (the static model). | right: Each assignment or read replaces the variable's current value.
M wrong rule / right ruleRereadIntoVariableInvalid: wrong: Reading a second input value into a variable that already holds one is an error, so the program cannot run. | right: A later read simply overwrites the variable's current value.
M wrong rule / right ruleArrayElementNotVariable: wrong: An array element a[i] is not a variable, so it cannot be read into directly or used inside another index, as in a[a[i]]. | right: Each element a[i] is a variable of the element type and can be used anywhere a variable of that type can, including as an index.
T uneven-application rulePoints to LT (a read gives the current value, and each assignment replaces it). Applied unevenly, a student updates the value after some assignments but keeps the first value after others, or switches between a memory model and an equation model across tasks (y = x - y read as x = 2y).
N identity ruleVariable: a name that refers to a typed storage location holding one data-type value.
S declarative ruleA variable must be declared with a type before use. It always holds a value of that type, must be assigned before it is read, and can be used only within its scope (from its declaration to the end of the enclosing block).
LT operational sequencing ruleEach time execution reaches an expression that uses the variable, its current value is fetched at that moment. An assignment to it takes effect only after its right-hand side has been fully evaluated.
OP evaluation / result ruleA variable in an expression yields the value most recently assigned to it, with its declared type. After int a = 5; int b = a; a = 3;, a is 3 and b is 5.
OS state-transition ruleOnly an assignment or an input read into the variable changes it, and it changes only that variable, replacing the old value. Other variables keep their values.
R composition rule (with a neighbour)with literal: Literals commonly give variables their values, and the literal's type must fit the variable's type (int x = 1.1; is rejected).
R composition rule (with a neighbour)with assignment: Assignment is the only statement that changes a variable, and its left-hand side must be a single variable.
R composition rule (with a neighbour)with expression: A variable name is itself an expression whose value is the variable's current value, and it combines with operators into larger expressions.
R composition rule (with a neighbour)with identifier: Each variable is named by an identifier, which must be legal and unique within the variable's scope.
R composition rule (with a neighbour)with naming_convention: A variable's name should describe what it holds (lowerCamelCase), but the name has no effect on its value.
R composition rule (with a neighbour)with program_state: The current values of all variables make up the program's state. A trace records each variable's value after each statement.
P plan / role ruleVariables keep track of values that change as a computation unfolds, each in one role (Sajaniemi): fixed value, stepper, most-recent holder, gatherer (running total), most-wanted holder, follower, one-way flag or temporary.
C conservation ruleRenaming a variable consistently keeps behavior. Reordering statements that write and read it changes results (a = b; b = a; is not a swap). Moving its declaration into a loop body narrows its scope and resets it on every pass.
D error rulerule broken: Every variable must be declared (with a type) before use and referred to by exactly the declared name, inside its scope. (compile-time)
D error rulerule broken: A local variable must be assigned before it is read. (compile-time)
D error rulerule broken: A variable can be used only inside its scope. (compile-time)
D error rulerule broken: One variable holds one value, so each role needs its own variable. (silent logic error)
X applicability ruleUse a variable when a value must be remembered, changes during the computation, or deserves a name as an intermediate result. Use a final constant for a value that never changes, and an array when many values of one type must all be kept.
