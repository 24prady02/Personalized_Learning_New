Rules of the concept (17)

Book (TJ-2e, p. 28 (pdf 50)): “If your program has a logic error, it will compile and run without generating error messages”
Book (TJ-2e, p. 29 (pdf 51)): “Instead, it will do exactly what you told it to do.”
Book (SW-1.1, ): “These errors are (hopefully) caught by the programmer when we execute the program”
Rule typeRule
E folk-meaning ruleEveryday reading: the computer understands what you meant and will complain if the program is wrong. Java rule: a program with a logic error compiles and runs without any message and does exactly what the code says, which differs from what was intended.
M wrong rule / right ruleCompilesMeansWorks: wrong: Code that compiles is code that works. | right: Code that compiles and runs can still compute the wrong result (a logic error).
T uneven-application ruleApplies the 'computer does exactly what is written' rule unevenly: traces some lines literally but reads the intended meaning into the faulty line, and so does not see the bug.
N identity ruleA logic error is an error that makes a program do something other than what the programmer intended, without any compiler or run-time message.
S declarative ruleIf a program has a logic error, it will compile and run without generating error messages, but it will not do the right thing; the compiler and JVM cannot detect it since they don't know what the right thing is.
LT operational sequencing ruleExecution proceeds normally, statement by statement; the faulty statement executes without complaint and passes a wrong value or output onward.
OP evaluation / result ruleResult is a normal-looking but wrong output, e.g. println("Hello, "); println("World!"); prints two lines where one was intended.
OS state-transition ruleEach step makes a legal state change (e.g. an empty statement after if, or resetting sum each pass), but not the intended one.
R composition rule (with a neighbour)with run: A logic error is seen only by running the program and comparing its output with the intended output.
R composition rule (with a neighbour)with run_time_error: A run-time error stops the program with an exception; a logic error lets it finish with wrong output.
P plan / role rulePurpose (of the category): name the errors that only testing against the intended behaviour can find, so they are found by tracing, test cases and added print statements.
C conservation ruleA logic error survives recompiling and rerunning unchanged; changing input may hide or reveal it; fixing it changes output only on the inputs it affected.
D error rulerule broken: The accumulator must be declared and initialized before the loop (silent logic error)
D error rulerule broken: A ; right after if (...) is an empty statement that forms the whole if body (silent logic error)
D error rulerule broken: A while loop tests its condition before the first pass (silent logic error)
D error rulerule broken: print vs println decides line breaks (silent logic error)
X applicability ruleSuspect a logic error when the program compiles and runs to the end but the output is wrong for some inputs; locate it by hand tracing, minimal test cases and print statements, since tools give no message.

L4Extended abstract (concrete-operational reversibility and conservation)
L4 for logical error: the answer reasons beyond the given code by these rules.
Does the answer link the code to a broader context: a changed program, a class of inputs, an unseen problem? Re-tracing changed code value by value is L2; fixing one given failing case is L3.
  • [0] predict_a_change (C) → CompilesMeansWorks: A logic error survives recompiling and rerunning unchanged; changing input may hide or reveal it; fixing it changes output only on the inputs it affected.
  • [1] diagnose_an_error (D): rule broken: A ; right after if (...) is an empty statement that forms the whole if body. Kind: silent logic error. Trigger class: if (x > 0); System.out.println("positive"); prints for every x
  • [2] diagnose_an_error (D): rule broken: The accumulator must be declared and initialized before the loop. Kind: silent logic error. Trigger class: int sum = 0; written inside the loop body: sum is reset each pass (and is out of scope after the loop)
  • [3] transfer_to_a_new_program (X): Suspect a logic error when the program compiles and runs to the end but the output is wrong for some inputs; locate it by hand tracing, minimal test cases and print statements, since tools give no message.
  • [4] diagnose_an_error (D): rule broken: A while loop tests its condition before the first pass. Kind: silent logic error. Trigger class: values set before the loop already make the condition false, so the body never runs
  • [5] diagnose_an_error (D): rule broken: print vs println decides line breaks. Kind: silent logic error. Trigger class: println used where print was meant (or the reverse)
