Rules of the concept (15)

Book (TJ-2e, p. 10 (pdf 32)): “An algorithm is a sequence of steps that specifies how to solve a problem.”
Book (TJ-2e, p. 219 (pdf 241)): “To outline this algorithm, we'll use a combination of Java statements and English comments. This technique is sometimes called pseudocode”
Rule typeRule
E folk-meaning ruleEveryday instructions leave steps to the reader's common sense. An algorithm lists every step that specifies how to solve the problem, and the computer does exactly those steps in order.
M wrong rule / right rulePseudocodeRunsAsIs: wrong: Pseudocode can be compiled and run as it is. | right: Pseudocode mixes Java and English to outline the algorithm; every English step must still be written as Java statements before the program compiles.
M wrong rule / right ruleComputerFillsInIntent: wrong: The computer fills in omitted steps or values that the programmer meant. | right: The computer executes exactly the statements written, once each in the order given; nothing that was meant but not written happens.
T uneven-application ruleApplies the algorithm idea unevenly: spells out every step for one part of the problem but leaves another part as a single vague step that the computer is expected to understand.
N identity ruleAlgorithm: a sequence of steps that specifies how to solve a problem; pseudocode: an outline of it in English and Java.
S declarative ruleAn algorithm is a sequence of steps that specifies how to solve a problem. Pseudocode outlines it with a mix of Java statements and English comments, and shows which smaller steps still have to be written.
LT operational sequencing ruleSequencing: state the problem, write the steps in order in pseudocode, refine each English step until it is one or a few Java statements, then code and test.
OP evaluation / result ruleResult: the outcome of an algorithm on an input is found by carrying out its steps by hand; Euclid's algorithm on 1440 and 408 gives 24.
OS state-transition ruleState transition: one step of an algorithm changes the values it works on in one defined way, as one statement does in the program.
R composition rule (with a neighbour)with statement: Each step of the algorithm becomes one or more statements, executed in the same order.
R composition rule (with a neighbour)with flowchart: A flowchart and pseudocode describe the same algorithm: one as a diagram of the flow of control, the other as text.
P plan / role rulePlan: decide what the program must do, step by step, before writing Java, so that the code only translates the steps.
C conservation ruleConservation: refining a pseudocode step into Java keeps its meaning; a different algorithm for the same problem (for example Euclid versus trying every divisor) keeps the answer but changes the number of steps.
D error rulerule broken: Every step of an algorithm must be stated. (logic error)
X applicability ruleBefore coding a non-trivial problem, write the algorithm as pseudocode, check it by hand on a small input, then translate each step into Java.
