Rules of the concept (22)

Book (SW-1e, p. 21 (pdf 31)): “the value of a / b is the number of times b goes into a with the fractional part discarded”
Book (SW-1e, p. 39 (pdf 49)): “Since both 10 and 3 are integer literals, Java sees no need for type conversion and uses integer division.”
Book (JLS-15.17, ): “Integer division rounds toward 0.”
Rule typeRule
E folk-meaning ruleIn everyday and school arithmetic, 'divide' gives an exact answer or a fraction (10 ÷ 3 = 3 1/3), and rounding goes to the nearest whole number. In Java, / with two int operands discards the fraction, rounding toward zero (59 / 60 is 0).
M wrong rule / right ruleAllDoublesToAvoidDivision: wrong: Making every variable a double is the right fix for integer division. | right: Use int for countable things and double for measured ones; where a fraction is needed, make one operand of the division a double (or cast) instead of changing every type.
M wrong rule / right ruleCastAfterIntDivision: wrong: (double) (3 / 5) is 0.6. | right: The integer division 3 / 5 = 0 happens before the cast, so the result is 0.0.
M wrong rule / right ruleIntegerDivisionGivesFraction: wrong: 10 / 3 evaluates to 3.333.... | right: Dividing two ints gives an int: the fractional part is discarded.
M wrong rule / right ruleLaterDoubleLiteralFixesDivision: wrong: Changing a later literal to 100.0 fixes an earlier int division. | right: The int division happens first; the double must be in the division itself.
M wrong rule / right ruleTargetTyping: wrong: The type of a numerical expression depends on the type expected by the surrounding context, so double d = a / b; keeps the fraction. | right: The type of a numerical expression is determined by the expression, so double d = a / b; with int a and b still divides as ints.
M wrong rule / right ruleNegativeRemainderSign: wrong: a % b is never negative, and integer division of a negative number rounds down. | right: a / b rounds toward 0 and a % b takes the sign of a: -14 / 3 is -4 and -14 % 3 is -2.
T uneven-application rulePoints to LT (each / looks at its own two operand types when it is evaluated). Applied unevenly, a student evaluates 9/5 as 1.8 in f = (9/5)*c + 32 but as 1 elsewhere, or assumes a later double operand rescues an earlier int division.
N identity ruleInteger division: / applied to two integer operands, giving the whole-number quotient with the fractional part discarded.
S declarative ruleIf both operands of / are integral types, the result is an integer that rounds toward 0 (-14 / 3 is -4). If either operand is a double, the division is floating point.
LT operational sequencing ruleEach / is evaluated when its turn comes (precedence, then left to right), using the types of its own two operands. Promoting the result to double, by a cast or by assignment, happens only afterwards and cannot restore the lost fraction.
OP evaluation / result rule10 / 3 is 3, 59 / 60 is 0, 1234 / 99 is 12, -14 / 3 is -4, and (double) (3 / 5) is 0.0.
OS state-transition ruleq = a / b stores the truncated quotient in q and leaves a and b unchanged. If b is 0, an ArithmeticException stops execution before anything is stored.
R composition rule (with a neighbour)with arithmetic_operators: / and % on ints are paired: q = a / b and r = a % b always satisfy a = b * q + r.
R composition rule (with a neighbour)with normalization: Normalizing counts must divide as doubles. With two ints, counts / total truncates to 0 whenever counts < total.
R composition rule (with a neighbour)with remainder_operator: % gives the remainder of the same truncating division: (a / b) * b + a % b == a.
P plan / role ruleQuotient plans: unit conversion (76 / 12 feet), dropping a digit (n / 10), finding a midpoint ((lo + hi) / 2), and computing a bucket or row index (i / cols).
C conservation ruleMaking one operand a double (10.0 / 3) keeps the fraction (3.333...). Casting after the division does not. Multiplying before dividing preserves precision (59 * 100 / 60 is 98). Changing an operand's sign changes only the quotient's sign, since rounding is toward zero.
D error rulerule broken: With two int operands, / discards the fraction. (silent logic error)
D error rulerule broken: int division by zero is undefined. (run-time exception)
D error rulerule broken: Integer division rounds toward zero, not down. (silent logic error)
X applicability ruleUse integer division when you want the whole quotient (units, digits, indices, half a size). When a fraction is needed, make one operand a double (10.0 / 3 or (double) a / b) rather than turning every variable into a double.
