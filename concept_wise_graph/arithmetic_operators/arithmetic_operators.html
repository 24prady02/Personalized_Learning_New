Rule typeRule
E folk-meaning ruleIn maths notation, multiplication can be implicit (2x), ^ or a superscript means a power, ÷ is exact division, and % means percent. In Java * must be written, / depends on the operand types, % is the remainder, and there is no power operator (^ is exclusive or).
M wrong rule / right ruleCaretIsPower: wrong: a^2 computes a squared. | right: Java has no exponent operator; ^ is exclusive or, and a * a or Math.pow(a, 2) computes a squared.
M wrong rule / right ruleArithmeticOnNumericStrings: wrong: "10" - 1 or "6" * "2" works because the strings look like numbers. | right: Arithmetic operators other than + are not defined for Strings; a String of digits must first be converted to a number, e.g. with Integer.parseInt.
T uneven-application rulePoints to LT (evaluate operands, then apply the operator in the promoted type). Applied unevenly, a student uses integer division for one / and real division for another / in the same int expression.
N identity ruleArithmetic operators: the binary operators + - * / % that combine two numeric operands into a numeric result.
S declarative ruleBoth operands must be numeric, and the result has the promoted type (int, long or double). * / % bind tighter than + -, all group left to right, and int / or % by zero throws ArithmeticException. Unary minus negates its operand (-x) and unary plus leaves it unchanged; they bind more tightly than * and /, so -a * b is (-a) * b.
LT operational sequencing ruleThe left operand is evaluated fully, then the right operand, and then the operator is applied in the promoted type.
OP evaluation / result ruleWith ints, 17 / 3 is 5 and 17 % 3 is 2. With doubles, 5.0 / 3.0 is 1.6666666666666667. With mixed operands, the int is promoted first (10 / 3.0 is 3.333...).
OS state-transition ruleAn arithmetic operator never changes its operands. Each variable is replaced by its value, and only an assignment (or ++ or op=) stores the result.
R composition rule (with a neighbour)with expression: Operators build larger expressions from smaller ones, and each operand can itself be any expression.
R composition rule (with a neighbour)with integer_division: For ints, / gives the truncated quotient and % the remainder, so (a / b) * b + a % b == a.
R composition rule (with a neighbour)with division_by_zero: int / or % by zero throws a run-time exception, while floating-point division by zero gives Infinity or NaN.
P plan / role ruleArithmetic operators turn formulas into code: totals, averages, unit conversions (inch * CM_PER_INCH), and digit extraction (n % 10, n / 10).
C conservation ruleChanging an operand's type changes the operator's meaning (int / versus double /). Reordering * and / changes integer results (59 * 100 / 60 is 98, 59 / 60 * 100 is 0). Replacing ^ with Math.pow gives a real power.
D error rulerule broken: int / and % by zero are undefined. (run-time exception)
D error rulerule broken: Arithmetic operators other than + are not defined for Strings. (compile-time)
D error rulerule broken: ^ is not exponentiation. (silent logic error)
D error rulerule broken: int arithmetic wraps silently on overflow. (silent logic error)
X applicability ruleUse the operators for arithmetic on numeric types. Use the Math library for powers, roots and absolute values, and parse numeric Strings before computing with them.
