Rules of the concept (19)

Book (SW-1e, p. 58 (pdf 68)): “In particular, we can use one or more of them in the <body> of another to make compound statements.”
Book (TJ-2e, p. 75 (pdf 97)): “you can also make complex decisions by nesting one conditional statement inside another.”
Book (OT-If, ): “once a condition is satisfied, the appropriate statements are executed (grade = 'C';) and the remaining conditions are not evaluated.”
Book (SW-1.3, ): “We can use one or more of them in the body of another statement to make compound statements.”
Rule typeRule
E folk-meaning ruleFolk meaning: in prose, indentation and line layout show what belongs to what, and two consecutive 'if' sentences can be heard as one combined condition. The Java compiler ignores indentation: an inner if belongs to the branch that syntactically contains it, and an else pairs with the innermost unmatched if.
M wrong rule / right ruleElseMatchesIndentation: wrong: The else belongs to the if it is lined up with. | right: The else belongs to the most recent unmatched if, whatever the indentation.
M wrong rule / right ruleMultipleElseIfBranchesRun: wrong: Every true branch of an else-if chain runs. | right: Only the first branch whose condition is true runs.
M wrong rule / right ruleNestedIfsInsteadOfLogicalOperators: wrong: A condition on several values has to be written as nested if statements, one value per if. | right: Several conditions combine into one boolean expression with && and ||, e.g. if (x == 0 && y == 0).
M wrong rule / right ruleInnerIfIgnoresOuter: wrong: An inner if runs its body whenever its own condition is true, even if the outer if condition is false. | right: The inner if is part of the outer branch: it is reached, and its condition tested, only when the outer condition is true.
M wrong rule / right ruleSequentialIfsAreNested: wrong: Of two if statements one after the other, the second runs its body only if both conditions are true. | right: Two ifs in sequence are independent: each tests only its own condition.
T uneven-application ruleApplies the nesting rule (LT) unevenly: on some inputs tests the inner condition even though the outer one was false, or matches an else to the if it is lined up with.
N identity ruleNested conditionals are if or if-else statements placed inside a branch of another conditional; an else-if chain is the common special case.
S declarative ruleAn if/if-else is a statement, so it can be the body (branch) of another conditional; without braces an else belongs to the innermost if to which it might belong, so braces should be used to resolve ambiguities.
LT operational sequencing ruleTest the outer condition; only if control enters the branch that contains the inner if is the inner condition tested; after the inner statement, control leaves the outer statement too.
OP evaluation / result ruleThe output is the action of the single path whose conditions all hold along the way: if (a > b) { if (b > c) X; else Y; } else Z; runs X when a > b > c, Y when a > b and b <= c, and Z otherwise.
OS state-transition ruleOne execution evaluates the conditions along one path only (outer, then possibly inner) and applies one leaf action; conditions on other paths are never evaluated.
R composition rule (with a neighbour)with if_else_statement: Nesting puts an if or if-else inside a branch of another if-else; when the inner statement fills the else branch it forms an else-if chain.
R composition rule (with a neighbour)with dangling_else: The dangling-else ambiguity arises when ifs are nested without braces: if <e1> if <e2> A else B attaches else to the inner if.
R composition rule (with a neighbour)with switch_statement: For more than two mutually exclusive alternatives a chain of if-else statements works, but a switch tests one expression against many values directly.
P plan / role rulePlan: decision tree - refine a case analysis step by step (e.g. find the smallest of three values, classify a value into ranges).
C conservation ruleCombining if (c1) { if (c2) S; } into if (c1 && c2) S; preserves behaviour when there are no else parts; adding or removing braces around an inner if can move an else to a different if. Swapping some branches can keep the specification only on certain inputs.
D error rulerule broken: Without braces an else pairs with the innermost if, whatever the indentation. (silent logic error)
X applicability ruleNest conditionals when a second test only makes sense once the first has succeeded or when cases form a tree; use && for a simple conjunction, an else-if chain for mutually exclusive ranges, and a switch for many discrete values; one or two levels usually suffice.
