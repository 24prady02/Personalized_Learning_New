Rules of the concept (13)

Book (SW-1e, p. 133 (pdf 143)): “enables us to create data-driven code”
Book (SW-1e, p. 177 (pdf 187)): “Data-driven code is prevalent”
Rule typeRule
E folk-meaning ruleIn the everyday sense, a 'program' includes its data, so changing the results means editing the code. In data-driven code the data live in files read from standard input, so they change while the program stays the same.
T uneven-application rulePoints to LT (the program reads the file's values, in the file's order, at run time). An uneven trace uses values from a different file, or hard-coded values, for some reads.
N identity ruleData-driven code is a design style: data are kept in files and the program reads them from standard input, so the data can change without changing the program.
S declarative ruleKeep the data in files and write programs that read from standard input. Then change the data, not the program.
LT operational sequencing ruleThe program is launched with `< file`. It reads values in file order and interprets them by a format convention (e.g. a header first, then records) until isEmpty().
OP evaluation / result ruleThe same program with different files gives different outputs. `java PlayThatTune < elise.txt` plays Für Elise, and another file plays another tune.
OS state-transition ruleEach read takes the next value from the data file, where a literal written in the code would otherwise be.
R composition rule (with a neighbour)with redirection: Redirecting a different data file to standard input changes what the unchanged program processes.
P plan / role ruleData-driven code lets one program serve many data sets (experiments, transactions, web models). It is the norm in data processing.
C conservation ruleChanging the data file keeps the program and its correctness. Changing the file's format (field order, header) breaks the program's reads.
D error rulerule broken: The data file must follow the program's input format. (run-time exception)
D error rulerule broken: The data file must contain all the values the program reads. (run-time exception)
X applicability ruleUse data-driven code when the same computation must run on many or changing data sets. Values that are intrinsic to the algorithm belong in the code, and a few launch parameters go on the command line.
