Rules of the concept (16)

Book (TJ-2e, p. 92 (pdf 114)): “If you want to increment or decrement a variable by an amount other than 1, you can use += and -=.”
Book (SW-1.3, ): “The compound assignment statement x += 0.5 is equivalent to x = (int) (x + 0.5).”
Rule typeRule
E folk-meaning ruleFolk meaning: x -= y reads as 'x equals minus y' and x += 0.5 as 'add a half' in arithmetic. In Java x op= e means x = (T) (x op e): it updates x from its current value and casts the result back to x's type.
M wrong rule / right ruleCompoundAssignmentNoCast: wrong: x += 0.5 adds one half to an int x. | right: x += 0.5 means x = (int) (x + 0.5) for an int x, so the sum is cast back to int and truncated: x stays the same (x = 3 gives 3.5, cast to 3).
M wrong rule / right ruleCompoundSubtractIsAssignNegative: wrong: x[i] -= y sets x[i] to -y (reads -= as assignment of a negated value). | right: x[i] -= y means x[i] = x[i] - y: it subtracts y from the current value.
T uneven-application ruleApplies the compound-assignment rule (LT) unevenly: uses the current value of x on some passes but treats x -= y as x = -y on others, or forgets the implicit cast on some lines.
N identity ruleA compound assignment operator (+=, -=, *=, /=, %=) is an assignment shorthand that combines a binary operation with storing the result back in the left-hand variable.
S declarative rulex op= e is equivalent to x = (T) ((x) op (e)) where T is the type of x, with x evaluated only once; it works for any arithmetic operator in any primitive numeric type. x op= e means x = (T)(x op e), with a hidden cast to the type T of x: with int x = 3, x += 0.5 compiles and leaves 3, while x = x + 0.5 does not compile.
LT operational sequencing ruleEvaluate x and save its value, then evaluate e, then compute x op e, cast to x's type, and store into x.
OP evaluation / result ruleThe new value of x is (T)(old x op e) and is also the expression's value: each starting from int x = 7: x += 3 gives 10, x /= 2 gives 3, and x += 0.5 gives 7 (7.5 truncated) instead of a compile error.
OS state-transition ruleOne execution changes exactly one variable, x, from its old value (sum += x[i] turns sum = 1 into 1 + 4 = 5).
R composition rule (with a neighbour)with assignment: x op= e is shorthand for the assignment x = x op e, so the new value depends on the old one (x is read, then written).
R composition rule (with a neighbour)with explicit_cast: x op= e includes a hidden narrowing cast to the type of x: with int x = 1, x += 1.7 compiles (as x = (int)(x + 1.7), giving 2) while x = x + 1.7 does not.
P plan / role rulePlan/role: the update step of a gatherer (sum += a[i], product *= i) or of a stepper with a step other than 1 (i += 2).
C conservation ruleFor a variable of the same type as the result, replacing x op= e by x = x op e preserves behaviour; when x is narrower (int x, double e), x = x op e no longer compiles, so the two are not always interchangeable. Swapping += and -= reverses the effect of each pass.
D error rulerule broken: x op= e silently casts the result to the type of x. (silent logic error)
D error rulerule broken: =- is assignment of a negated value, not -=. (silent logic error)
X applicability ruleUse op= for in-place updates of accumulators, products and counters with steps other than 1; avoid it when x is int and e is fractional (silent truncation), and use explicit x = x op e when the cast should be visible.

  • [1] transfer_to_a_new_program (X): Use op= for in-place updates of accumulators, products and counters with steps other than 1; avoid it when x is int and e is fractional (silent truncation), and use explicit x = x op e when the cast should be visible.

  • [3] diagnose_an_error (D): rule broken: =- is assignment of a negated value, not -=. Kind: silent logic error. Trigger class: Typing x =- y for x -= y: compiles as x = -y.
