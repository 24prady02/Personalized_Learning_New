Rules of the concept (14)

Book (TJ-2e, p. 62 (pdf 84)): “Start with a working program and make small, incremental changes. At any point, if there is an error, you will know where to look.”
Book (TJ-2e, p. 11 (pdf 33)): “Instead, start with a program that does something and make small modifications, debugging them as you go, until the program does what you want.”
Rule typeRule
E folk-meaning ruleEveryday writing is drafted all at once and revised at the end. A program is grown in small steps from a version that already works, compiling and running after each step.
M wrong rule / right ruleWriteAllThenTest: wrong: Write the whole program first, then compile and test it all at the end. | right: Start with a working program and make small changes, compiling and testing after each one, so an error is always in the last change.
T uneven-application ruleApplies incremental development unevenly: tests the first few steps one at a time, then adds a large block of untested code at once.
N identity ruleIncremental development: growing a program in small, tested steps from a version that works.
S declarative ruleStart with a working program and make small, incremental changes; at any point, if there is an error, you will know where to look. Use variables for intermediate values so you can check them.
LT operational sequencing ruleSequencing: write a few lines, compile, run and check them, then add the next few; never more than one untested change at a time.
OP evaluation / result ruleResult: after every step there is a program that compiles and runs, and does a little more than before.
OS state-transition ruleState transition: one step adds a small piece of code and ends with the program compiling and passing its checks again.
R composition rule (with a neighbour)with run: Running after each step shows at once whether the new lines do what was intended.
R composition rule (with a neighbour)with debugging: Small steps make debugging local: the newest change is the first suspect.
P plan / role rulePlan: keep a working program at all times so that errors are found where they are made.
C conservation ruleConservation: each step must keep everything that already worked; if a step breaks it, that step is undone or fixed before going on.
D error rulerule broken: Compile and test after each small change. (compile-time or logic error)
X applicability ruleFor any new program: get a minimal version running first (even just printing the inputs), then add one feature at a time, testing each.
