Rule typeRule
E folk-meaning ruleFolk meaning: a number is a number, so 3, 3.0 and "3" are the same value, and a variable will take whatever form the context needs (the result 'becomes' double when stored in a double). Java rule: every value has a fixed type; conversions happen only by automatic promotion to a wider type, by an explicit cast, by conversion methods (Integer.parseInt, Math.round), or by String conversion with +.
M wrong rule / right ruleNarrowingAssignmentAllowed: wrong: A double value can be stored in an int variable like an int in a double. | right: int to double is automatic (widening); double to int needs a cast, otherwise the assignment is a compile-time error.
M wrong rule / right ruleNoCastIfSameSize: wrong: If a variable is at least as big as a value, no cast is needed to assign the value. | right: The compiler decides by types, not values: assigning a double to an int needs a cast even when the value (e.g. 3.0) would fit, because a conversion that might involve loss of information leads to a compile-time error.
M wrong rule / right ruleTargetTyping: wrong: The type of a numerical expression depends on the type expected by the surrounding context, so double d = a / b; keeps the fraction. | right: The type of a numerical expression is determined by its operands, so double d = a / b; with int a and b still divides as ints and only then widens the result (1 / 3 gives 0.0).
T uneven-application rulePoints to LT (each subexpression is computed in its own type, and conversion happens only where the types meet). Applied unevenly: the student promotes before an int division on one line (treating 9/5 as 1.8) but not on another, or casts the whole expression on one pass and only the first operand on the next.
N identity ruleType conversion is changing a value of one type into a value of another type: automatic promotion (widening), an explicit cast, an explicit conversion method (Integer.parseInt, Double.parseDouble, Math.round), or automatic conversion to String.
S declarative ruleJava converts automatically to a type with a larger range (promotion) because no information is lost; a conversion that might lose information (double to int) requires an explicit cast or is a compile-time error; Strings and numbers convert only via methods or string conversion.
LT operational sequencing ruleInnermost subexpressions are evaluated in their own types first; at each binary operator the narrower operand is promoted; a cast converts the single value right after it; at an assignment the final value is converted to the variable's type (widening allowed, narrowing rejected at compile time).
OP evaluation / result ruleTypical results: "1234" + 99 is the String "123499"; Integer.parseInt("123") is int 123; (int) 2.71828 is int 2; Math.round(2.71828) is long 3; 11 * 0.3 is double 3.3; 11 * (int) 0.3 is int 0; (int) (11 * 0.3) is int 3.
OS state-transition ruleA conversion produces a new value and never changes the source variable or its declared type: after int x = (int) pi; x is 3 and pi still holds 3.14159.
R composition rule (with a neighbour)with primitive_type: Conversions between primitive types follow their ranges: int to double happens automatically, double to int needs a cast that drops the fraction, and boolean converts to no numeric type.
R composition rule (with a neighbour)with parsing: Parsing methods are explicit type conversion from String to a number: a method takes an argument of one type and produces a result of another.
R composition rule (with a neighbour)with explicit_cast: A cast is the explicit conversion between primitive types, required when information may be lost: (int) 2.71828 is 2.
R composition rule (with a neighbour)with widening_conversion: Widening (promotion) is the automatic kind of conversion, applied at operators and assignments when the target type has a larger range.
P plan / role ruleAdapts data between parts of a program: command-line text to numbers, int counts to double for an average ((double) sum / n), doubles to int indices or counts.
C conservation ruleMoving the point of conversion changes the result: (double) (a / b) differs from (double) a / b, and (int) 11 * 0.3 differs from (int) (11 * 0.3). Widening int to double and back is reversible for int values; narrowing double to int loses the fraction irreversibly.
D error rulerule broken: A conversion that may lose information needs an explicit cast. (compile-time)
D error rulerule broken: Promotion happens per operator, after an int division has already truncated. (silent logic error)
D error rulerule broken: Casts work only between compatible types; a String is converted with a parse method. (compile-time)
D error rulerule broken: A parse method accepts only a valid textual representation of the number. (run-time exception)
X applicability ruleRely on automatic promotion when mixing int with double; write a cast only when you intend to drop information; use parse methods for text input and string conversion for output; paying attention to types avoids subtle bugs.
