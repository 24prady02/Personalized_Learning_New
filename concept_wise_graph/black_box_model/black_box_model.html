Rules of the concept (13)

Book (SW-1e, p. 9 (pdf 19)): “we might think of our Java program as a black box that converts our input string to some output string.”
Rule typeRule
E folk-meaning ruleEveryday meaning: a 'black box' is something mysterious or a flight recorder. Here it means treating a program purely as a function from its input string (the command-line argument) to its output string, ignoring how it works inside.
T uneven-application ruleApplies the model unevenly: treats the program as input-to-output on one run but expects it to remember an earlier run's input, or counts the program text itself as input.
N identity ruleThe black-box model is the view of a Java program as a box that converts an input string (the command-line argument) into an output string (what it prints).
S declarative ruleA program like UseArgument implements a function that maps a string of characters (the argument) into another string of characters (the message printed); the model is general enough, in principle, for any computational task.
LT operational sequencing ruleInput is supplied at launch, the program computes, output is produced; the model hides the order of internal steps.
OP evaluation / result rulePrediction at this level is input-output: for UseArgument, input Alice gives output Hi, Alice. How are you?
OS state-transition ruleOne run maps one input string to one output string; nothing persists between runs.
R composition rule (with a neighbour)with command_line_args: The command-line argument is the box's input string, and what the program prints is its output string; parseInt lets the strings be read as numbers.
P plan / role rulePurpose: describe what a program does (its specification, input to output) separately from how it does it; the compiler itself fits the model (.java text in, .class out).
C conservation ruleAny change inside the box that keeps every input-output pair the same keeps the program's behaviour; a change that alters any pair is a behaviour change.
D error rulerule broken: The output depends only on the input given (run-time exception)
D error rulerule broken: Input and output in 1.1 are limited to strings of limited size (silent logic error)
X applicability ruleUse the black-box view to specify and test programs by input/output pairs; it extends in 1.5 to standard input, standard output, drawing and audio. It does not help to locate an error inside the box; for that, trace the code.
