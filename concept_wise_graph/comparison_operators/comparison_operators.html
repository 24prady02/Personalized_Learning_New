Rules of the concept (26)

Book (SW-1e, p. 26 (pdf 36)): “The most important operators of this kind are the comparison operators ==, !=, <, <=, >, and >=, which all are defined for each primitive numeric type and produce a boolean result.”
Book (SW-1e, p. 28 (pdf 38)): “The comparison operations have lower precedence than arithmetic operators and higher precedence than boolean operators”
Book (OT-Op2, ): “Keep in mind that you must use "==", not "=", when testing if two primitive values are equal.”
Book (SW-1.2, ): “The comparison operators are mixed-type operations that take operands of one type and produce a result of type boolean.”
Rule typeRule
E folk-meaning ruleFolk meaning: in maths = states that two things are equal, and inequalities can be chained (a < b < c) or spoken as 'equal or less than' (=<). Java rule: = assigns while == compares; the operators are spelled <= and >= only; a < b < c does not compile; and on Strings == compares references.
M wrong rule / right ruleAssignCompares: wrong: = compares two values instead of assigning. | right: x = y copies the value of y into x; x == y is what compares them and produces a boolean.
M wrong rule / right ruleChainedComparison: wrong: 90 <= grade <= 100 tests whether grade is between 90 and 100. | right: a < b < c does not compile (a < b is a boolean); a range test is written 90 <= grade && grade <= 100.
M wrong rule / right ruleComparisonWithBooleanLiteral: wrong: You must write == true / == false to test a boolean. | right: if (b) already tests b, so writing == true adds nothing.
M wrong rule / right ruleEqualsComparesReferences: wrong: .equals() compares references, not contents. | right: s.equals(t) checks whether the two Strings contain the same characters; it is == that compares references.
M wrong rule / right ruleEqualityOperatorComparesObjectsValues: wrong: == compares the contents of two Strings. | right: s == t is true only when s and t refer to the same object; "abc" == "ab" + x is false even when x is "c"; s.equals(t) compares the text.
M wrong rule / right ruleStringRelationalComparison: wrong: s < t compares two Strings alphabetically. | right: < and > are defined only for primitive types; comparing Strings with them does not compile (use s.compareTo(t)).
M wrong rule / right ruleLessGreaterSwapped: wrong: < and > mean the same thing (or a < b means a is greater than b). | right: a < b is true when a is smaller than b; a > b when a is larger.
T uneven-application rulePoints to LT (evaluate both operands, promote to a common type, then compare). Applied unevenly: the student treats < as <= on the boundary pass of a loop, or compares an int with a double as ints on one line and as doubles on another.
N identity ruleComparison (relational) operators ==, !=, <, <=, >, >= are mixed-type operators: they take two operands of a numeric type and produce a boolean.
S declarative rule==, !=, <, <=, >, >= are defined for each primitive numeric type and produce a boolean; they have lower precedence than arithmetic and higher than boolean operators; < and > are not defined for Strings, and == on non-primitive types compares identity.
LT operational sequencing ruleEvaluate the left operand (including its arithmetic), then the right operand; if their types differ, promote the narrower one (int to double); then compare and produce true or false.
OP evaluation / result ruleThe result is a boolean: (2 <= 2) is true, 2 < 2 is false, (x < 3.1) is true for int x = 3; any comparison involving NaN, even NaN == NaN, is false.
OS state-transition ruleA comparison changes no variable and only returns a boolean, unlike =, which changes the value of the variable on its left.
R composition rule (with a neighbour)with expression: A comparison is itself an expression whose value is a boolean, so it can appear anywhere a boolean is needed, including on the right of an assignment (boolean ok = x > y;).
R composition rule (with a neighbour)with boolean_expression: Comparisons are the building blocks of conditions: together with boolean logic they provide the basis for decision-making.
R composition rule (with a neighbour)with logical_operators: Comparisons bind tighter than && and ||, so they are evaluated first and logical operators combine their boolean results.
