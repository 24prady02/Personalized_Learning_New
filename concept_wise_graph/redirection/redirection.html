Rule typeRule
E folk-meaning ruleIn maths `<` and `>` mean less-than and greater-than. In a command line they are directives to the operating system: `< file` makes the file the standard input and `> file` sends standard output to the file. They are not part of Java or of args[].
M wrong rule / right ruleRedirectionIsArgument: wrong: A redirected file shows up in args[]. | right: With `< data.txt` the operating system supplies standard input from the file. args[] does not contain it, and the program just reads standard input whatever the source.
T uneven-application rulePoints to LT (the OS connects the file before the program runs; reads come from the file and writes go only to the file). An uneven trace shows output on the screen as well as in the file, or treats the file name as a command-line argument.
N identity ruleRedirection is an operating-system (shell) mechanism that connects a program's standard input or standard output to a file.
S declarative rule`java P > data.txt` writes standard output to data.txt instead of the terminal. `java P < data.txt` makes StdIn read from data.txt. The program itself is not changed.
LT operational sequencing ruleThe shell opens the file and connects it before main starts. Each StdIn read then takes the next value from the file, and each print appends text at the end of the output file.
OP evaluation / result rule`java RandomSeq 1000 > data.txt` prints nothing in the terminal and leaves a file of 1,000 values. `java Average < data.txt` prints their average.
OS state-transition ruleEach read or print still does exactly what it does at a terminal; only the source or destination is a file (one print appends to the file).
R composition rule (with a neighbour)with standard_output: `> file` diverts all standard output (print, println, printf) into the file, so nothing appears in the terminal.
R composition rule (with a neighbour)with standard_input: `< file` makes the file's contents the standard input stream: the same StdIn calls read the file's tokens in order.
R composition rule (with a neighbour)with piping: `A > f` followed by `B < f` has the same effect as `A | B`, except that the pipe creates no file.
R composition rule (with a neighbour)with data_driven_code: Redirecting different files into the same program changes the data it processes without changing the program.
P plan / role ruleRedirection saves output for later and feeds large amounts of data from files, without typing.
C conservation ruleThe program is unchanged whether its input or output is the terminal or a file: the I/O abstraction is conserved. Changing only the file changes only the data.
D error rulerule broken: `> file` replaces the file's previous contents. (silent logic error)
D error rulerule broken: The input file must exist and be readable. (launch error)
D error rulerule broken: A redirected file is finite. (run-time exception)
X applicability ruleUse redirection when the data are in a file or the results should be saved. When a program needs several input or output files at once, use In/Out instead (one standard stream each way).
