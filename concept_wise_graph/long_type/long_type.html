Rules of the concept (15)

Book (SW-1e, p. 23 (pdf 33)): “The long, short, and byte types are the same as int except that they use 64, 16, and 8 bits respectively, so the range of allowed values is accordingly different.”
Book (SW-1.3, p. 85 (pdf 95)): “Use the long data type.”
Rule typeRule
E folk-meaning ruleIn English 'long' just means lengthy, so novices expect any big number to become a long automatically. In Java long is a separate 64-bit type that must be declared, and an integer literal outside the int range needs the L suffix.
M wrong rule / right ruleLargeIntegerLong: wrong: a large integer literal is automatically long | right: A sequence of digits is an int literal only if its value falls within the int range; for larger values the book advises the long type.
T uneven-application rulePoints to LT (only operations with a long operand run in 64 bits). Applied unevenly, a student treats long x = a * b (int a, b) as 64-bit because the target is long.
N identity rulelong: Java's 64-bit signed integer primitive type.
S declarative rulelong ranges from -9223372036854775808 to 9223372036854775807, and its literals end in L. An integer operation with at least one long operand is done in 64 bits and gives a long. int widens to long automatically, but long to int needs a cast.
LT operational sequencing ruleIn a mixed expression each operation checks its own operands. Only operations with a long operand run in 64 bits, so pure-int subexpressions that came earlier were already computed in 32 bits.
OP evaluation / result rule2147483647L + 1 is the long 2147483648. Math.round(3.14159) has type long and value 3.
OS state-transition ruleAssigning to a long variable stores a 64-bit value. Storing a long in an int requires an (int) cast, which keeps only the low 32 bits.
R composition rule (with a neighbour)with int: long is the wider integer type: an int widens to long automatically, and mixing an int with a long in an operation gives a long.
P plan / role rulelong holds huge integers: counts or sums beyond 2 billion, factorials up to 20!, products of large ints, and times in milliseconds.
C conservation ruleChanging int to long removes overflow below about 9.2e18, but a literal product is still computed in int unless one operand is long (1000000 * 1000000 overflows, while 1000000L * 1000000 does not).
D error rulerule broken: A long value needs an explicit cast to be stored in an int. (compile-time)
D error rulerule broken: An integer literal outside the int range needs an L suffix. (compile-time)
D error rulerule broken: A long target does not make int operands 64-bit. (silent logic error)
X applicability ruleUse long when integer values may reach ten digits or more, and int otherwise. Use BigInteger beyond long's range, and double for non-integers.
