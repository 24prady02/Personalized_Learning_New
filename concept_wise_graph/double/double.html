Book (SW-1e, p. 23 (pdf 33)): “The double type is for representing floating-point numbers, for use in scientific and commercial applications.”
Book (OT-Datatypes, ): “For decimal values, this data type is generally the default choice.”

Rule typeRule
E folk-meaning ruleFolk meaning: a number with a decimal point is the exact real number of school maths, and a whole-looking number such as 207. or 2.3e4 is an integer. Java rule: a double is a 64-bit binary approximation from a finite set of values, and any literal with a decimal point or exponent is a double (207. is 207.0, 2.3e4 is 23000.0).
M wrong rule / right ruleFloatingPointIsExact: wrong: Math.sqrt(2) * Math.sqrt(2) == 2 is true. | right: A double is an approximation: Math.sqrt(2) * Math.sqrt(2) is 2.0000000000000004, so the == test is false; compare doubles with a tolerance.
M wrong rule / right ruleWholeNumberLiteralIsInt: wrong: 207. and 2.3e4 are int values because they are whole numbers. | right: A decimal point or scientific notation makes the literal a double, whatever its value: 207. is 207.0 and 2.3e4 is 23000.0, so int n = 2.3e4; does not compile.
T uneven-application rulePoints to LT (at each operator the narrower operand is promoted, then the operation is done in double and rounded). Applied unevenly: the student promotes to double on one line but keeps integer division on another, e.g. treats 1/2 * x as 0.5 * x on one pass and as 0 on the next.
N identity ruledouble is a primitive data type: Java's 64-bit IEEE 754 floating-point type for representing real numbers.
S declarative ruleValues are 64-bit IEEE 754 numbers (about 15 significant digits) plus the special values Infinity and NaN; +, -, *, / (and %) are defined; if at least one operand of a binary arithmetic operator is double, the operation is a floating-point operation.
LT operational sequencing ruleOperators are applied in precedence order, left operand first; at each operator, if one operand is double the other is widened to double before the operation, and the result is rounded to the nearest double before the next operator uses it.
OP evaluation / result ruleThe result has type double: 5.0/3.0 is 1.6666666666666667, 10/3.0 is 3.3333333333333335, 1.0/0.0 is Infinity, Math.sqrt(-1.0) is NaN; println always shows a decimal part (3.0, not 3).
OS state-transition ruleAn assignment to a double variable stores the nearest representable value (x = x + 0.1 replaces x with the rounded sum); no double operation throws an exception, so the variable may end up holding Infinity or NaN.
R composition rule (with a neighbour)with int: Type flow decides the division: with two int operands a / b discards the fraction (10/3 is 3, and double d = 10/3; stores 3.0); if either operand is double the other is promoted and the fraction is kept (10/3.0 is 3.3333333333333335).
R composition rule (with a neighbour)with boolean: double and boolean never convert into each other (no cast is allowed either way); they meet only through comparisons, which take doubles and produce a boolean, e.g. (x < 3.1).
R composition rule (with a neighbour)with char: char is an integral numeric type, so a char widens automatically to double in arithmetic ('a' + 0.5 is 97.5), but a double needs an explicit cast to become a char.
R composition rule (with a neighbour)with floating_point_precision: Every double operation rounds its result to the nearest representable value, so double results carry rounding error that can accumulate; this is why == on computed doubles is unreliable.
R composition rule (with a neighbour)with division_by_zero: For double operands a zero divisor is not an error: 1.0/0.0 is Infinity, -1.0/0.0 is -Infinity and 0.0/0.0 is NaN, whereas int division by zero throws an exception.
R composition rule (with a neighbour)with primitive_type: double is one of the eight primitive types and the default type of decimal literals (float would need an f suffix and is not used in the book).
P plan / role ruleUsed for measured or computed real quantities (physics formulas, roots, averages, probabilities); a double variable often plays the gatherer role, as in Harmonic's sum += 1.0/i.
C conservation ruleChanging a variable from int to double changes / from truncating to real division and changes the printed form (3 becomes 3.0); changing back needs a cast and loses the fraction. Invariant: values are approximations, so reordering a sum ((a+b)+c vs a+(b+c)) may change the last digits.
D error rulerule broken: A double cannot be assigned to an int (narrowing) without a cast. (compile-time)
D error rulerule broken: Floating-point division needs at least one double operand. (silent logic error)
D error rulerule broken: Computed doubles are approximations and must not be compared with ==. (silent logic error)
X applicability ruleUse double for real-valued quantities where approximate results are acceptable (science, geometry, probabilities, averages); do not use it for counts, array indices, loop counters or money that must be exact (use int or long, e.g. cents).
