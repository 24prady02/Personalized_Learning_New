Rules of the concept (25)

Book (SW-1e, p. 49 (pdf 59)): “We often refer to the statement block in a loop as the body of the loop.”
Book (SW-1e, p. 49 (pdf 59)): “As with the if statement, the braces are optional if a while loop body has just one statement.”
Book (SW-1.3, ): “The while loop enables us to execute a group of statements many times.”
Rule typeRule
E folk-meaning ruleFolk meaning: an everyday 'repeat this' instruction can be read loosely - a helper fills in missing steps, does each step N times in turn, or stops partway. A Java loop body is exactly the statements inside its braces (or one statement), all executed in order on every pass.
M wrong rule / right ruleLoopBodyAlwaysOnce: wrong: The loop body always runs at least once, even if the condition is false at the start. | right: A while or for body runs zero times when the condition is false at the start.
M wrong rule / right ruleWhileStopsMidBody: wrong: The loop stops the moment the condition becomes false, even in the middle of the body. | right: The condition is tested only before each pass, so the whole body finishes before the loop can stop.
M wrong rule / right ruleComputerFillsInIntent: wrong: The computer fills in omitted steps or values that the programmer meant, e.g. REPEAT 4 [FORWARD 30] draws a square without a turn command. | right: The computer executes only what the code states; every needed step and value must be written.
M wrong rule / right ruleIfInLoopUnchecked: wrong: An if inside a loop body runs its branch on every pass without testing its condition. | right: The if condition is tested again on every pass, with the current values, so the branch runs only on passes where it is true.
M wrong rule / right ruleLoopCountIsStatementCount: wrong: The repeat count of a counted loop says how many of the body statements are executed. | right: The repeat count is how many times the whole body runs; every pass runs all body statements.
M wrong rule / right ruleLoopBodyStatementOutsideLoop: wrong: Some statements inside the braces of a loop body are not repeated; they run once, before or after the loop. | right: Every statement inside the loop braces is part of the body and runs on every pass.
M wrong rule / right ruleStatementAfterLoopInBody: wrong: A statement written after the loop is repeated with the loop body. | right: The body ends at the closing brace (or after its single statement); code after it runs once, after the loop ends.
M wrong rule / right ruleForLoopPartSkipped: wrong: A pass of a loop may leave out one of its parts (the condition test, the body, the update, or the initialization). | right: Each pass of a for loop runs test, then body, then update, every time; the initialization runs once, at the start.
M wrong rule / right ruleLoopRunsStatementsSeparately: wrong: A loop runs its first body statement all N times, then its second body statement all N times. | right: Each pass runs the whole body in order, so the body statements interleave: S1, S2, S1, S2, ...
M wrong rule / right ruleLoopOutputSameEachPass: wrong: A loop prints the same thing on every pass; the changing loop variable does not affect what the body does. | right: The body uses the current value of the loop variable, so its output can differ on each pass.
M wrong rule / right ruleStateChangeIgnoredAcrossPasses: wrong: Values changed by one pass of a loop (other than the loop variable) do not affect later passes. | right: Each pass starts from the state left by the previous pass, so a change in one pass carries into the next ones.
T uneven-application ruleApplies the body rule (LT) unevenly: runs all body statements on some passes but only some on others, includes the statement after the loop on some passes, or uses stale values from the first pass later.
N identity ruleThe loop body is the statement block that a loop repeats on each pass.
S declarative ruleThe body is the block after the loop header; braces are optional only if it is a single statement, in which case only that one statement is repeated.
LT operational sequencing ruleOn each pass the body's statements run in order, first to last, after a true test (and, in a for loop, before the update); the next pass starts from the state left by this one.
OP evaluation / result ruleThe body's output on each pass depends on the current values, so successive passes can print different lines: TenHellos prints '4th Hello', '5th Hello', ...; the number of executions of each body statement equals the number of passes.
OS state-transition ruleOne pass of the body changes exactly the variables it assigns (e.g. print i and v, double v, increment i) and these changes carry into the next test and pass.
R composition rule (with a neighbour)with accumulator_pattern: The accumulator update (sum += x) is placed inside the body so it runs once per pass, while the accumulator is declared and initialized before the loop.
R composition rule (with a neighbour)with counter_pattern: count++ sits inside the body, often under an if, so it runs once on each pass that matches; the counter is declared before the loop.
R composition rule (with a neighbour)with while_loop: The body is what the while repeats; the condition is tested only between complete executions of it.
P plan / role rulePlan: the body is the 'process one item / one step' part of a loop plan: each pass performs the same process on a new value (next element, next bet, next term).
C conservation ruleMoving a statement from inside the body to after the loop changes it from running once per pass to once in total (and vice versa); reordering two body statements that share a variable changes the results (e.g. increment before vs after use).
D error rulerule broken: Without braces, the body of an if, while or for is exactly one statement; indentation does not add statements to it. (silent logic error)
X applicability rulePut inside the body exactly what must happen once per pass; put set-up before the loop and final reporting after it. Always brace a multi-statement body.

  • [2] misconception (M) → LoopBodyStatementOutsideLoop: wrong rule: Some statements inside the braces of a loop body are not repeated; they run once, before or after the loop. Right rule: Every statement inside the loop braces is part of the body and runs on every pass.
  • [3] misconception (M) → StatementAfterLoopInBody: wrong rule: A statement written after the loop is repeated with the loop body. Right rule: The body ends at the closing brace (or after its single statement); code after it runs once, after the loop ends.
  • [4] misconception (M) → LoopRunsStatementsSeparately: wrong rule: A loop runs its first body statement all N times, then its second body statement all N times. Right rule: Each pass runs the whole body in order, so the body statements interleave: S1, S2, S1, S2, ...
  • [5] misconception (M) → StateChangeIgnoredAcrossPasses: wrong rule: Values changed by one pass of a loop (other than the loop variable) do not affect later passes. Right rule: Each pass starts from the state left by the previous pass, so a change in one pass carries into the next ones.
  • [6] inconsistent_trace (T) → LoopBodyAlwaysOnce: Applies the body rule (LT) unevenly: runs all body statements on some passes but only some on others, includes the statement after the loop on some passes, or uses stale values from the first pass later. (here mixing in: "The loop body always runs at least once, even if the condition is false at the start")
  • [7] misconception (M) → WhileStopsMidBody: wrong rule: The loop stops the moment the condition becomes false, even in the middle of the body. Right rule: The condition is tested only before each pass, so the whole body finishes before the loop can stop.
  • [8] misconception (M) → ComputerFillsInIntent: wrong rule: The computer fills in omitted steps or values that the programmer meant, e.g. REPEAT 4 [FORWARD 30] draws a square without a turn command. Right rule: The computer executes only what the code states; every needed step and value must be written.
  • [9] misconception (M) → IfInLoopUnchecked: wrong rule: An if inside a loop body runs its branch on every pass without testing its condition. Right rule: The if condition is tested again on every pass, with the current values, so the branch runs only on passes where it is true.
  • [10] misconception (M) → LoopCountIsStatementCount: wrong rule: The repeat count of a counted loop says how many of the body statements are executed. Right rule: The repeat count is how many times the whole body runs; every pass runs all body statements.
  • [11] misconception (M) → ForLoopPartSkipped: wrong rule: A pass of a loop may leave out one of its parts (the condition test, the body, the update, or the initialization). Right rule: Each pass of a for loop runs test, then body, then update, every time; the initialization runs once, at the start.
  • [12] misconception (M) → LoopOutputSameEachPass: wrong rule: A loop prints the same thing on every pass; the changing loop variable does not affect what the body does. Right rule: The body uses the current value of the loop variable, so its output can differ on each pass.
