Rules of the concept (22)

Book (SW-1e, p. 47 (pdf 57)): “depending on whether the boolean expression is true or false, as in the following template: if (<boolean expression>) <statements T> else <statements F>”
Book (OT-If, ): “The if-then-else statement provides a secondary path of execution when an "if" clause evaluates to false.”
Book (SW-1.3, p. 46 (pdf 56)): “Most computations require different actions for different inputs.”
Rule typeRule
E folk-meaning ruleFolk meaning: in English 'otherwise' can be heard as 'and then also', and 'if ... else ...' as two separate rules that are each checked. In Java the condition is tested once and exactly one of the two branches runs.
M wrong rule / right ruleBothBranchesExecute: wrong: Both the then branch and the else branch run. | right: Exactly one of the two branches runs.
M wrong rule / right ruleConditionalIsSequence: wrong: if-else is the same as two separate ifs | right: In if-else, c is tested once and exactly one of A or B runs, even if A changes the variables that c uses.
M wrong rule / right ruleDuplicateCodeInBranches: wrong: Writes the same statements in both branches of an if-else. | right: Code common to both branches belongs before or after the if-else.
M wrong rule / right ruleElseAlwaysExecutes: wrong: The else branch of an if-else statement always executes. | right: The else branch runs only when the if condition is false.
M wrong rule / right ruleBranchChosenByIntent: wrong: Which branch runs is decided by what the programmer meant or by code outside the if, not by whether the condition is true. | right: The then branch runs exactly when the condition evaluates to true at the moment it is tested; otherwise the else branch (if any) runs.
T uneven-application ruleApplies the if-else rule (LT) unevenly: on some traces runs both branches, re-tests the condition after the then branch to decide whether to run the else branch, or runs the else branch whatever the condition.
N identity ruleThe if-else statement is a two-way conditional: it executes one of two statements (or blocks) depending on a boolean condition.
S declarative ruleSyntax: if (<boolean expression>) <statements T> else <statements F>; it executes one or the other, but not both: T if the condition is true, F otherwise.
LT operational sequencing ruleEvaluate the condition once; if true execute the then branch, otherwise execute the else branch; then continue with the statement after the whole if-else (the condition is not re-tested).
OP evaluation / result ruleExactly one branch's effects occur; e.g. if (x > y) max = x; else max = y; leaves max equal to the larger value, and the coin flip prints either Heads or Tails, never both.
OS state-transition ruleOne execution reads the condition's variables and applies the effects of exactly one branch; a change made by the then branch to the condition's variables cannot cause the else branch to run.
R composition rule (with a neighbour)with if_statement: if-else is an if with a second branch for the false case; dropping the else gives a plain if in which the false case does nothing.
R composition rule (with a neighbour)with nested_conditionals: Either branch may itself be an if or if-else, which nests conditionals; without braces an inner else pairs with the innermost if.
R composition rule (with a neighbour)with conditional_operator: c ? a : b is the expression form of if (c) v = a; else v = b;: it yields a value of one branch, evaluating only the selected operand.
R composition rule (with a neighbour)with else_if_chain: An else-if chain is an if-else whose else part is another if-else, repeated; the final else catches all remaining cases.
P plan / role rulePlan: two-way choice / alternative action - compute one of two results (max of two values, heads or tails, error message or quotient).
C conservation ruleSwapping the two branches and negating the condition preserves behaviour; swapping the branches alone inverts it. Replacing if-else with two separate ifs is not equivalent when the then branch changes a variable used in the condition.
D error rulerule broken: else takes no condition: it is the branch for the false case of the preceding if; a further test needs else if (...). (compile-time)
D error rulerule broken: Code common to both branches belongs before or after the if-else. (silent logic error)
D error rulerule broken: An else must directly follow the then statement of an if. (compile-time)
X applicability ruleUse if-else when exactly one of two actions must happen; use a plain if when nothing happens in the false case, an else-if chain or switch for more than two mutually exclusive cases, and c ? a : b when you only need to choose a value.
