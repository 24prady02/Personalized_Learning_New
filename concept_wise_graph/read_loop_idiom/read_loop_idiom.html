Rules of the concept (17)

Book (SW-1e, p. 131 (pdf 141)): “Before reading each number, the program uses the method StdIn.isEmpty() to check whether there are any more numbers in the input stream.”
Book (SW-1.5, ): “Our StdIn library takes data from a standard input stream that contains a sequence of values separated by whitespace ... your program consumes values when it reads them.”
Rule typeRule
E folk-meaning ruleEveryday 'read until the end' assumes you know how long the text is, and 'empty' suggests a blank screen or line. The stream's length is unknown to the program, and isEmpty() is true only when no more tokens remain.
M wrong rule / right ruleAssignmentNotExpression: wrong: An assignment cannot be used inside a larger expression. | right: An assignment is an expression whose value is the value assigned, so (x = v) both stores v in x and yields v. This is used, for example, in while ((line = in.readLine()) != null).
M wrong rule / right ruleInputReadOnceBeforeLoop: wrong: Reading a value once before the loop is enough; the loop will process each new input value. | right: The read must be inside the loop body so that every pass consumes a new value.
T uneven-application rulePoints to LT (test !isEmpty(), then read, then process, on every pass). An uneven trace processes the old value before reading on some passes, or reads twice on one pass.
N identity ruleThe read loop is an input idiom: a while loop whose condition is !StdIn.isEmpty() and whose body reads one value and processes it.
S declarative ruleBefore each read, call StdIn.isEmpty() to check whether more values remain. isEmpty() is true when only whitespace is left.
LT operational sequencing ruleEach pass: evaluate !StdIn.isEmpty(). If it is true, read one value, then process it (e.g. sum += value; cnt++;) and go back to the test. If it is false, leave the loop and run the code after it (e.g. compute and print the average).
OP evaluation / result ruleAfter the loop, every value has been read exactly once and the accumulators hold their totals. Average with input 10.0 5.0 6.0 3.0 7.0 32.0 <ctrl-d> prints Average is 10.5.
OS state-transition ruleOne pass consumes exactly one value (or one fixed group, e.g. an x, y pair) and updates the loop's accumulators. The isEmpty() test consumes nothing.
R composition rule (with a neighbour)with standard_input: isEmpty() false guarantees only one more token. A body that reads k values per pass assumes the input count is a multiple of k.
R composition rule (with a neighbour)with end_of_input: The loop ends only when isEmpty() becomes true: at the end of a redirected file, or after the end-of-file keystroke (<ctrl-d>, or <ctrl-z> on some systems).
R composition rule (with a neighbour)with sentinel_loop: A sentinel loop keeps the read-then-test structure but stops on a special data value instead of, or as well as, isEmpty(). The sentinel must be tested before it is processed.
P plan / role rulePlan: the process-all-input loop (Soloway's read/process loop). sum is a gatherer and cnt a counter (stepper), and value is a most-recent holder.
C conservation ruleThe loop works for any input length, including 0 (the body is skipped). With empty input, though, Average's sum / cnt is 0.0/0 = NaN. Moving the read out of the loop breaks it, so one value is reused forever.
D error rulerule broken: Every read needs a preceding isEmpty() check that guarantees a value. (run-time exception)
D error rulerule broken: Do not divide by a count of 0. (silent logic error)
X applicability ruleUse the read loop when the number of values is unknown and all input should be processed. When N is given first, use a counted for loop (AddInts). Use a sentinel loop when a stop value marks the end.
