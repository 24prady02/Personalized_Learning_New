Rules of the concept (15)

Book (TJ-2e, p. 84 (pdf 106)): “flag: A variable (usually boolean) that represents a condition or status.”
Book (RS-web, ): “if the code finds a factor of the number, prime will be set to false, but on the next pass through the loop, if the next number isn't a factor, prime will be reset to true again.”
Rule typeRule
E folk-meaning ruleFolk meaning: in English, 'found' or 'is OK' describes the current item, so a novice writes `found = (a[i] == target);` on every pass. In a search, the flag must record whether any pass so far matched: it is set once (`if (a[i] == target) found = true;`) and never reset.
M wrong rule / right ruleFlagResetInLoop: wrong: A search flag should be set back (to false/true) whenever a test fails. | right: A search flag is a one-way flag: once a pass records a find, no later pass may reset it, so the loop body contains only `if (match) found = true;` with no else.
T uneven-application ruleApplies the LT rule unevenly: on a trace, the flag is updated on non-matching passes as if there were an else, or the trace forgets that the flag carries over from the previous pass. The traced final flag then reflects only the last element.
N identity ruleLoop plan: a boolean flag variable initialised before a loop and set by the loop when a condition is found, recording whether the condition held on any pass.
S declarative rule`boolean found = false; for (int i = 0; i < n; i++) if (a[i] == target) found = true;` To stop early, add the flag to the test: `while (i < n && !found)`.
LT operational sequencing ruleOrder: initialise the flag once before the loop. On each pass, test the loop condition (which may include `!found`), then evaluate the guard, and only if it is true assign `found = true`. Read the flag after the loop.
OP evaluation / result ruleThe result is a boolean: true if at least one pass satisfied the guard, false if none did (including zero passes). For {3, 5, 7} and target 5, found is true.
OS state-transition ruleA matching pass changes only the flag, from false to true (and it stays true). A non-matching pass changes nothing. `found = true` as a statement has the value true, which is discarded.
R composition rule (with a neighbour)with for_loop: The flag must be declared before the for loop to be visible after it. The for loop's test can include `!found` to stop at the first find; without that, the loop runs all passes, and the flag still works because it is one-way.
P plan / role rulePlan: search / existence-check plan. The flag plays the Sajaniemi one-way flag role. It answers 'is there any element with property P?' or 'is the array sorted?'.
C conservation ruleInvariant: after k passes, found == (some element among the first k matched). Adding an else that resets the flag breaks the invariant, as does replacing the guard with `found = (a[i] == target)`. Adding `!found` to the loop test keeps the result and only saves passes. Initialising the flag to true breaks the result for inputs with no match.
D error rulerule broken: A while loop tests its condition before the first pass: if the values set before the loop make the condition false, the body never runs. (silent logic error)
D error rulerule broken: A search flag is one-way: it must not be reassigned on every pass. (silent logic error)
D error rulerule broken: Using = instead of == on a boolean flag assigns instead of testing. (silent logic error)
X applicability ruleUse a flag when you need a yes/no answer after a loop, or a stopping condition that is set in the middle of a pass. In a method, `return` from inside the loop (or `break`) is often simpler. Use a counter when you need how many, not whether.
