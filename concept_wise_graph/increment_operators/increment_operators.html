Rules of the concept (20)

Book (SW-1e, p. 75 (pdf 85)): “In expressions, both increment i, but ++i has the value after the increment and i++ the value before the increment.”
Book (TJ-2e, p. 92 (pdf 114)): “Specifically, ++ is the increment operator; it has the same effect as i = i + 1.”
Book (OT-Op1, ): “The only difference is that the prefix version (++result) evaluates to the incremented value, whereas the postfix version (result++) evaluates to the original value.”
Rule typeRule
E folk-meaning ruleFolk meaning: '++' reads as 'plus plus' (add twice) or as a maths symbol with no effect, and i++ inside an expression is read as 'add 1 at some later time'. In Java i++ and ++i each add exactly 1 to i immediately when evaluated; they differ only in the value the expression yields.
M wrong rule / right rulePostIncrementAssignsLater: wrong: i = i++ increases i by 1. | right: i++ evaluates to the old value, so i = i++ stores the old value back.
M wrong rule / right rulePreIncrementBeforeLoop: wrong: ++i in the for-update runs before the body each pass | right: The update runs after each pass of the body, so with either ++i or i++ the first pass uses i = s.
M wrong rule / right rulePrePostIncrementSameValue: wrong: x = i++ and x = ++i store the same value in x. | right: Both increment i, but ++i has the value after the increment and i++ the value before.
M wrong rule / right ruleIdiomOverridesCode: wrong: An array loop processes the whole array from index 0 to length-1 and increments its index at the end of the body, whatever the code says. | right: The loop visits exactly the indices that its initialisation, guard and update produce, in the order in which its statements are written.
M wrong rule / right ruleIncrementByTwo: wrong: i++ increases i by 2. | right: i++ (and ++i) increases i by exactly 1.
T uneven-application ruleApplies the increment rule (LT) unevenly: uses the old value in one expression and the new value in another for the same i++, or performs the increment at the end of the loop body instead of where it is written.
N identity rule++ and -- are the increment and decrement operators: shorthand that adds 1 to (or subtracts 1 from) a numeric variable.
S declarative rule++ has the same effect as i = i + 1 and -- the same as i = i - 1; as statements i++ and ++i are the same, but in expressions ++i has the value after the increment and i++ the value before.
LT operational sequencing rulei++: fetch the value of i (that is the expression's value), then store i + 1 into i. ++i: store i + 1 into i, and the new value is the expression's value. Both happen before the rest of the enclosing expression continues.
OP evaluation / result ruleWith i = 5: x = i++ gives x = 5, i = 6; x = ++i gives x = 6, i = 6; i = i++ leaves i = 5.
OS state-transition ruleOne execution changes exactly one variable (i) by exactly 1 and returns its old (i++) or new (++i) value.
R composition rule (with a neighbour)with loop_control: The usual for-loop update is i++ (shorthand for i = i + 1); as a stand-alone update statement ++i and i++ give the same loop.
R composition rule (with a neighbour)with side_effect_order: Inside a larger expression the result depends on which value (old or new) the increment yields and on left-to-right evaluation, e.g. j += j++ in Exercise 1.3.6.
R composition rule (with a neighbour)with assignment: i++ is shorthand for the assignment i = i + 1 (and i += k for i = i + k), so it changes the variable's stored value.
P plan / role rulePlan/role: the update of a stepper or counter (count++ in a counter, i++ in a counted loop).
C conservation ruleAs a stand-alone statement, replacing i++ by ++i, i += 1 or i = i + 1 preserves behaviour; inside an expression (x = i++ vs x = ++i) the swap changes the value used by 1.
D error rulerule broken: i = i++ stores the old value back. (silent logic error)
D error rulerule broken: ++ and -- apply only to a variable. (compile-time)
X applicability ruleUse i++ / i-- as stand-alone statements and in for-loop updates; avoid them inside larger expressions (x = ++i), as the book does, and use += for steps other than 1.
