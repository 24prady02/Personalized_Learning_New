Rules of the concept (14)

Book (SW-1e, p. 46 (pdf 56)): “This description introduces a formal notation known as a template”
Rule typeRule
E folk-meaning ruleFolk meaning: angle brackets read as the less-than and greater-than signs, or as text to be typed. In a template, `<boolean expression>` is a placeholder that is replaced by any instance of that construct; only the other tokens (if, parentheses, braces) are typed literally.
T uneven-application ruleApplies the substitution rule unevenly: some placeholders are filled with the right kind of construct and others with the wrong kind (a statement for an expression), or fixed tokens like the parentheses are dropped in some instances.
N identity ruleNotation (metalanguage): a template is S&W's pattern for the form of a Java construct. Fixed tokens are written literally, and a name in angle brackets stands for any instance of a previously defined construct.
S declarative ruleIn `if (<boolean expression>) { <statements> }`, `if`, `(`, `)`, `{`, `}` must appear as written. `<boolean expression>` may be any expression of type boolean, and `<statements>` any statement block. The braces are optional for a single statement. Syntax is the form a statement must have, checked by the compiler (syntax errors); semantics is what the statement means when it runs, which the compiler does not check.
LT operational sequencing ruleReading order: match the template's fixed tokens left to right against the code, then for each placeholder check that the code in that position is an instance of the named construct, recursively (a boolean expression may itself contain sub-expressions).
OP evaluation / result ruleFilling a template produces one concrete, legal Java construct. For example, if (<boolean expression>) <statements> becomes `if (x < 0) x = -x;`.
OS state-transition ruleOne substitution step replaces one placeholder with one instance of its construct and leaves the rest of the template unchanged.
R composition rule (with a neighbour)with boolean_expression: The `<boolean expression>` slot accepts only expressions of type boolean (`x > y`, `found`, `a && b`). An int expression or an assignment such as `x = y` with int x is a compile error in that slot.
P plan / role rulePurpose: to describe compactly what every instance of a construct looks like (if, while, for, do-while), so that you can write new instances and check existing code against the form.
C conservation ruleChanging what fills a placeholder (any other boolean expression) keeps the code legal. Changing or omitting a fixed token (dropping the parentheses, adding `then`) breaks it.
D error rulerule broken: Fixed tokens of the template must appear exactly. (compile-time)
D error rulerule broken: A placeholder must be filled by an instance of the named construct. (compile-time)
D error rulerule broken: Angle brackets are notation, not code. (compile-time)
X applicability ruleUse templates to learn or check the form of a new construct. They show syntax, not meaning (the meaning of while vs if is not in the template), and they leave out details such as optional braces, so read them together with the semantic rule.
