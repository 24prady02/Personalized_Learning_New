Rules of the concept (22)

Book (SW-1e, p. 34 (pdf 44)): “Java has eight primitive data types: boolean, char, byte, short, int, long, float, and double.”
Book (OT-Datatypes, ): “A primitive type is predefined by the language and is named by a reserved keyword.”
Book (SW-1.2, ): “A data type is a set of values and a set of operations defined on them.”
Rule typeRule
E folk-meaning ruleIn English 'primitive' means crude or old-fashioned, which suggests these are a lesser type or that anything simple-looking (String) is primitive. In Java a primitive type is one of eight types predefined by the language and named by a keyword. It holds a plain value of fixed size, so it has no methods and no overflow checking.
M wrong rule / right ruleNewArrayHoldsGarbage: wrong: The slots of a new int[n] hold unpredictable values until assigned. | right: new fills every element with a default: 0 for numeric types, false for boolean, null for String and other non-primitive types.
M wrong rule / right ruleStringIsPrimitive: wrong: String is a primitive type like int. | right: String is not a primitive type; it is a class whose values are objects, although Java gives it some built-in support (literals, +).
T uneven-application rulePoints to LT (each operation is done in its type's fixed size). Applied unevenly, a student truncates and wraps int results on one line but treats another int intermediate as an unbounded real number, e.g. tracing 59 / 60 * 100 as 98.
N identity rulePrimitive type: one of Java's eight built-in data types (boolean, char, byte, short, int, long, float, double). Its values are simple values, not objects.
S declarative rulebyte, short, int and long are 8/16/32/64-bit signed two's-complement integers. char is 16-bit unsigned. float and double are IEEE 754 32-bit and 64-bit. boolean has exactly the values true and false. The other four primitive types are byte and short (smaller integers), long (64-bit integers) and float (32-bit floating point).
LT operational sequencing ruleIn an expression over primitives, the left operand is evaluated, then the right one. Both are then promoted to a common type (at least int, or long or double if either operand has that type), and the operator is applied in that type.
OP evaluation / result ruleThe result is a primitive value whose type comes from promotion: byte, short, char and int combinations give int, any long operand gives long, and any double operand gives double (e.g. 'a' + 1 is int 98, 1 + 2L is long 3, 1 + 2.0 is double 3.0).
OS state-transition ruleAssigning to a primitive variable copies the value into it. After int b = a; a = 3;, b still holds the old value because nothing is shared (unlike array references).
R composition rule (with a neighbour)with literal: How a literal is written fixes its primitive type (1234 int, 3.14 double, true boolean, 'c' char), and it must fit the primitive type of the variable it initializes.
R composition rule (with a neighbour)with type_conversion: Between numeric primitive types, widening (int to double) happens automatically, while narrowing (double to int) needs a cast that drops information. boolean converts to no numeric type.
R composition rule (with a neighbour)with data_type: Each primitive type is a data type: a fixed set of values plus the operators defined for them.
R composition rule (with a neighbour)with int: int is the 32-bit signed integral primitive. Arithmetic on byte, short and char is also carried out in int.
R composition rule (with a neighbour)with double: double is the 64-bit IEEE 754 primitive. Once a double meets an integral operand in a binary operator, the whole operation becomes floating point.
R composition rule (with a neighbour)with boolean: boolean is the primitive with only true and false. It does not mix with numeric primitives: it cannot be cast to them, and only booleans may be used as conditions.
R composition rule (with a neighbour)with char: char is an integral primitive (16-bit unsigned UTF-16 code unit), so a char takes part in arithmetic as its numeric code.
P plan / role rulePrimitive types hold the single numbers, characters and truth values that every computation is built from. You pick the one that matches the quantity: int for counts, double for measurements, boolean for conditions, char for one character.
C conservation ruleSwitching one primitive type for another changes range and precision. int to long removes overflow up to about 9.2e18. int to double keeps fractions but stops being exact for very large integers. Changing a type to boolean breaks every arithmetic use.
D error rulerule broken: A narrowing primitive conversion needs an explicit cast. (compile-time)
D error rulerule broken: Integer primitives have fixed ranges and integer operators do not report overflow. (silent logic error)
D error rulerule broken: Primitive type names are lowercase keywords. (compile-time)
X applicability ruleUse a primitive type for a single numeric, character or true/false value. Use String for text, arrays for collections, BigInteger for integers beyond long, and int cents rather than double when money must be exact.
