Array name holds a memory address (id array_reference, section 1.4 1.4 Arrays, topic 1.4.b Memory representation and bounds checking)

Description: the array variable stores the memory address (pointer) of the array; a[i] is found by adding i to that address

Rules of the concept (12)

Book (SW-1e, p. 90 (pdf 100)): “We refer to the address as a pointer”
Book (SW-1e, p. 97 (pdf 107)): “as if the array name were a variable whose value is the memory address of the array.”
Rule typeRule
E folk-meaning ruleFolk meaning: a variable is a box, so the array's values are 'inside' a. Java rule: the variable a holds only a reference (memory address, pointer) to the array object, which lives elsewhere.
T uneven-application rulePoints to LT: a[i] means fetch the address stored in a, add i, and access that memory location. Inconsistent application: the trace copies elements when a is assigned on one step but shares them on another.
N identity ruleIdentity: an array reference, the value of an array variable; it is the memory address of the array, called a pointer.
S declarative ruleDeclarative: a variable of array type holds a reference to an array object; operations on the name itself (assignment, ==, printing) act on that address.
LT operational sequencing ruleSequencing: for a[i], the address stored in a is read, the index i is added (scaled by the element size), and the memory at the resulting address is accessed: two elementary operations.
OP evaluation / result ruleResult: the value of a is a reference (printed as hexadecimal). With the array at locations 523..530, a[4] is found at location 523 + 4 = 527.
OS state-transition ruleState transition: assigning a reference (a = b, or a = new ...) changes only which array the variable points to; the arrays themselves are unchanged.
R composition rule (with a neighbour)with array_creation: new reserves the memory and yields the array's address, which the array variable then stores.
P plan / role rulePlan/role: the model that explains constant-time indexing, aliasing, reference equality and printing of arrays.
C conservation ruleConservation: copying a reference keeps one shared array (changes through either name are seen by both); assigning a new reference breaks the link without changing either array.
D error rulerule broken: A reference must point to an array before it is indexed. (run-time exception)
X applicability ruleApplicability: reason in terms of references whenever arrays are assigned, compared, printed or passed to methods. Reason in terms of elements when indexing.
