Rules of the concept (18)

Book (SW-1e, p. 19 (pdf 29)): “the concatenation operator (+) that we just considered is built in to the language as a binary operator in the same way as familiar operations on numbers.”
Book (OT-Op1, ): “The + operator can also be used for concatenating (joining) two strings together”
Book (SW-1.2, ): “The most common operation that we perform on strings is known as concatenation.”
Rule typeRule
E folk-meaning ruleIn arithmetic, + always means 'add', and 'plus' combines quantities, so novices expect "1" + 2 to be 3. In Java, + with a String operand joins text end to end, and a chain of + is processed left to right, one operator at a time.
M wrong rule / right ruleArithmeticPlusPrecedes: wrong: arithmetic + binds tighter than string-concatenation + | right: Both uses of + have the same precedence and are evaluated left to right, so "s" + a + b joins a and then b as text; only "s" + (a + b) adds them first.
M wrong rule / right ruleStringPlusLeftToRight: wrong: 2 + 3 + "bc" and "bc" + 2 + 3 give the same text. | right: + is evaluated left to right: 2 + 3 + "bc" is "5bc" but "bc" + 2 + 3 is "bc23".
M wrong rule / right ruleStringPlusStringifiesExpression: wrong: + with a String turns the whole other side into a string first | right: The expression (a + b) is evaluated first, and its value is then turned into text and joined to s.
T uneven-application rulePoints to LT (left to right, and each + adds or concatenates according to its operands at that moment). Applied unevenly, a student keeps adding numbers after a String has appeared, or concatenates before any String appears (1 + 2 + "x" as "12x").
N identity ruleString concatenation: the + operator with a String operand, which joins two values end to end into a new String.
S declarative ruleIf either operand of + is a String, the other is converted to a String, and the result is a new String made of the first operand's characters followed by the second's.
LT operational sequencing ruleA chain of + is evaluated left to right, after any parenthesized parts. At each + the current operand types decide: two numbers are added, otherwise the values are concatenated.
OP evaluation / result ruleThe result is a String: 2 + "bc" is "2bc", 2 + 3 + "bc" is "5bc", "bc" + 2 + 3 is "bc23", and "bc" + (2+3) is "bc5".
OS state-transition ruleConcatenation creates a new String and changes no operand. A variable changes only if the result is assigned, as in ruler = ruler + i + ruler;.
R composition rule (with a neighbour)with string_type: Concatenation always yields a String, even when one operand is a number, so its result cannot be used in arithmetic without parsing.
R composition rule (with a neighbour)with string_conversion: The non-String operand is converted to its printed form (int 99 to "99", double 1.0 to "1.0", char 'a' to "a") before joining.
P plan / role ruleConcatenation builds output lines and labels from computed values (a + " + " + b + " = " + c). Repeated s = s + piece makes s a gatherer of text.
C conservation ruleParenthesizing numeric parts changes the result ("sum " + (a + b) adds before joining). Moving numbers before or after the first String changes whether they are added. Concatenating into a printf format string removes the separate argument printf needs.
D error rulerule broken: Once a String appears in a + chain, every later + concatenates. (silent logic error)
D error rulerule broken: char + char is numeric addition, not concatenation. (silent logic error)
D error rulerule broken: printf needs its values as separate arguments matching the format specifiers. (run-time exception)
X applicability ruleUse + concatenation for simple output and labels, putting parentheses around any arithmetic inside. Use printf when numbers need formatting, and parse Strings before using them as numbers.
