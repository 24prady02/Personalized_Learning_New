Rule typeRule
E folk-meaning ruleIn maths `7.2` (or %2.4f) reads as a decimal number, or as '7 digits before the point, 2 after'. In a format specifier the number before the point is the total field width and the number after it is the digits after the decimal point. Also `%` is not 'percent'.
M wrong rule / right rulePrintfAnyConversion: wrong: Any conversion code (%d, %f, %s) works with any argument type. | right: The conversion must fit the argument's type (%s accepts any type). printf("%12d", Math.PI) or printf("%4.2f", 512) throws IllegalFormatConversionException at run time.
M wrong rule / right ruleFieldWidthIsIntegerDigits: wrong: %2.4f prints two digits before the decimal point and four after. | right: The first number is the width of the whole field. %7.2f means 7 characters in total, with 2 digits after the decimal point.
M wrong rule / right rulePrintfAddsNewline: wrong: printf() ends the line like println(). | right: printf() adds no newline. Put \n (or %n) in the format string.
M wrong rule / right ruleManyDigitsMeanAccurate: wrong: A result printed with many decimal places must be accurate to those places. | right: Printing precision is only formatting. A value printed to many places can still be inaccurate, and ensuring accuracy is the hard part.
T uneven-application rulePoints to LT (specifiers are paired with arguments left to right, and the other characters pass through). An uneven trace pairs a specifier with the wrong argument, drops the literal text between specifiers, or pads on the wrong side on some fields.
N identity ruleprintf is the formatted-print method of standard output. It takes a format string and arguments and writes the formatted string.
S declarative ruleA format specifier has the form %[argument_index$][flags][width][.precision]conversion: d for integer types, f for floating-point values, s for String or any type. The width is a minimum character count, and for f the precision is the number of digits after the point.
LT operational sequencing ruleThe arguments are evaluated first. The format string is then scanned left to right: ordinary characters are copied, and each specifier takes the next argument, converts it, rounds it to the precision and pads it with blanks to the width (left side by default, right side with the `-` flag).
OP evaluation / result ruleThe output is the formatted text. printf("%7.5f", Math.PI) gives 3.14159, printf("PI is approximately %.2f\n", Math.PI) gives `PI is approximately 3.14` and a newline, and printf("%5d", 42) gives ` 42`. Rounding is half-up.
OS state-transition ruleOne call appends one formatted string to standard output and adds no newline unless \n or %n is in the format. The stored values of the arguments do not change (only their printed form is rounded).
R composition rule (with a neighbour)with standard_output: printf output goes into the same stream as print/println and lands at the point in the stream where it was called. It does not end the line.
R composition rule (with a neighbour)with println: println prints a double with all its digits (about 15 places) and always ends the line. printf("%.2f\n", x) controls the digits and ends the line only because of \n.
P plan / role rulePlan: table printing. Inside a loop, one fixed format string with a specifier per column prints aligned rows (e.g. a loan table) at a chosen precision.
C conservation ruleChanging the precision changes only the printed digits, not the stored value. Changing the width changes only the padding. A width smaller than the converted text is ignored, so nothing is truncated.
D error rulerule broken: The conversion code must match the argument type. (run-time exception)
D error rulerule broken: There must be an argument for every specifier, and the format syntax must be legal. (run-time exception)
D error rulerule broken: printf adds no line separator. (silent logic error)
X applicability ruleUse printf when the number of digits, the field width or column alignment matters (tables, money, reports). For quick checks of a value, println is enough.
