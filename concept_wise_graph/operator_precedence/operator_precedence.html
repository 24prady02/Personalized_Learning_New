Rules of the concept (19)

Book (SW-1e, p. 17 (pdf 27)): “When arithmetic operators have the same precedence, the order is determined by left-associativity, so that a-b-c and (a-b)-c represent the same sequence of operations.”
Book (OT-Expressions, ): “Operators that have a higher precedence get evaluated first.”
Book (OT-Expressions, ): “When writing compound expressions, be explicit and indicate with parentheses which operators should be evaluated first.”
Rule typeRule
E folk-meaning ruleSchool order of operations (PEMDAS/BODMAS) covers only arithmetic, so novices read other operators left to right as in English, or treat ^ as a power. Java's precedence table also places casts above * / %, comparisons below + -, && above ||, and = lowest.
M wrong rule / right ruleArithmeticPlusPrecedes: wrong: arithmetic + binds tighter than string-concatenation + | right: Both uses of + have the same precedence and are evaluated left to right, so "s" + a + b joins a and then b as text; only "s" + (a + b) adds them first.
M wrong rule / right ruleBooleanPrecedence: wrong: a || b && c is evaluated left to right as (a || b) && c. | right: && binds tighter than ||, so it is a || (b && c).
M wrong rule / right ruleCastAppliesToWholeExpression: wrong: (int) 2.5 / 0.15 casts the whole quotient to int. | right: The cast applies only to what comes right after it, here 2.5.
M wrong rule / right ruleStringPlusLeftToRight: wrong: 2 + 3 + "bc" and "bc" + 2 + 3 give the same text. | right: + is evaluated left to right: 2 + 3 + "bc" is "5bc" but "bc" + 2 + 3 is "bc23".
M wrong rule / right ruleWrongOperatorOrder: wrong: G * m1 * m2 / r * r divides by r squared. | right: * and / are applied left to right, so it divides by r and then multiplies by r; use / (r * r).
T uneven-application rulePoints to LT (group by precedence, then left to right for operators of equal precedence). Applied unevenly, a student applies * before + in one place but reads G * m1 * m2 / r * r as dividing by r squared.
N identity ruleOperator precedence (order of operations): the rules that decide which operator binds its operands first, with associativity breaking ties.
S declarative rule* / % bind before + -, and operators of equal precedence group left to right (a-b-c is (a-b)-c). Casts bind tighter than arithmetic, comparisons are below arithmetic and above && and ||, and parentheses override everything. Operators of equal precedence are applied left to right: a-b-c is (a-b)-c, 1 + 2 + "Hello" is "3Hello" but "Hello" + 1 + 2 is "Hello12".
LT operational sequencing ruleGrouping is fixed first: innermost parentheses, then casts and unary operators, * / %, + -, comparisons, &&, ||, and finally =. Within a level grouping goes left to right, and operands are then evaluated left to right inside that grouping.
OP evaluation / result rule1 + 2 * 3 is 7. 3 + 5 / 2 is 5. 3 - 5 - 2 is -4. 2 + 3 + "bc" is "5bc" but "bc" + 2 + 3 is "bc23".
OS state-transition rulePrecedence changes no variable. It only decides which intermediate value is computed next: in minute * 100 / 60 with minute = 59, 5900 is computed before the division.
R composition rule (with a neighbour)with expression: Precedence decides the grouping of a multi-operator expression, and a parenthesized subexpression is evaluated as one unit with its own value.
P plan / role rulePrecedence lets compact formulas read like maths notation. Programmers add parentheses to state the intended grouping, e.g. (a + b) / 2 for an average.
C conservation ruleAdding parentheses that match precedence keeps the value ((minute * 100) / 60). Parentheses that change the grouping change it (3 - (5 - 2) is 0, not -4). Reordering equal-precedence int operations can also change it (59 / 60 * 100 is 0).
D error rulerule broken: * and / have equal precedence and group left to right; + binds weaker than / . (silent logic error)
D error rulerule broken: Comparisons yield booleans, and < is not defined between a boolean and an int. (compile-time)
D error rulerule broken: + groups left to right, so once a String appears, later + operators concatenate. (silent logic error)
X applicability ruleRely on precedence for ordinary arithmetic. Add parentheses whenever the expression mixes levels that readers may not know (casts, && with ||, + with Strings, chains of * and /). Break very long formulas into named intermediate variables.
