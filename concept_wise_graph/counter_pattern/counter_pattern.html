Rules of the concept (18)

Book (SW-1e, p. 67 (pdf 77)): “continuing until the gambler is broke or the goal is reached, and keeping track of the number of wins and the number of bets.”
Book (SW-1.3, ): “It uses two variables-one as an index that controls a loop, and the other to accumulate a computational result.”
Rule typeRule
E folk-meaning ruleFolk meaning: 'count' in everyday speech is done by looking at the whole collection at once, so a novice expects `count` to 'know' how many items matched. In Java a counter is just an int that changes only when `count++` executes, once per matching pass, starting from the value it was given before the loop.
M wrong rule / right ruleVariableRolesInferred: wrong: Java recognises which variable is the counter and which is the running total, and keeps their values apart even if one variable is used for both. | right: A variable holds one value at a time and Java infers no roles: a counter needs its own variable, initialised before the loop (`int wins = 0;`) and updated only by its own statement (`wins++`).
T uneven-application ruleApplies the LT rule (test the condition, then `count++` only on passes where it holds) unevenly: increments on a pass whose test was false, skips one matching pass, or forgets that the counter keeps its value from the previous pass, so the traced final count is off by one or more.
N identity ruleLoop plan (Soloway counter plan): an int variable set to 0 before a loop and increased by 1 on each pass that meets a condition, so it ends holding the number of matches.
S declarative ruleDeclare and initialise the counter before the loop (`int wins = 0;`); inside the loop guard `wins++` with the condition being counted (`if (cash == goal) wins++;`); read it after the loop.
LT operational sequencing ruleOrder: the initialisation `count = 0` runs once before the loop; then on each pass the loop test, the guard (`if (...)`) and, only when the guard is true, `count++`; the counter is read once after the loop ends.
OP evaluation / result ruleThe result is an int equal to the number of passes on which the guard was true (0 if none); it is between 0 and the number of passes. Turning it into a rate with ints truncates: `100*wins/T` with wins = 503, T = 1000 prints 50.
OS state-transition ruleOne matching pass changes only the counter, by exactly +1 (`wins++` turns 7 into 8); a non-matching pass leaves it unchanged. `count++` as a statement returns nothing that is used.
R composition rule (with a neighbour)with loop_body: The `count++` (with its guard) must be inside the loop body, while the declaration `int count = 0;` must be outside and before it. Inside the body it runs once for each matching pass. After the loop it runs only once, so the count is at most 1.
R composition rule (with a neighbour)with accumulator_pattern: Same skeleton (initialise before, update inside, read after); the accumulator adds the current value (`sum += x`), the counter adds the constant 1 on matching passes (`count++`). The two are often combined to compute an average `sum / count`, which needs a guard against `count == 0`.
R composition rule (with a neighbour)with monte_carlo_simulation: A Monte Carlo estimate is the counter divided by the number of trials (`(double) wins / T`). So the counter has to be initialised once, before the trial loop, and must not be reset inside it.
P plan / role rulePlan: counting plan; the counter variable plays a Sajaniemi 'stepper'-like counting role (Soloway's counter variable). Its job is to answer 'how many passes satisfied P?', e.g. wins or number of bets.
C conservation ruleInvariant: after k passes, count equals the number of matching passes among those k. Moving the guard or the update changes the count. Moving `count++` out of the `if` turns it into a pass counter. Starting at 1 instead of 0 makes every result one too high. Reordering statements that do not touch count leaves it unchanged.
D error rulerule broken: The counter/accumulator must be declared and initialised before the loop. `int count = 0;` inside the body re-creates and resets it on every pass. (silent logic error)
D error rulerule broken: A variable declared inside the loop body is out of scope after the loop. (compile-time)
D error rulerule broken: Integer division truncates: a rate computed as `count / total` with ints is 0 whenever count < total. (silent logic error)
D error rulerule broken: A local counter must be definitely assigned before it is read. (compile-time)
X applicability ruleUse a counter when the question is 'how many' (wins, bets, primes, distinct values); use an accumulator when it is 'how much in total', and a boolean flag when you only need 'whether any'. When you need a count for each of many values, use an array of counters (a histogram) instead of many separate variables.
