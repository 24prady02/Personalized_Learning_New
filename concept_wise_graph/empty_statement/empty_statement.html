Rules of the concept (13)

Book (SW-1e, p. 76 (pdf 86)): “It is generally better style to use a while statement than null statements in a for loop.”
Book (SW-1.3, ): “It is legal (but uncommon) to have a block that does not belong to a conditional statement, loop, or method.”
Rule typeRule
E folk-meaning ruleFolk meaning: in English a semicolon just separates or ends a clause, so 'if (x > 0);' still reads as 'if x is positive, do the next thing'. In Java a lone ; is a complete statement that does nothing, and it becomes the whole body of the if or loop.
T uneven-application ruleApplies the empty-statement rule (LT) unevenly: treats a stray ; after an if or loop header as ending the body on one line but not on another, e.g. expects the following block to be controlled.
N identity ruleThe empty (null) statement is a lone semicolon: a statement that does nothing.
S declarative ruleAn empty statement does nothing, and its execution always completes normally; any part of a for loop, including its body, may be left empty, but a while loop is better style than null statements.
LT operational sequencing ruleExecuting ; does nothing and passes control to the next statement; as a loop body it means each pass is just test (then update, for a for loop).
OP evaluation / result ruleAn empty statement produces no value and no output; e.g. for (int v = 1; v <= N/2; v *= 2) ; computes the same final v as the while version, but v is out of scope afterwards.
OS state-transition ruleOne execution changes no variable and returns nothing; only the header parts around it (test, update) change state.
R composition rule (with a neighbour)with statement: The empty statement can stand wherever a statement is required (if body, loop body, for slots), and a block { } can stand alone; a ; after a header therefore silently becomes the body.
P plan / role rulePlan: placeholder - an intentionally empty body when the loop header does all the work; the book avoids it and prefers a while loop.
C conservation ruleDeleting a ; that stands right after an if or loop header changes the program: the next statement becomes the body. Adding or removing an extra ; between ordinary statements changes nothing.
D error rulerule broken: A ; right after if (...) is an empty statement that forms the whole then branch; the following statement or block is no longer part of the if. (silent logic error)
D error rulerule broken: A ; right after while (...) or for (...) is an empty statement that is the whole loop body; the block written next is not repeated. (silent logic error)
X applicability ruleUse an empty statement only for a loop whose header does all the work, and comment it; otherwise write { } or restructure as a while loop. Never put ; directly after if (...), while (...) or for (...) by habit.
