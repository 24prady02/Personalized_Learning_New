Rules of the concept (21)

Book (SW-1e, p. 15 (pdf 25)): “A literal is a source-code representation of a data-type value.”
Book (OT-Datatypes, ): “An integer literal is of type long if it ends with the letter L or l; otherwise it is of type int.”
Book (OT-Datatypes, ): “A floating-point literal is of type float if it ends with the letter F or f; otherwise its type is double and it can optionally end with the letter D or d.”
Book (OT-Datatypes, ): “Always use 'single quotes' for char literals and "double quotes" for String literals.”
Book (RS, ): “Character literals (of type char) are enclosed in single quotation marks and can include just one character”
Book (RS, ): “Notice that 207. is considered a double even though it coincides with an integer because of the decimal point.”
Rule typeRule
E folk-meaning ruleIn everyday writing, 1,000,000, 007, 1/2 and $5 all stand for numbers. Java literals have strict forms: commas are not allowed, 1/2 is an int division expression worth 0, and a leading 0 makes the number octal (013 is 11).
M wrong rule / right ruleLargeIntegerLong: wrong: a large integer literal is automatically long | right: A sequence of digits is an int literal only if its value falls within the int range; for larger values the book advises the long type.
M wrong rule / right ruleNoFloatLiterals: wrong: Java has no float literals | right: A decimal literal ending in f is a float; without the f it is a double.
M wrong rule / right ruleNoLongLiterals: wrong: Java has no long literals | right: An integer literal ending in L is a long.
M wrong rule / right ruleWholeNumberLiteralIsInt: wrong: 207. and 2.3e4 are int values because they are whole numbers. | right: A decimal point or scientific notation makes the literal a double.
T uneven-application rulePoints to LT (each literal denotes one fixed value whose type is read from how it is written). Applied unevenly, a student reads 2.0 as an int in one place, or '7' as the number 7 in one expression and as a character in the next.
N identity ruleLiteral: a source-code representation of one fixed data-type value, such as 42, 3.14, true, 'a' or "hi".
S declarative ruleA digit sequence within the int range is an int literal. A decimal point or e-notation makes a double (3.14, 6.022e23). Suffix L gives a long and f a float. true and false are boolean, one character in single quotes is a char, and characters in double quotes are a String. Integer literals can also be written in hexadecimal (0x1F), octal (a leading 0: 013 is 11) or binary (0b101) and may contain underscores (1_000_000); a trailing L makes a long literal (2147483648L) and a trailing F a float literal (2.5F).
LT operational sequencing ruleA literal is evaluated at once, with no computation, and its evaluation always completes normally. An expression built from literals, such as 1/2, is still computed by its operators when it is reached.
OP evaluation / result ruleA literal's value is itself, with a type fixed by its form: 1234 is int 1234, 3.0 is double, '1' is char (code 49), and "2.5" is a String, not a number.
OS state-transition ruleA literal changes no state by itself. On the right of an assignment it supplies the value stored, e.g. a = 1234; sets a to 1234.
R composition rule (with a neighbour)with primitive_type: The form of a literal selects its primitive type, and that type must be assignable to the target: int x = 3.0; does not compile even though 3.0 is a whole number.
R composition rule (with a neighbour)with variable: Literals commonly initialize variables. The literal's type must equal or widen to the variable's type: double y = 1; widens, but int x = 1.1; is an error.
R composition rule (with a neighbour)with scientific_notation: E-notation is a form of double literal. 6.022e23 and even 1e6 are doubles, so int n = 1e6; needs a cast.
R composition rule (with a neighbour)with int_literal_limit: A literal without L must lie in -2147483648..2147483647, so 2147483648 alone is a compile error. Larger values need a long literal (2147483648L).
P plan / role ruleLiterals supply the fixed values a computation starts from: initial values of counters and totals (0), messages and labels, and known constants. A meaningful number that is repeated (a 'magic number') should become a named constant.
C conservation ruleRewriting a literal in another form keeps the value but changes the type, and so the operation: 10 / 3 is 3 but 10.0 / 3 is 3.333..., and "5" + 1 is "51" but 5 + 1 is 6.
D error rulerule broken: An int literal must lie within the int range. (compile-time)
D error rulerule broken: A char literal holds exactly one character in single quotes, and a String literal must be closed on the same line. (compile-time)
D error rulerule broken: A leading 0 makes an integer literal octal. (silent logic error)
X applicability ruleUse a literal for a self-explanatory value fixed when the program is written (0, 1, "Hello"). Use a final named constant for a meaningful or repeated value, and command-line or standard input for values that change between runs.
