### Concept: assignment

L2 Multistructural:

  - one_step_execution: Exactly one variable, the left one, changes, and its old value is lost. Variables on the right keep their values: x = x + 5; with x = 5 makes x 10.

  - relation_to_neighbour: Exchanging a[i] and a[j] takes three assignments in a fixed order through a temporary, because each assignment overwrites its target.

  - misconception: wrong rule: b = a exchanges the values of a and b.

L1 Unistructural:

  - states_the_rule: int t = a; a = b; b = t; exchanges a and b. The temporary t must have their type, and the three statements must run in exactly this order.
  boundary: Covering every part of the code in order is L2.

  - output_prediction: Starting from a = 1234 and b = 99, the swap ends with a = 99, b = 1234 and t = 1234.
  - one_step_execution: Each of the three statements changes exactly one variable: first t, then a, then b.
  boundary: One segment stating the purpose of the whole is L3. A word-for-word transliteration with no interpretation is L0 (Chen score 0).

  boundary: Two correct but separate rules are L1. Executing the two in sequence is L2. A relational answer may be correct or a relational error.
  boundary: Narrating the lines is L2. A purpose induced from a few traced cases is L2. A wrong purpose is still L3, but with an error.

  - transfer_to_a_new_program: Use the swap when two variables or array elements must exchange values (sorting, shuffling, ordering a pair). It is not needed when you only need a new variable holding the larger value, or when you can compute directly into new v
  - diagnose_an_error: rule broken: An assignment overwrites its target, so a value about to be overwritten must be saved first. Kind: silent logic error. Trigger class: Swapping without a temporary (a = b; b = a;) or in the wrong order: both variables

  boundary: Reproducing or slightly varying a familiar program is L1 to L3.
