### Concept: compile
L0 Prestructural:
  - everyday_reading: Everyday meaning: to 'compile' is to gather or put together (compile a list), and 'running' a program sounds like it starts on its own. 
  - misconception: wrong rule: Compiling also executes the program. 
  - misconception: wrong rule: Code that compiles is code that works. 
  boundary: Any correct, programming-specific statement about compile makes the answer L1 or higher.
  boundary: A single slip in an otherwise rule-correct trace is L2 with an error. Style or strategy breaches are not language misconceptions, and beliefs about a library are tagged scope=library.
L1 Unistructural:
  - names_the_element: Compiling is translating the whole Java source file into a lower-level form (Java bytecode) before execution; javac is the Java compiler.
  - states_the_rule: javac Name.java takes the file Name.java as input and, if there are no compile-time errors, produces Name.class (the bytecode version) with the same name.
  boundary: Covering every part of the code in order is L2.
  boundary: Applying the rule to this code's values is L2. Stating a rule that the language disproves is L0.
L2 Multistructural:
  - line_by_line_trace: The compiler first reads (parses) the entire file, then translates it; it does all this before the program starts running, and only if no errors were found does it write Name.class.
  - output_prediction: Result of javac Name.java: either a new file Name.class and no terminal output, or a list of error messages (file:line: message, then 'N errors') and no Name.class.
  - one_step_execution: One compile changes only the file system: it creates or overwrites Name.class; it changes no program variable and prints no program output.
  boundary: One segment stating the purpose of the whole is L3. A word-for-word transliteration with no interpretation is L0 (Chen score 0).
  boundary: A bare correct output is not levelled: it may be a guess, or hide a misconception. A prediction justified by the code's purpose is L3.
L3 Relational:
  - relation_to_neighbour: java Name loads the Name.class made by javac, so a successful compile must come before running, and edits take effect only after recompiling.
  - relation_to_neighbour: A compile-time error stops the translation, so no Name.class is produced and there is nothing new to run.
  - relation_to_neighbour: javac takes the program text Name.java as input; its file name must match the public class name.
  - purpose_of_the_whole: Purpose: check the program against the language rules and turn it into a form the JVM can execute, once, so it can then be run repeatedly with different inputs.
  boundary: Two correct but separate rules are L1. Executing the two in sequence is L2. A relational answer may be correct or a relational error.
  boundary: Narrating the lines is L2. A purpose induced from a few traced cases is L2. A wrong purpose is still L3, but with an error.
L4 Extended abstract:
  - predict_a_change: Recompiling the same unchanged source gives the same Name.class; any edit to the source is invisible to java Name until recompiled; adding or deleting comments or whitespace changes nothing the program does.
  - transfer_to_a_new_program: Compile after every change before running, and compile often while making small changes, so each error is found close to its cause; compiling cannot find run-time or logic errors.
  - diagnose_an_error: rule broken: Source must obey Java's syntax and type rules. Kind: compile-time. Trigger class: any syntax error (missing ; or brace, misspelled keyword) or type error in Name.java
  - diagnose_an_error: rule broken: javac needs the .java file name. Kind: launch error. Trigger class: typing javac Name (no .java) or the wrong file name / directory
  boundary: Re-tracing the changed code value by value is L2 on the new code. Adapting given code to a familiar variant may be only relational.
  boundary: Reproducing or slightly varying a familiar program is L1 to L3.

### Concept: compile_time_error
L0 Prestructural:
  - everyday_reading: Everyday reading: 'error' means the program will do something wrong when used, and a message points exactly at the mistake. 
  - misconception: wrong rule: Code that compiles is code that works. 
  - misconception: wrong rule: The line number in a javac error is always the line that has the mistake. 
  - misconception: wrong rule: Doing exactly what the compiler message suggests will fix the error. 
  boundary: Any correct, programming-specific statement about compile time error makes the answer L1 or higher.
  boundary: A single slip in an otherwise rule-correct trace is L2 with an error. Style or strategy breaches are not language misconceptions, and beliefs about a library are tagged scope=library.
L1 Unistructural:
  - names_the_element: A compile-time error (syntax error) is an error in the source code, caught by javac, that prevents the program from being translated.
  - states_the_rule: Compile-time errors occur when the code violates the rules of the Java language (syntax, names, types); they are caught when you compile and prevent the translation.
  boundary: Covering every part of the code in order is L2.
  boundary: Applying the rule to this code's values is L2. Stating a rule that the language disproves is L0.
L2 Multistructural:
  - line_by_line_trace: javac reads the whole file, reports each error with file name, line number and message, tries to recover and continue, and prints a count; the first message is the most reliable.
  - output_prediction: Result: messages such as Bad.java:4: ';' expected ... 3 errors, and no Name.class; nothing of the program runs.
  - one_step_execution: A failed compile leaves the file system without a new Name.class (an older one, if any, is not updated) and changes no program state.
  boundary: One segment stating the purpose of the whole is L3. A word-for-word transliteration with no interpretation is L0 (Chen score 0).
  boundary: A bare correct output is not levelled: it may be a guess, or hide a misconception. A prediction justified by the code's purpose is L3.
L3 Relational:
  - relation_to_neighbour: A compile-time error is reported while javac compiles Name.java, so no new Name.class is produced.
  - relation_to_neighbour: Each compile-time error comes with a message; reading it (first error first, line may be late) is how it is found and fixed.
  - relation_to_neighbour: A compile-time error is found by javac before the program runs; a run-time error only while it runs, so code that compiles can still crash.
  - purpose_of_the_whole: Purpose (of the check): catch rule violations automatically before running, so they cannot cause wrong behaviour; S&W say treat the compiler as a friend.
  boundary: Two correct but separate rules are L1. Executing the two in sequence is L2. A relational answer may be correct or a relational error.
  boundary: Narrating the lines is L2. A purpose induced from a few traced cases is L2. A wrong purpose is still L3, but with an error.
L4 Extended abstract:
  - predict_a_change: Fixing the first error and recompiling can remove many messages at once; a single missing brace or semicolon can cause several messages.
  - diagnose_an_error: rule broken: Each statement must end with ;. Kind: compile-time. Trigger class: missing ; at the end of a statement: ';' expected
  - diagnose_an_error: rule broken: Every { must be matched by a }. Kind: compile-time. Trigger class: missing or extra brace: '{' expected, 'class' or 'interface' expected, reached end of file while parsing
  - diagnose_an_error: rule broken: A String literal is enclosed in a pair of double quotes. Kind: compile-time. Trigger class: missing closing quote: unclosed string literal, often with confusing follow-on errors
  boundary: Re-tracing the changed code value by value is L2 on the new code. Adapting given code to a familiar variant may be only relational.
  boundary: Locating and fixing the mistake for one given failing case is L3. A compiler-flagged slip fixed from the message is weak evidence.
